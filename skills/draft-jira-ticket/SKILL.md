# Подготовка черновика задачи Jira

## Цель

Подготовить полный черновик задачи для проверки человеком, не изменяя Jira.

## Допустимые источники

- ссылка на GitHub Issue;
- описание ошибки;
- запрос новой функции;
- отзыв пользователя;
- заметки или требования.

## Порядок работы

1. Прочитать предоставленный источник.
2. Сохранить его URL или внешний идентификатор.
3. Отделить подтверждённые факты от предположений.
4. Определить предполагаемый тип задачи:
   - ошибка;
   - пользовательская история;
   - техническая задача;
   - исследование.
5. Найти недостающую информацию.
6. Задать только те вопросы, без которых нельзя подготовить полезный черновик.
7. Если доступны инструменты Jira только для чтения, найти возможные дубликаты.
8. Подготовить черновик по шаблону `references/ticket-template.md`.
9. Проверить, что критерии приёмки наблюдаемы и проверяемы.
10. Перечислить нерешённые вопросы и предположения.

## Обязательные правила

- Никогда не создавать и не изменять задачи Jira.
- Не придумывать отсутствующие факты.
- Помечать неподтверждённые сведения как `[ПРЕДПОЛОЖЕНИЕ — не проверено]`.
- Не назначать приоритет, исполнителя, оценку или срок без исходных данных.
- Сохранять ссылку на первоначальный источник.
- Не включать секреты и лишние персональные данные.
- Отвечать на языке пользователя.

## Критерии завершения

Черновик должен содержать:

- предполагаемый проект;
- тип задачи;
- краткий заголовок;
- описание проблемы;
- текущее и ожидаемое поведение;
- критерии приёмки;
- ограничения задачи;
- ссылку на источник;
- предположения;
- нерешённые вопросы;
- возможные дубликаты либо отметку, что поиск не выполнялся.
