# Как создавать и использовать правила Cursor

Правило (rule) — это постоянная инструкция для AI-агента в Cursor. Агент не
помнит прошлые чаты, поэтому без правил ему приходится объяснять одно и то же
заново. Когда правило срабатывает, Cursor сам передаёт его текст агенту
в начале работы — как памятку для нового сотрудника.

Инструкция основана на официальной документации:
[Rules](https://cursor.com/docs/rules). Готовые заготовки лежат
в [`templates/rule/`](../templates/rule/README.md).

## Шаг 1. Выберите тип правила

Cursor поддерживает четыре типа правил:

| Что нужно | Тип правила | Где хранится |
| --- | --- | --- |
| Правила одного проекта, которые хранятся вместе с ним | **Project Rule** | Файлы `.mdc` в папке `.cursor/rules` проекта |
| Простая памятка для проекта без настроек | **`AGENTS.md`** | Файл `AGENTS.md` в корне проекта |
| Личные предпочтения во всех ваших проектах | **User Rule** | Настройки Cursor: **Customize → Rules** |
| Единые правила для всей команды | **Team Rule** | Дашборд Cursor, тарифы Team и Enterprise |

Все подходящие правила действуют вместе. Если они противоречат друг другу,
главнее Team Rules, затем Project Rules, затем User Rules.

## Шаг 2. Для Project Rule выберите, когда правило срабатывает

| Тип | Когда правило срабатывает | Пример |
| --- | --- | --- |
| **Always Apply** | В каждом чате | «Не изменяй сгенерированные файлы в папке `dist/`» |
| **Apply Intelligently** | Когда агент сам решит, что правило относится к задаче. Он судит по описанию правила | Как оформлять коммиты и описания pull request |
| **Apply to Specific Files** | Когда агент работает с файлом, подходящим под glob-шаблон | Требования к документам в папке `docs/` |
| **Apply Manually** | Только когда вы упомянули правило в чате через `@` | Памятка «объясняй простыми словами», которую вы вызываете сами |

Glob-шаблон — короткая запись, которая описывает сразу много файлов. Например,
`docs/**/*.md` — это все файлы `.md` в папке `docs` и её подпапках.

## Шаг 3. Создайте правило

### Project Rule

Подойдёт любой из способов:

1. **Попросить агента.** Наберите в чате `/create-rule` и опишите своими
   словами, что нужно. Агент создаст файл правила с нужными настройками
   в папке `.cursor/rules`.
2. **Через меню.** Откройте **Customize** в боковой панели, перейдите
   в **Rules** и нажмите **Add Rule**. Cursor создаст файл правила
   в `.cursor/rules`. Тип правила выбирается в выпадающем списке.
3. **По шаблону.** Скопируйте подходящий файл из
   [`templates/rule/`](../templates/rule/README.md) в папку `.cursor/rules`
   своего проекта и замените текст в квадратных скобках.

Файл правила выглядит так:

```md
---
alwaysApply: true
---

- Не изменяй сгенерированные файлы в папках `dist/` и `build/`.
- Если не уверен в деталях, сначала прочитай связанные файлы.
```

Строки между `---` — настройки: они задают тип правила. Ниже — текст правила
обычными словами. Расширение файла должно быть `.mdc`: файлы `.md` в папке
`.cursor/rules` Cursor игнорирует.

### AGENTS.md

Создайте в корне проекта файл `AGENTS.md` и напишите в нём указания обычным
текстом. Настроек у этого файла нет. Шаблон —
[`AGENTS.template.md`](../templates/rule/AGENTS.template.md).

Такой же файл можно положить в подпапку. Он действует, когда агент работает
с файлами этой папки, и дополняет указания из корня проекта.

### User Rule

Откройте **Customize → Rules** и добавьте свои предпочтения обычным текстом,
например: «Отвечай кратко, без повторов и лишних слов». Шаблон —
[`user-rule.md`](../templates/rule/user-rule.md).

### Team Rule

Правило создаёт администратор команды в
[дашборде Cursor](https://cursor.com/dashboard/team-content). Текст пишется
в свободной форме. Шаблон — [`team-rule.md`](../templates/rule/team-rule.md).
При создании доступны настройки:

- **Glob-шаблон** — правило действует, только когда агент работает
  с подходящими файлами. Без шаблона оно действует в каждом чате.
- **Enable this rule immediately** — правило начинает действовать сразу.
  Без этой отметки оно сохраняется как черновик.
- **Enforce this rule** — правило обязательно для всех участников. Правило
  без этой отметки участник может отключить у себя в **Customize**.

## Шаг 4. Пользуйтесь правилом

| Правило | Что нужно сделать |
| --- | --- |
| Always Apply, `AGENTS.md`, User Rule, Team Rule | Ничего: правило действует само |
| Apply Intelligently | Просто опишите задачу: агент сам подключит подходящее правило |
| Apply to Specific Files | Работайте с файлами, которые подходят под glob-шаблон |
| Apply Manually | Наберите в чате `@` и имя правила, например `@my-rule` |

Все правила и их состояние видны в **Customize → Rules**. Правила действуют
только на агента в чате: на автодополнение Cursor Tab и другие AI-функции
они не влияют.

## Шаг 5. Проверьте и улучшайте

1. Откройте **Customize → Rules** и убедитесь, что правило есть в списке.
2. Откройте новый чат и дайте задачу, в которой правило должно сработать.
3. Если агент снова ошибся, уточните текст правила.
4. Сохраните файлы правил в git вместе с проектом — тогда правила получит
   вся команда.

## Как написать хорошее правило

- Пишите конкретно, как понятную инструкцию: что делать и чего не делать.
- Одно правило — одна тема. Большое правило разделите на несколько.
- Держите правило короче 500 строк.
- Приводите примеры или ссылайтесь на файл-образец: `@имя-файла`. Агент сам
  прочитает этот файл, когда он понадобится.
- Не пересказывайте то, что агент и так знает: общие правила стиля,
  известные команды, редкие случаи.
- Начинайте с малого: добавляйте правило, когда агент повторяет одну и ту же
  ошибку.

## Если правило не срабатывает

Проверьте по списку:

- **Любой Project Rule.** Файл лежит в папке `.cursor/rules` и имеет
  расширение `.mdc`.
- **Apply Intelligently.** У правила заполнено описание (`description`).
- **Apply to Specific Files.** Glob-шаблон подходит к файлам, с которыми вы
  работаете.
- **Apply Manually.** Правило упомянуто в чате через `@`.
- **Team Rule.** Правило включено администратором и не отключено вами
  в **Customize**.
