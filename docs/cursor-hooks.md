# Как создавать и использовать хуки Cursor

Хук (hook) — это действие, которое Cursor выполняет сам в определённый момент
работы: перед командой в терминале, после правки файла, при отправке запроса.
Правило — это просьба к агенту, и агент может ей не последовать. Хук
срабатывает каждый раз, как турникет на входе: он не зависит от решения
агента.

Зачем нужны хуки:

- **Порядок в коде.** Форматировать файлы сразу после правок агента.
- **Журнал.** Записывать, какие команды выполнял агент и какие файлы менял.
- **Защита данных.** Искать пароли, ключи и персональные данные до того, как
  они попадут в запрос.
- **Защита от опасных действий.** Останавливать команды, которые удаляют
  данные, или спрашивать подтверждение.
- **Контроль субагентов.** Разрешать или запрещать запуск субагентов.
- **Подготовка чата.** Добавлять нужные сведения в начало каждого нового чата.

Инструкция основана на официальной документации:
[Hooks](https://cursor.com/docs/hooks). Готовые заготовки лежат
в [`templates/hook/`](../templates/hook/README.md).

## Шаг 1. Решите, нужен ли хук

| Хук подходит, если | Достаточно правила (rule), если |
| --- | --- |
| Действие должно выполняться каждый раз, без исключений | Достаточно попросить агента, и редкий пропуск не страшен |
| Действие нужно проверить или запретить до того, как оно выполнено | Нужно объяснить агенту, как принято работать в проекте |
| Требование звучит как «когда происходит X, сделай Y» | Требование нельзя проверить автоматически |

Хук — это программа, которая запускается на вашем компьютере автоматически.
Устанавливайте только те хуки, которым доверяете, и просматривайте чужие
скрипты перед установкой. Как создавать правила, описано
в [`docs/cursor-rules.md`](cursor-rules.md).

## Шаг 2. Ответьте на три вопроса

Тип хука складывается из трёх ответов: где хук хранится, как он выполняется
и что его запускает.

### Где хранится хук

| Что нужно | Тип хука | Где хранится |
| --- | --- | --- |
| Хук одного проекта, общий для команды | **Project hooks** | Файл `.cursor/hooks.json` в проекте |
| Личный хук во всех ваших проектах | **User hooks** | Файл `~/.cursor/hooks.json` — в домашней папке пользователя |
| Хук для всей команды во всех её проектах | **Team hooks** | Дашборд Cursor; только тариф Enterprise |
| Хук для всех компьютеров организации | **Enterprise hooks** | Системная папка компьютера; файлы раздаёт IT-отдел |

Все подходящие хуки выполняются вместе. Если один хук разрешает действие,
а другой запрещает, побеждает запрет.

### Как выполняется хук

| Что нужно | Тип хука | Как работает |
| --- | --- | --- |
| Точная проверка, одинаковая каждый раз | **Command-based hooks** (по умолчанию) | Cursor запускает скрипт — небольшую программу |
| Правило, которое проще описать словами | **Prompt-based hooks** | Условие обычными словами проверяет AI-модель |

### Что запускает хук

| Что нужно | Тип хука | События |
| --- | --- | --- |
| Следить за работой агента в чате | **Agent hooks** | 18 событий: команды, файлы, инструменты, запросы |
| Следить за автодополнением Tab — подсказками в редакторе | **Tab hooks** | 2 события: чтение и правка файла |
| Выполнить действие при открытии проекта | **App lifecycle hooks** | 1 событие: Cursor открыл проект |

Если сомневаетесь, начните с такого сочетания: Project hooks, Command-based
hooks, Agent hooks — то есть скрипт в проекте, который следит за работой
агента.

## Шаг 3. Выберите событие

Событие — момент, в который срабатывает хук. Самые полезные события:

| Когда должен сработать хук | Событие | Что может хук |
| --- | --- | --- |
| Агент собирается выполнить команду в терминале | `beforeShellExecution` | Разрешить, запретить или спросить вас |
| Агент собирается прочитать файл | `beforeReadFile` | Разрешить или запретить |
| Агент изменил файл | `afterFileEdit` | Выполнить действие, например форматирование |
| Вы отправили запрос, но он ещё не ушёл | `beforeSubmitPrompt` | Не отправить запрос |
| Агент собирается обратиться к внешнему сервису (MCP) | `beforeMCPExecution` | Разрешить, запретить или спросить вас |
| Агент собирается использовать любой инструмент | `preToolUse` | Разрешить или запретить |
| Агент собирается запустить субагента | `subagentStart` | Разрешить или запретить |
| Агент закончил работу над запросом | `stop` | Продолжить работу новым сообщением |
| Создан новый чат | `sessionStart` | Добавить сведения в чат |
| Tab собирается прочитать файл | `beforeTabFileRead` | Разрешить или запретить |
| Cursor открыл проект | `workspaceOpen` | Подключить плагины из папок |

События, имя которых начинается с `before`, срабатывают до действия и могут
его запретить. События, имя которых начинается с `after` или `post`,
срабатывают после действия и отменить его уже не могут. Полный список
из 21 события приведён в [`templates/hook/README.md`](../templates/hook/README.md).

## Шаг 4. Создайте хук

### Project hooks и User hooks

Подойдёт любой из способов:

1. **Попросить агента.** Наберите в чате `/create-hook` и опишите своими
   словами, что нужно. Например: «Создай хук, который после каждой правки
   PHP-файла запускает форматирование».
2. **По шаблону.** Скопируйте подходящий файл и скрипты из
   [`templates/hook/`](../templates/hook/README.md) в папку `.cursor` проекта
   или в `~/.cursor` и впишите свои условия.
3. **По промпту.** Возьмите готовый текст запроса из таблицы в конце этой
   инструкции: агент задаст уточняющие вопросы и подготовит хук.

Хук состоит из двух частей. Первая — запись в файле `hooks.json`: она говорит,
в какой момент и какой скрипт запустить.

```json
{
  "version": 1,
  "hooks": {
    "afterFileEdit": [
      {
        "command": ".cursor/hooks/format.sh"
      }
    ]
  }
}
```

Эта запись означает: «когда агент изменил файл, запусти скрипт
`.cursor/hooks/format.sh`». Вторая часть — сам скрипт. Cursor передаёт ему
сведения о событии, а скрипт печатает ответ:

```bash
#!/usr/bin/env bash
# Прочитать сведения о событии и ответить «ничего не менять».
cat > /dev/null
printf '%s\n' '{}'
```

| Настройка | Что означает |
| --- | --- |
| `version` | Версия формата файла. Всегда `1` |
| `command` | Какой скрипт запустить |
| `matcher` | Условие: запускать хук только для подходящих команд или инструментов |
| `timeout` | Сколько секунд ждать ответа скрипта |
| `failClosed` | `true` — если хук сломался, действие запрещается. Без этой настройки действие выполняется |
| `type` и `prompt` | Вместо скрипта — условие обычными словами, которое проверяет AI-модель |

Путь к скрипту зависит от места хранения. В хуках проекта его пишут от корня
проекта: `.cursor/hooks/format.sh`. В личных хуках — от папки `~/.cursor`:
`./hooks/format.sh`.

Файл `hooks.json` Cursor проверяет строго: в нём не должно быть комментариев,
а имена событий пишутся точно, с учётом больших и маленьких букв. Одна ошибка
отключает все хуки этого файла. Скрипт должен быть исполняемым — то есть
файлом, который разрешено запускать как программу: для этого выполняют команду
`chmod +x` с путём к скрипту.

### Team hooks

Team hook — не файл проекта. Его создаёт администратор команды
в [дашборде Cursor](https://cursor.com/dashboard/team-content?section=hooks),
а Cursor сам доставляет хук на компьютеры участников и обновляет его каждые
тридцать минут. Один хук в дашборде — один скрипт или одно условие для одного
события. Доступно только на тарифе Enterprise. Форма для администратора —
[`team-hooks.md`](../templates/hook/team-hooks.md).

### Enterprise hooks

Хуки организации лежат в системной папке компьютера и действуют для всех его
пользователей. Файлы на компьютеры сотрудников раздаёт IT-отдел: Cursor их
не раздаёт и не обновляет. Шаблон —
[`enterprise-hooks.json`](../templates/hook/enterprise-hooks.json).

## Шаг 5. Проверьте хук

1. Откройте **Customize** в боковой панели и перейдите на вкладку **Hooks**:
   хук должен быть в списке.
2. Вызовите событие. Например, попросите агента изменить файл или выполнить
   команду.
3. Откройте панель **Output** и выберите в списке канал **Hooks**: в нём
   видно, какие хуки запускались и с какими ошибками.
4. Cursor сам перечитывает `hooks.json` после сохранения. Если хук
   не появился, перезапустите Cursor.

## Шаг 6. Поделитесь хуком

| Кому нужен хук | Что сделать |
| --- | --- |
| Всем, кто работает с проектом | Сохраните `.cursor/hooks.json` и папку `.cursor/hooks` в git вместе с проектом |
| Всей команде во всех проектах | Попросите администратора создать Team hook в дашборде |
| Всем компьютерам организации | Передайте файлы IT-отделу: это Enterprise hooks |
| Другим командам | Упакуйте хуки в плагин: [`docs/cursor-plugin.md`](cursor-plugin.md) |

User hooks остаются только на вашем компьютере.

## Как написать хороший хук

- Один хук — одна понятная задача.
- Сначала проверьте хук без условия `matcher`: так видно, что он вообще
  срабатывает. Затем сузьте условие.
- Пишите понятные сообщения: что запрещено и что делать вместо этого.
- Хук запускается при каждом событии. Чем больше хуков и чем медленнее
  скрипты, тем дольше ждёт агент.
- Для хуков, от которых зависит безопасность, включайте `failClosed`: тогда
  сломанный хук запрещает действие, а не пропускает его.
- Не храните в скриптах пароли и ключи доступа.
- Хук с условием для AI-модели может ошибаться. Строгие запреты оформляйте
  скриптом.

## Если хук не срабатывает

Проверьте по списку:

- **Хука нет в списке.** Файл называется `hooks.json` и лежит в папке
  `.cursor` проекта или в `~/.cursor`. В файле нет ошибок и комментариев:
  одна ошибка отключает все хуки файла. Вы доверяете проекту: хуки проекта
  не работают в недоверенном проекте.
- **Скрипт не запускается.** Путь к скрипту записан от правильной папки,
  а скрипт исполняемый.
- **Хук срабатывает не тогда, когда нужно.** Имя события выбрано верно,
  а условие `matcher` подходит к событию. Для проверки временно уберите его.
- **Хук запрещает всё подряд.** Скрипт печатает что-то кроме ответа. Для
  событий, которые разрешают или запрещают действие, непонятный ответ
  считается запретом.
- **Хук не запрещает действие.** Событие срабатывает до действия: события
  `after` и `post` запретить ничего не могут. Ответ «спросить пользователя»
  работает только для `beforeShellExecution` и `beforeMCPExecution`.
- **Хук не работает в облаке.** Облачные агенты выполняют только скрипты
  из `.cursor/hooks.json` проекта, а на тарифе Enterprise — также Team hooks
  и Enterprise hooks, и не все события. User hooks, Tab hooks и Prompt-based
  hooks в облаке не работают.
- **Изменения не подхватились.** Перезапустите Cursor.

## Шаблоны и промпты

Промпт — готовый текст запроса для агента. По нему агент задаёт уточняющие
вопросы, готовит хук и ждёт вашего подтверждения.

| Тип хука | Шаблон | Промпт |
| --- | --- | --- |
| Project hooks — хуки одного проекта | [`project-hooks.json`](../templates/hook/project-hooks.json) | [создать](../prompts/create-hook-project.md) |
| User hooks — личные хуки | [`user-hooks.json`](../templates/hook/user-hooks.json) | [создать](../prompts/create-hook-user.md) |
| Team hooks — хуки команды | [`team-hooks.md`](../templates/hook/team-hooks.md) | [создать](../prompts/create-hook-team.md) |
| Enterprise hooks — хуки организации | [`enterprise-hooks.json`](../templates/hook/enterprise-hooks.json) | [создать](../prompts/create-hook-enterprise.md) |
| Command-based hooks — хук запускает скрипт | [`command-based-hooks.json`](../templates/hook/command-based-hooks.json) | [создать](../prompts/create-hook-command-based.md) |
| Prompt-based hooks — условие проверяет AI-модель | [`prompt-based-hooks.json`](../templates/hook/prompt-based-hooks.json) | [создать](../prompts/create-hook-prompt-based.md) |
| Agent hooks — события агента в чате | [`agent-hooks.json`](../templates/hook/agent-hooks.json) | [создать](../prompts/create-hook-agent.md) |
| Tab hooks — события автодополнения Tab | [`tab-hooks.json`](../templates/hook/tab-hooks.json) | [создать](../prompts/create-hook-tab.md) |
| App lifecycle hooks — Cursor открыл проект | [`app-lifecycle-hooks.json`](../templates/hook/app-lifecycle-hooks.json) | [создать](../prompts/create-hook-app-lifecycle.md) |

У каждого шаблона `.json` есть копия с пояснениями к каждой строке — файл
с тем же именем и окончанием `.annotated.jsonc`. Скрипты-заготовки лежат
в папке [`templates/hook/hooks/`](../templates/hook/README.md). Хуки внутри
плагина описаны в [шаблоне плагина](../templates/plugin/README.md).
