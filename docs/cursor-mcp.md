# Как подключать и использовать MCP в Cursor

MCP (Model Context Protocol) — способ подключить Cursor к внешним сервисам
и данным: трекеру задач, базе данных, макетам, документации. Связь
обеспечивает MCP-сервер — программа-посредник между Cursor и сервисом. Его
можно сравнить с переходником: у каждого сервиса свой разъём, а MCP-сервер
превращает его в розетку, к которой Cursor умеет подключаться.

Агент получает от сервера инструменты — действия, которые он может выполнить:
найти задачу, прочитать макет, посмотреть структуру базы данных. Данные
не нужно копировать в чат: агент берёт их сам.

Зачем нужен MCP:

- **Задачи и документы.** Агент читает задачу в трекере, требования
  и заметки там, где они хранятся.
- **Данные.** Агент сверяется с базой данных и другими сервисами, а не
  угадывает.
- **Макеты.** Агент сравнивает экран с макетом.
- **Действия.** Агент выполняет действия во внешнем сервисе, например
  оставляет комментарий к задаче.

Инструкция основана на официальной документации:
[Model Context Protocol (MCP)](https://cursor.com/docs/mcp)
и [MCP integrations](https://cursor.com/help/customization/mcp). Готовые
заготовки лежат в [`templates/mcp/`](../templates/mcp/README.md).

## Шаг 1. Решите, нужен ли MCP-сервер

| MCP-сервер подходит, если | Достаточно другого средства, если |
| --- | --- |
| Агенту нужны данные, которых нет в проекте: задачи, макеты, документы, записи базы данных | Сведения можно один раз записать в правило (rule) или в файл проекта |
| Агент должен выполнять действия во внешнем сервисе | Действие — команда в терминале, которую агент может выполнить и так |
| Данные часто меняются, и копировать их в чат неудобно | Данные нужны один раз: проще вставить их в запрос |

MCP-сервер получает данные, которые передаёт ему агент, и выполняет действия
от вашего имени. Подключайте только те серверы, которым доверяете. Как
создавать правила, описано в [`docs/cursor-rules.md`](cursor-rules.md).

## Шаг 2. Найдите сервер и проверьте его

Где искать серверы:

- [Cursor Marketplace](https://cursor.com/marketplace) — официальные плагины
  и серверы, которые устанавливаются в один клик;
- [cursor.directory](https://cursor.directory) — плагины и серверы
  сообщества;
- официальная документация сервиса, который вы хотите подключить.

Перед подключением проверьте сервер:

- **Источник.** Сервер выпущен разработчиком, которому вы доверяете.
- **Доступ.** Понятно, какие данные и сервисы сервер читает и изменяет.
- **Ключи.** Ключ доступа можно выдать с наименьшими правами, которых
  достаточно серверу, например только на чтение.
- **Код.** Для важных подключений исходный код сервера просмотрел
  специалист.

## Шаг 3. Ответьте на два вопроса

Тип подключения складывается из двух ответов: как Cursor связывается
с сервером и где хранится конфигурация — запись о сервере.

### Как подключается сервер

Способ подключения указан в документации сервера: там приведена либо команда
запуска, либо адрес.

| Что известно о сервере | Тип | Что указывают |
| --- | --- | --- |
| Сервер — программа, которая запускается на вашем компьютере | **stdio server** | Команду запуска |
| Сервер развёрнут отдельно и доступен по адресу для HTTP | **Streamable HTTP server** | Адрес |
| Сервер развёрнут отдельно и доступен только по адресу для SSE | **SSE server** | Адрес |
| Владелец сервера заранее выдаёт Client ID для входа | **Remote server with Static OAuth** | Адрес, Client ID и Client Secret |

Если сервер предлагает адрес и для HTTP, и для SSE, выбирайте Streamable
HTTP server.

### Где хранится конфигурация

| Что нужно | Тип | Где хранится |
| --- | --- | --- |
| Серверы одного проекта, общие для команды | **Project Configuration** | Файл `.cursor/mcp.json` в проекте |
| Личные серверы во всех ваших проектах | **Global Configuration** | Файл `~/.cursor/mcp.json` — в домашней папке пользователя |
| Сервер для всей команды и её облачных агентов | **Team MCP server** | Дашборд Cursor; сервер добавляет администратор команды |

Cursor объединяет серверы проекта и личные серверы. Если имя сервера
совпадает, действует запись проекта.

## Шаг 4. Подключите сервер

### В один клик

Если нужный сервер есть в Cursor Marketplace, файл не понадобится:

1. Откройте **Customize** в боковой панели.
2. Перейдите в раздел **MCPs**.
3. Найдите сервер в списке или через поиск.
4. Нажмите **Add to Cursor** рядом с сервером.
5. Если сервис просит войти, выполните вход.

### Через файл mcp.json

Подойдёт любой из способов:

1. **По шаблону.** Скопируйте подходящий файл из
   [`templates/mcp/`](../templates/mcp/README.md) в папку `.cursor` проекта
   или в `~/.cursor` под именем `mcp.json` и впишите свои данные.
2. **По промпту.** Возьмите готовый текст запроса из таблицы в конце этой
   инструкции: агент задаст уточняющие вопросы и подготовит запись.

Файл `mcp.json` — список серверов. У каждого сервера есть имя и настройки:

```json
{
  "mcpServers": {
    "project-tools": {
      "type": "stdio",
      "command": "node",
      "args": ["${workspaceFolder}/tools/mcp-server.js"]
    },
    "issue-tracker": {
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${env:MY_SERVICE_TOKEN}"
      }
    }
  }
}
```

Первая запись означает: «сервер `project-tools` — программа из папки проекта,
запусти её командой `node`». Вторая: «сервер `issue-tracker` доступен
по адресу, а ключ доступа возьми из переменной окружения `MY_SERVICE_TOKEN`».

| Настройка | Что означает |
| --- | --- |
| `mcpServers` | Список серверов: имя сервера и его настройки |
| `command` и `args` | Локальный сервер: команда запуска и её аргументы |
| `env` и `envFile` | Локальный сервер: переменные окружения — настройки и ключи доступа |
| `url` | Удалённый сервер: его адрес |
| `headers` | Удалённый сервер: заголовки с ключом доступа |
| `auth` | Удалённый сервер: Client ID и Client Secret для Static OAuth |
| `${env:ИМЯ}` | Подстановка: значение берётся из переменной окружения и не хранится в файле |
| `${workspaceFolder}` | Подстановка: корень проекта |

Ключи доступа и пароли в `mcp.json` не записывают: файл проекта увидят все,
у кого есть доступ к репозиторию. Ключ хранят в переменной окружения —
именованном значении в настройках системы. На macOS и Linux её задают строкой
`export MY_SERVICE_TOKEN="значение"` в файле профиля оболочки, например
`~/.zshrc`. Если вы делаете это впервые, попросите помощи у разработчика.

После изменения `mcp.json` или переменных окружения сохраните файл
и перезапустите Cursor.

### Team MCP server

Team MCP server — не файл проекта. Его добавляет администратор команды
в [дашборде Cursor](https://cursor.com/dashboard/plugins), в разделе
**Plugins & MCPs**. Такой сервер доступен облачным агентам команды. Чтобы
участники могли установить его и в приложении Cursor, администратор выбирает
**Add to Team Marketplace**. Форма для администратора —
[`team-mcp.md`](../templates/mcp/team-mcp.md).

## Шаг 5. Проверьте сервер

1. Откройте **Customize** в боковой панели и перейдите в раздел **MCPs**:
   сервер должен быть в списке и включён. Сервер из файла проекта может
   ждать, пока вы его включите.
2. Если сервис просит войти, выполните вход там же.
3. Попросите агента воспользоваться сервером: назовите инструмент или просто
   опишите, что нужно. Cursor сам использует инструменты MCP, когда они
   подходят к запросу.
4. По умолчанию Cursor спрашивает разрешение перед вызовом инструмента.
   Нажмите на стрелку рядом с именем инструмента, чтобы увидеть, какие
   данные агент передаёт серверу.
5. Если сервер не подключился, откройте панель **Output** и выберите
   в списке **MCP Logs**: в журнале видны запуск сервера, вызовы
   инструментов и ошибки.

## Шаг 6. Поделитесь сервером

| Кому нужен сервер | Что сделать |
| --- | --- |
| Всем, кто работает с проектом | Сохраните `.cursor/mcp.json` в git вместе с проектом. Ключи доступа каждый участник задаёт на своём компьютере |
| Всей команде и её облачным агентам | Попросите администратора добавить Team MCP server в дашборде |
| Другим командам | Упакуйте серверы в плагин: [`docs/cursor-plugin.md`](cursor-plugin.md) |

Серверы из `~/.cursor/mcp.json` остаются только на вашем компьютере.

## Как безопасно пользоваться MCP

- Подключайте только нужные серверы. Сервер, который сейчас не нужен, можно
  выключить в разделе **Customize → MCPs**, не удаляя его.
- Имя пакета, команду запуска и адрес берите из официальной документации
  сервера. Команда вроде `npx -y` загружает пакет из интернета и сразу
  запускает его: из-за ошибки в имени может запуститься чужая программа.
- Не записывайте ключи доступа и пароли в `mcp.json`.
- Выдавайте серверу ключ с наименьшими правами. Если агенту достаточно
  читать данные, не давайте права на изменение.
- Смотрите, что агент передаёт серверу, прежде чем разрешить вызов
  инструмента.
- С закрытыми данными работайте через локальные серверы — stdio server.
- Не передавайте серверу лишнего. Сервер получает все переменные из файла,
  указанного в `envFile`.

## Если сервер не работает

Проверьте по списку:

- **Сервера нет в списке.** Файл называется `mcp.json` и лежит в папке
  `.cursor` проекта или в `~/.cursor`. В файле нет ошибок записи. После
  изменения файла Cursor был перезапущен.
- **Сервер выключен.** Включите его в разделе **Customize → MCPs**. Сервер
  из файла проекта включают вручную, а после изменения его записи,
  возможно, придётся включить снова.
- **Локальный сервер не запускается.** Программа из `command` установлена,
  а имя пакета и путь указаны точно. Причина ошибки видна в журнале
  **MCP Logs**.
- **Удалённый сервер не подключается.** Адрес указан без ошибок, вход
  в сервис выполнен, ключ доступа действует.
- **Сервер не получает ключ.** Переменная окружения задана, её имя
  в `mcp.json` записано без ошибок, а Cursor перезапущен после её
  изменения.
- **Агент не пользуется сервером.** Назовите инструмент в запросе
  и проверьте, что сервер включён.
- **Сервер работает на компьютере, но не в облачном агенте.** Для облачных
  агентов серверы настраивают отдельно: личные — на странице
  [cursor.com/agents](https://cursor.com/agents), общие — администратор
  команды в дашборде. Входы в сервисы у облачных агентов свои. Собственные
  серверы с подключением по SSE облачные агенты не поддерживают.
- **Сервер заблокирован.** На тарифе Enterprise администратор может
  ограничить список серверов, которые разрешено запускать. Обратитесь
  к администратору.
- **Сервер перестал отвечать во время работы.** Cursor покажет ошибку
  в чате и отметит вызов как неудачный. Повторите запрос или посмотрите
  журнал **MCP Logs**. Остальные серверы продолжают работать.
- **Нужна новая версия сервера.** Для сервера, который запускается через
  `npx`: удалите сервер в разделе **Customize → MCPs**, выполните команду
  `npm cache clean --force` и добавьте сервер снова.

## Шаблоны и промпты

Промпт — готовый текст запроса для агента. По нему агент задаёт уточняющие
вопросы, готовит запись о сервере и ждёт вашего подтверждения.

| Тип | Шаблон | Промпт |
| --- | --- | --- |
| stdio server — локальный сервер-программа | [`stdio-server.json`](../templates/mcp/stdio-server.json) | [создать](../prompts/create-mcp-stdio.md) |
| SSE server — удалённый сервер, адрес для SSE | [`sse-server.json`](../templates/mcp/sse-server.json) | [создать](../prompts/create-mcp-sse.md) |
| Streamable HTTP server — удалённый сервер, адрес для HTTP | [`streamable-http-server.json`](../templates/mcp/streamable-http-server.json) | [создать](../prompts/create-mcp-streamable-http.md) |
| Remote server with Static OAuth — вход с заранее выданным Client ID | [`static-oauth-server.json`](../templates/mcp/static-oauth-server.json) | [создать](../prompts/create-mcp-static-oauth.md) |
| Project Configuration — серверы одного проекта | [`project-mcp.json`](../templates/mcp/project-mcp.json) | [создать](../prompts/create-mcp-project.md) |
| Global Configuration — личные серверы | [`global-mcp.json`](../templates/mcp/global-mcp.json) | [создать](../prompts/create-mcp-global.md) |
| Team MCP server — сервер для всей команды | [`team-mcp.md`](../templates/mcp/team-mcp.md) | [создать](../prompts/create-mcp-team.md) |

У каждого шаблона `.json` есть копия с пояснениями к каждой строке — файл
с тем же именем и окончанием `.annotated.jsonc`. MCP-серверы внутри плагина
описаны в [шаблоне плагина](../templates/plugin/README.md).
