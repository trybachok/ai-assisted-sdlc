# Как создавать и использовать субагентов Cursor

Субагент (subagent) — это отдельный AI-помощник, которому основной агент
Cursor поручает часть работы. Субагент получает задание, выполняет его
самостоятельно и возвращает только итог. Это похоже на поручение коллеге:
вы объясняете задачу, а в ответ получаете короткий отчёт, а не все черновики.

Зачем нужны субагенты:

- **Чистый чат.** У субагента своя «рабочая память» (окно контекста): долгие
  поиски и разборы не занимают место в основном чате.
- **Параллельная работа.** Несколько субагентов работают одновременно.
- **Специализация.** У субагента свои инструкции, права и модель.
- **Повторное использование.** Субагента описывают один раз, а пользуются им
  постоянно.

Инструкция основана на официальной документации:
[Subagents](https://cursor.com/docs/subagents). Готовые заготовки лежат
в [`templates/subagent/`](../templates/subagent/README.md).

## Шаг 1. Решите, нужен ли субагент

| Субагент подходит, если | Достаточно навыка (skill), если |
| --- | --- |
| Нужно долгое исследование, которое не должно засорять основной чат | Задача одна и простая: составить список изменений, отформатировать текст |
| Несколько частей работы идут параллельно | Нужно быстрое повторяемое действие |
| Задача требует специальных знаний и многих шагов | Задача выполняется за один шаг |
| Нужна независимая проверка сделанной работы | Отдельная «рабочая память» не нужна |

Субагент не ускоряет простые задачи: он начинает с чистого листа и расходует
токены отдельно от основного агента. Пять субагентов, работающих параллельно,
тратят примерно в пять раз больше токенов, чем один агент. Шаблон навыка —
[`templates/skill/`](../templates/skill/README.md).

## Шаг 2. Выберите вид субагента

| Что нужно | Вид субагента | Где хранится или как запускается |
| --- | --- | --- |
| Найти что-то в коде или поработать с браузером | **Встроенный**: Explore и Browser | Создавать не нужно: агент использует их сам |
| Помощник для одного проекта, общий для команды | **Project subagent** | Файл в папке `.cursor/agents` проекта |
| Личный помощник во всех ваших проектах | **User subagent** | Файл в папке `~/.cursor/agents` — в домашней папке пользователя |
| Долгая задача, которая выполняется в облаке | **Cloud subagent** | Команда `/in-cloud` в окне Agents Window |

Если у двух субагентов одинаковое имя, главнее Project subagent.

## Шаг 3. Для своего субагента выберите режим и права

| Настройка | Вариант | Как работает | Пример |
| --- | --- | --- | --- |
| Режим | **Foreground** (по умолчанию) | Основной агент ждёт, пока субагент закончит, и сразу получает результат | Проверка выполненной задачи |
| Режим | **Background** | Субагент работает в фоне, основной агент его не ждёт | Долгий запуск всех тестов |
| Права | Обычные (по умолчанию) | Субагент может изменять файлы и запускать команды | Исправление ошибки |
| Права | **Только чтение** | Субагент не изменяет файлы и не выполняет команды, меняющие состояние | Проверка безопасности |

Режим и права не зависят друг от друга и от места хранения: например, личный
субагент может работать в фоне и только на чтение.

## Шаг 4. Создайте субагента

### Project subagent и User subagent

Подойдёт любой из способов:

1. **Попросить агента.** Наберите в чате `/create-subagent` и опишите своими
   словами, какой помощник нужен. Например: «Создай субагента в файле
   `.cursor/agents/verifier.md`: он проверяет выполненную работу, запускает
   тесты и сообщает, что работает, а что нет».
2. **Через меню.** Откройте **Customize** в боковой панели и перейдите
   в **Subagents**: там можно добавлять субагентов и управлять ими.
3. **По шаблону.** Скопируйте подходящий файл из
   [`templates/subagent/`](../templates/subagent/README.md) в папку
   `.cursor/agents` проекта или в `~/.cursor/agents` и замените текст
   в квадратных скобках.

Файл субагента выглядит так:

```md
---
name: verifier
description: Проверяет выполненную работу. Используй после того, как задача названа готовой.
readonly: false
is_background: false
---

Ты — придирчивый проверяющий. Убедись, что работа, названная выполненной,
действительно сделана.

При вызове:

1. Определи, какая работа названа выполненной.
2. Проверь, что реализация существует и работает.
3. Запусти тесты.

Сообщи, что подтверждено, а что не сделано или не работает.
```

Строки между `---` — настройки. Ниже — задание для субагента обычными
словами. Субагент не видит переписку основного агента, поэтому всё важное
должно быть в задании.

| Настройка | Что означает |
| --- | --- |
| `name` | Имя субагента: строчные латинские буквы и дефисы. Совпадает с именем файла |
| `description` | Что делает субагент и когда ему передавать задачу. По описанию агент решает, поручать ли работу |
| `model` | Модель. Без этой строки субагент работает на той же модели, что и основной агент |
| `readonly` | `true` — права «только чтение» |
| `is_background` | `true` — режим Background |

Каждую настройку пишите в одну строку, без кавычек и без пояснений после
значения — иначе Cursor прочитает её неверно.

### Cloud subagent

Cloud subagent — не файл. В приложении Cursor откройте Agents Window, наберите
`/in-cloud` и отправьте задачу: она выполнится в облаке, на отдельной
виртуальной машине и в отдельной ветке, а ваш компьютер останется свободным.
Чтобы субагент довёл до слияния уже открытый pull request, используйте
`/autopilot`. Шаблон задачи —
[`cloud-subagent.md`](../templates/subagent/cloud-subagent.md).

Облачным агентам нужен доступ к репозиторию и тариф, в который они входят.
Подробнее — [Cloud Agents](https://cursor.com/docs/cloud-agent).

## Шаг 5. Пользуйтесь субагентом

| Способ | Что сделать |
| --- | --- |
| Автоматически | Просто опишите задачу: агент сам передаст её подходящему субагенту. Он выбирает по описанию субагента |
| Явно | Наберите `/` и имя субагента: `/verifier проверь, что вход в систему работает`. Или напишите словами: «Используй субагента verifier, чтобы проверить вход в систему» |
| Параллельно | Попросите выполнить части работы одновременно: «Проверь изменения API и обнови документацию параллельно» |
| В отдельных копиях проекта | Если несколько субагентов меняют файлы одновременно, попросите запускать каждого в своём окружении — так они не затрут изменения друг друга |
| По цепочке | Для сложной работы поручите этапы разным субагентам: один составляет план, второй выполняет, третий проверяет |
| Продолжить работу | Каждый запуск субагента получает идентификатор. Попросите: «Продолжи работу агента abc123 и разбери оставшиеся ошибки» |

## Шаг 6. Проверьте и улучшайте

1. Откройте **Customize → Subagents** и убедитесь, что субагент есть в списке.
2. В новом чате вызовите субагента явно и дайте ему простую задачу.
3. Дайте задачу, не называя субагента: агент должен передать её сам.
4. Если агент не передаёт задачу или субагент ошибается, уточните описание
   и текст задания.
5. Сохраните папку `.cursor/agents` в git вместе с проектом — тогда субагента
   получит вся команда.

## Как написать хорошего субагента

- Один субагент — одна понятная задача. «Помощник на все случаи» не работает.
- Вложитесь в описание: по нему агент решает, когда передавать задачу.
  Вместо «для общих задач» напишите, для каких именно.
- Чтобы агент передавал задачу без напоминаний, добавьте в описание слова
  «используй проактивно» или «всегда используй для…».
- Пишите задание коротко и конкретно. Длинный текст не делает субагента
  умнее, а только замедляет его.
- Начните с двух-трёх субагентов. Добавляйте новых, когда появляется
  отдельная понятная задача.
- Не заводите субагента для простого действия: для него достаточно навыка.

## Если субагент не срабатывает

Проверьте по списку:

- **Субагента нет в списке.** Файл лежит в папке `.cursor/agents` проекта или
  в `~/.cursor/agents`, имеет расширение `.md` и начинается со строки `---`,
  а под настройками есть текст задания.
- **Агент не передаёт задачу сам.** В описании названы задачи, для которых
  нужен субагент. Проверьте самого субагента, вызвав его явно.
- **Субагент ведёт себя не по настройкам.** Каждая настройка записана в одну
  строку, без кавычек и без пояснений после значения.
- **Работает не тот субагент.** Имена субагентов не совпадают: при совпадении
  главнее Project subagent.
- **Используется другая модель.** Указанная модель не заблокирована
  администратором команды и доступна на вашем тарифе: иначе Cursor заменяет
  её на другую.
- **Cloud subagent не запускается.** У облачных агентов Cursor есть доступ
  к репозиторию, и они входят в ваш тариф.

Промпт — готовый текст запроса для агента. По нему агент задаёт уточняющие
вопросы, готовит субагента и ждёт вашего подтверждения.

создавать и настраивать.
