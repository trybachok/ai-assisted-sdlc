# Team MCP server: [название сервера]

## Настройки в дашборде

| Настройка | Значение | Пояснение |
| --- | --- | --- |
| Имя сервера | [короткое имя из латинских букв, например `issue-tracker`] | Под этим именем сервер видят участники команды и агенты |
| Способ подключения | [Streamable HTTP / stdio] | Облачные агенты поддерживают собственные серверы с подключением по Streamable HTTP или stdio; SSE и `mcp-remote` не поддерживаются. Рекомендуется Streamable HTTP: настройки и ключи доступа сервера не попадают в среду, где работает агент |
| Вход в сервис | [OAuth / ключ доступа / не нужен] | При входе через OAuth каждый участник входит в сервис сам, даже если сервер общий. Ключ доступа вводит администратор |
| **Add to Team Marketplace** | [выбрать / не выбирать] | Не выбирать — сервер доступен только облачным агентам. Выбрать — сервер появляется в маркетплейсе команды, и участники могут установить его в приложении Cursor и в Cursor CLI. Облачным агентам сервер доступен в обоих случаях |
| **Marketplace Access** | [вся команда / группы: названия групп] | Кто видит маркетплейс команды. По умолчанию — все участники |
| Режим установки | [**Default Off** / **Default On** / **Required**] | **Default Off** — участник сам решает, устанавливать ли сервер. **Default On** — сервер установлен сразу, но его можно отключить. **Required** — сервер установлен всегда, удалить его нельзя |

## Конфигурация сервера

Оставьте один из двух вариантов. Конфигурация записана в формате файла
`mcp.json`. Если в дашборде вместо текста отдельные поля, перенесите в них
значения с теми же названиями.

### Вариант 1. Удалённый сервер (Streamable HTTP)

```json
{
  "mcpServers": {
    "[имя сервера]": {
      "url": "[адрес сервера из его официальной документации]",
      "headers": {
        "Authorization": "Bearer [ключ вводит администратор в дашборде]"
      }
    }
  }
}
```

Если сервер использует вход через OAuth, настройка `headers` не нужна.

### Вариант 2. Локальная команда (stdio)

```json
{
  "mcpServers": {
    "[имя сервера]": {
      "type": "stdio",
      "command": "[команда запуска из официальной документации сервера]",
      "args": [
        "[аргумент команды]"
      ],
      "env": {
        "[ИМЯ_ПЕРЕМЕННОЙ]": "[значение вводит администратор в дашборде]"
      }
    }
  }
}
```

У облачного агента такой сервер запускается в его облачной среде, поэтому
программы, которые нужны серверу, должны быть в ней установлены. Агент
получает доступ к настройкам и переменным окружения сервера.
