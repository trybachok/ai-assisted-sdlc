# Шаблоны MCP для Cursor

Заготовки для подключения MCP-серверов всех типов по официальной документации:
[Model Context Protocol (MCP)](https://cursor.com/docs/mcp).

MCP (Model Context Protocol) — способ подключить Cursor к внешним сервисам
и данным: трекеру задач, базе данных, макетам, документации. Связь
обеспечивает MCP-сервер — программа-посредник между Cursor и сервисом. Агент
получает от сервера инструменты и вызывает их во время работы. Как выбрать тип
подключения и как им пользоваться, простыми словами описано в
[`docs/cursor-mcp.md`](../../docs/cursor-mcp.md).

## Структура

```text
templates/mcp/
├── stdio-server.json            # stdio server: локальный сервер-программа
├── sse-server.json              # SSE server: удалённый сервер, адрес SSE
├── streamable-http-server.json  # Streamable HTTP server: удалённый сервер
├── static-oauth-server.json     # удалённый сервер со Static OAuth
├── project-mcp.json             # Project Configuration: серверы проекта
├── global-mcp.json              # Global Configuration: личные серверы
├── team-mcp.md                  # Team MCP server: форма для дашборда команды
├── *.annotated.jsonc            # копии файлов .json с пояснениями
└── README.md                    # этот файл (в проект не копируется)
```

У каждого файла `.json` есть копия `*.annotated.jsonc`: те же настройки
и пояснение к каждой строке. В формате JSON комментариев нет, поэтому рабочие
файлы оставлены чистыми. В проект копируют только файл `.json`: копию
с пояснениями Cursor не читает.

## Какой шаблон выбрать

Тип подключения — это ответ на два вопроса: как Cursor связывается с сервером
и где хранится конфигурация. Варианты ответов взяты из документации; для
каждого есть шаблон и промпт.

### Как подключается сервер

| Тип | Шаблон | Чем отличается | Куда поместить | Промпт |
| --- | --- | --- | --- | --- |
| stdio server | [`stdio-server.json`](stdio-server.json), [пояснения](stdio-server.annotated.jsonc) | Локальный сервер: программа, которую Cursor сам запускает на вашем компьютере. Пользуется сервером один человек. Записывается командой запуска | Запись в `mcp.json` | [создать](../../prompts/create-mcp-stdio.md) |
| SSE server | [`sse-server.json`](sse-server.json), [пояснения](sse-server.annotated.jsonc) | Удалённый сервер: развёрнут отдельно, им могут пользоваться несколько человек. Записывается адресом для SSE. Облачные агенты собственные серверы с SSE не поддерживают | Запись в `mcp.json` | [создать](../../prompts/create-mcp-sse.md) |

Способы подключения в документации:

| Способ | Где работает сервер | Кто разворачивает | Пользователи | Что указывают | Вход в сервис |
| --- | --- | --- | --- | --- | --- |
| `stdio` | На вашем компьютере | Cursor запускает сервер сам | Один | Команду запуска | Вручную: ключи доступа |
| `SSE` | На компьютере или удалённо | Сервер развёрнут отдельно | Несколько | Адрес для SSE | OAuth |
| `Streamable HTTP` | На компьютере или удалённо | Сервер развёрнут отдельно | Несколько | Адрес для HTTP | OAuth |

### Где хранится конфигурация

| Тип | Шаблон | Чем отличается | Куда поместить | Промпт |
| --- | --- | --- | --- | --- |
| Project Configuration | [`project-mcp.json`](project-mcp.json), [пояснения](project-mcp.annotated.jsonc) | Серверы одного проекта: файл хранится в git, и серверы получают все, кто открыл проект | `.cursor/mcp.json` в корне проекта | [создать](../../prompts/create-mcp-project.md) |
| Global Configuration | [`global-mcp.json`](global-mcp.json), [пояснения](global-mcp.annotated.jsonc) | Личные серверы: доступны во всех ваших проектах на этом компьютере | `~/.cursor/mcp.json` | [создать](../../prompts/create-mcp-global.md) |
| Team MCP server | [`team-mcp.md`](team-mcp.md) | Сервер для всей команды: администратор добавляет его в дашборде. Доступен облачным агентам, а через маркетплейс команды — и в приложении Cursor | Не файл проекта: [дашборд Cursor](https://cursor.com/dashboard/plugins), раздел **Plugins & MCPs** | [создать](../../prompts/create-mcp-team.md) |

Cursor объединяет серверы из `.cursor/mcp.json` проекта и из
`~/.cursor/mcp.json`. Если имя сервера совпадает, действует запись проекта.

Настоящее подключение отвечает на оба вопроса сразу. Например: удалённый
сервер (Streamable HTTP server) записан в файле проекта (Project
Configuration). Начните с шаблона, который отвечает на самый важный для вас
вопрос, а остальное допишите по другим шаблонам. Если сомневаетесь, возьмите
`project-mcp.json`.

- Готовый сервер из [Cursor Marketplace](https://cursor.com/marketplace)
  устанавливают без файла: **Customize → MCPs → Add to Cursor**.
- MCP-серверы внутри плагина — отдельный случай. Их шаблон —
  [`templates/plugin/mcp.json`](../plugin/mcp.annotated.jsonc).
- Шаблоны описывают подключение готовых серверов. Как написать собственный
  сервер, описано на сайте протокола:
  [Model Context Protocol](https://modelcontextprotocol.io/introduction).
  Регистрация серверов из расширений через
  [Extension API](https://cursor.com/docs/mcp#using-the-extension-api) —
  задача разработчиков расширений, шаблона для неё нет.

## Настройки mcp.json

Файл `mcp.json` состоит из списка «имя сервера → настройки сервера»:

```json
{
  "mcpServers": {
    "remote-server": {
      "url": "https://mcp.example.com/mcp"
    }
  }
}
```

| Настройка | Обязательна | Назначение |
| --- | --- | --- |
| `mcpServers` | да | Список серверов. Имя сервера — любое: под ним сервер виден в Cursor |

Настройки локального сервера (stdio server):

| Настройка | Обязательна | Назначение |
| --- | --- | --- |
| `type` | да — по таблице документации | Тип подключения: `"stdio"`. В примерах документации настройка опущена: Cursor 3.30 узнаёт локальный сервер по настройке `command` |
| `command` | да | Команда запуска сервера: программа, доступная в системном пути (PATH), или полный путь к ней. Примеры: `"npx"`, `"node"`, `"python"`, `"docker"` |
| `args` | нет | Аргументы команды — список строк |
| `env` | нет | Переменные окружения для сервера: настройки и ключи доступа |
| `envFile` | нет | Путь к файлу с дополнительными переменными окружения, например `"${workspaceFolder}/.env"`. Только для локальных серверов |

Настройки удалённого сервера (SSE server, Streamable HTTP server):

| Настройка | Обязательна | Назначение |
| --- | --- | --- |
| `url` | да | Адрес сервера |
| `headers` | нет | Заголовки, которые Cursor отправляет серверу, например с ключом доступа |
| `auth` | нет | Данные приложения OAuth для Static OAuth |
| `auth.CLIENT_ID` | да, если есть `auth` | Client ID, который выдал владелец сервера |
| `auth.CLIENT_SECRET` | нет | Client Secret, если владелец сервера его выдаёт |
| `auth.scopes` | нет | Права доступа, которые Cursor запросит у сервера, — список строк. Без настройки Cursor узнаёт список у сервера |

### Подстановки в значениях

Вместо значения можно записать подстановку: Cursor заменит её при запуске
сервера. Подстановки работают в настройках `command`, `args`, `env`, `url`,
`headers` и `auth`.

| Подстановка | Что подставит Cursor |
| --- | --- |
| `${env:ИМЯ}` | Значение переменной окружения системы с этим именем |
| `${userHome}` | Путь к домашней папке пользователя |
| `${workspaceFolder}` | Корень проекта — папку, в которой лежит `.cursor/mcp.json` |
| `${workspaceFolderBasename}` | Имя папки проекта |
| `${pathSeparator}` и `${/}` | Разделитель частей пути, принятый в операционной системе |

Переменная окружения — именованное значение, которое хранится в настройках
системы, а не в файле проекта. Так ключ доступа остаётся на вашем компьютере
и не попадает в git. На macOS и Linux переменную задают строкой
`export MY_SERVICE_TOKEN="значение"` в файле профиля оболочки, например
`~/.zshrc`. После этого Cursor перезапускают.

### Что сервер может дать Cursor

| Возможность | Что это |
| --- | --- |
| Tools | Инструменты — действия, которые может выполнить AI-модель |
| Prompts | Заготовки сообщений и сценариев для пользователя |
| Resources | Структурированные данные, которые можно читать и на которые можно ссылаться |
| Roots | Запросы сервера о границах доступных ему папок и адресов |
| Elicitation | Запросы сервера на дополнительные сведения от пользователя |
| Apps | Интерактивные элементы интерфейса, которые возвращают инструменты сервера |

## Как записывать mcp.json

Соблюдайте простые правила — иначе серверы не загрузятся:

- файл — обычный JSON без комментариев; пояснения держите в копии
  `*.annotated.jsonc`;
- в файле есть список `mcpServers`;
- у каждого сервера есть `command` (локальный сервер) или `url` (удалённый
  сервер), но не обе настройки сразу;
- строку `"type": "stdio"` пишут только у локального сервера;
- `args` и `scopes` — списки строк, значения `env` и `headers` — строки. Числа
  тоже пишут в кавычках: `"3000"`, а не `3000`;
- ключи доступа и пароли в файл не записывают: вместо значения пишут
  подстановку `${env:ИМЯ}`;
- имя переменной окружения состоит из латинских букв, цифр и знака
  подчёркивания: `MY_SERVICE_TOKEN`;
- настройка `envFile` есть только у локальных серверов;
- имя пакета, команду запуска и адрес сервера берут из официальной
  документации сервера, а не придумывают.

В Cursor 3.30 ошибка в записи одного сервера — например, число без кавычек
в `env` — может отключить все серверы файла.

## Как пользоваться шаблоном

### Project Configuration

1. Скопируйте шаблон в свой проект, например из корня этого репозитория:

   ```bash
   mkdir -p ~/my-project/.cursor
   cp -n templates/mcp/project-mcp.json ~/my-project/.cursor/mcp.json
   ```

   Ключ `-n` не даёт заменить файл, который уже есть. Если в проекте уже есть
   `.cursor/mcp.json`, перенесите в него нужные серверы вручную.
2. Оставьте в `.cursor/mcp.json` нужные серверы и замените имена, команды
   и адреса своими: пояснения — в
   [`project-mcp.annotated.jsonc`](project-mcp.annotated.jsonc).
3. Задайте переменные окружения с ключами доступа на своём компьютере.
4. Сохраните файл и перезапустите Cursor.
5. Сохраните `.cursor/mcp.json` в git. Убедитесь, что в файле нет ключей
   доступа и паролей.

### Global Configuration

1. Скопируйте шаблон в папку `.cursor` в домашней папке пользователя:

   ```bash
   mkdir -p ~/.cursor
   cp -n templates/mcp/global-mcp.json ~/.cursor/mcp.json
   ```

   Если файл `~/.cursor/mcp.json` уже есть, перенесите в него нужные серверы
   вручную.
2. Оставьте нужные серверы и замените имена, команды и адреса своими.
3. Сохраните файл и перезапустите Cursor.
4. Не подключайте здесь серверы, которые нужны только одному проекту.

### Team MCP server

Это не файл проекта: сервер добавляет администратор команды в дашборде.

1. Заполните [`team-mcp.md`](team-mcp.md): имя сервера, способ подключения
   и конфигурацию. Ключи доступа в файл не записывайте.
2. Передайте заполненный файл администратору команды.
3. Администратор добавляет сервер в
   [дашборде Cursor](https://cursor.com/dashboard/plugins), в разделе
   **Plugins & MCPs**, и вводит ключи доступа. Сервер становится доступен
   облачным агентам команды.
4. Чтобы участники могли установить сервер в приложении Cursor, администратор
   выбирает **Add to Team Marketplace** в блоке **Team MCP Servers**. Сервер
   не устанавливается всем автоматически: это зависит от доступа
   к маркетплейсу и режима установки.

### stdio server, SSE server, Streamable HTTP server и Static OAuth

Эти шаблоны показывают, как записать один сервер. Перенесите запись сервера
в свой `mcp.json` — в `.cursor/mcp.json` проекта или в `~/.cursor/mcp.json`:

- **stdio server** — запись с настройкой `command`. Замените текст
  в квадратных скобках именем пакета из официальной документации сервера.
  Программа из `command` должна быть установлена на компьютере.
- **SSE server** и **Streamable HTTP server** — запись с настройкой `url`.
  Оба способа записывают одинаково, различается только адрес: его сообщает
  владелец сервера. Если сервер предлагает оба адреса, выбирайте Streamable
  HTTP.
- **Remote server with Static OAuth** — запись с настройками `url` и `auth`.
  Сначала получите у владельца сервера Client ID и внесите в настройки его
  приложения адреса возврата Cursor: они перечислены
  в [`static-oauth-server.annotated.jsonc`](static-oauth-server.annotated.jsonc).

Если в файле уже есть серверы, добавьте новую запись внутрь `mcpServers` через
запятую, а не заменяйте файл целиком.

## Проверка

1. Убедитесь, что файл — корректный JSON. Откройте его в Cursor: редактор
   подчёркивает ошибки записи. Если установлена программа `jq`, файл можно
   проверить командой — она напечатает файл или сообщит об ошибке:

   ```bash
   jq . .cursor/mcp.json
   ```

2. Перезапустите Cursor, откройте **Customize** в боковой панели и перейдите
   в раздел **MCPs**: сервер должен быть в списке.
3. Убедитесь, что сервер включён. Сервер из файла проекта Cursor 3.30
   не запускает, пока вы его не включите, — и после изменения его записи
   сервер, возможно, придётся включить снова.
4. Если сервер требует входа, войдите в сервис там же.
5. Попросите агента воспользоваться сервером: назовите инструмент или опишите,
   что нужно. По умолчанию Cursor спрашивает разрешение перед вызовом
   инструмента MCP: аргументы вызова видны, если нажать на стрелку рядом
   с именем инструмента.
6. Если сервер не подключился, откройте панель **Output**
   (`Cmd+Shift+U` на macOS, `Ctrl+Shift+U` на Windows и Linux) и выберите
   в списке **MCP Logs**: в журнале видны запуск сервера, вызовы инструментов
   и ошибки.
7. Если сервер не появился или не работает, проверьте:
   - файл называется `mcp.json` и лежит в папке `.cursor` проекта или
     в `~/.cursor`;
   - файл записан по правилам из раздела «Как записывать mcp.json»;
   - программа из `command` установлена, а адрес в `url` указан без ошибок;
   - переменные окружения с ключами заданы, и после этого Cursor был
     перезапущен;
   - сервер разрешён в организации: на тарифе Enterprise администратор может
     ограничить список серверов, которые разрешено запускать.

В Cursor CLI действует та же конфигурация. Команда `agent mcp list`
показывает серверы и их состояние, `agent mcp list-tools <имя сервера>` —
инструменты сервера, а `agent mcp login <имя сервера>` выполняет вход
в сервис.

## Безопасность

MCP-сервер обращается к внешним сервисам и выполняет действия от вашего имени.
Перед подключением:

- **Проверьте источник.** Подключайте серверы только от разработчиков
  и из репозиториев, которым доверяете.
- **Проверьте, к чему сервер получает доступ.** Какие данные и сервисы он
  читает и изменяет.
- **Ограничьте ключи доступа.** Выдавайте ключ с наименьшими правами, которых
  достаточно серверу.
- **Проверьте код.** Для важных подключений просмотрите исходный код сервера.
- **Не записывайте секреты в файл.** Используйте переменные окружения.
- **Не передавайте серверу лишнего.** Сервер получает все переменные из файла
  `envFile`: не указывайте файл с паролями, которые серверу не нужны.
- **Работайте с закрытыми данными локально.** Для них документация советует
  локальные серверы — stdio server.

## Как поделиться серверами

| Кому нужны серверы | Способ |
| --- | --- |
| Всем, кто работает с проектом | Project Configuration: сохраните `.cursor/mcp.json` в git |
| Всей команде и её облачным агентам | Team MCP server: администратор добавляет сервер в дашборде |
| Другим командам и проектам | Плагин: серверы упаковывают в плагин и публикуют через маркетплейс |

Серверы из Global Configuration остаются только на вашем компьютере. Для
облачных агентов серверы настраивают отдельно: личные — на странице
[cursor.com/agents](https://cursor.com/agents), общие — администратор команды
в дашборде.

Шаблон плагина — [`templates/plugin/`](../plugin/README.md), инструкция —
[`docs/cursor-plugin.md`](../../docs/cursor-plugin.md).
