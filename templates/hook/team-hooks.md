<!--
  ШАБЛОН TEAM HOOKS: хук для всей команды во всех её проектах.
  Документация: https://cursor.com/docs/hooks#cloud-distribution-enterprise-only

  Team hook хранится не в файле проекта: его создаёт администратор команды
  в дашборде Cursor (https://cursor.com/dashboard/team-content?section=hooks).
  Доступно только на тарифе Enterprise. Cursor сам доставляет хук
  на компьютеры участников команды и обновляет его каждые тридцать минут.

  Как пользоваться:
    1. Заполните таблицу настроек и содержимое хука: замените текст
       в квадратных скобках.
    2. Передайте заполненный файл администратору команды.
    3. Администратор создаёт хук в дашборде, выставляет настройки из таблицы
       и вставляет скрипт или условие из раздела «Содержимое хука».

  Один Team hook — это один скрипт или одно условие для одного события.
  Настроек matcher и failClosed у такого хука нет: если хук должен
  срабатывать не всегда, условие проверяет сам скрипт.

  Названия настроек в таблице описательные: в дашборде они могут называться
  иначе. Точное название взято из документации только у настройки
  Block until hooks are ready.

  Хук действует во всех проектах команды, поэтому не используйте в нём то,
  что верно только для одного проекта.
-->

# Team hook: [название хука]

## Настройки в дашборде

| Настройка | Значение | Пояснение |
| --- | --- | --- |
| Событие | [имя события, например `beforeShellExecution`] | Один хук — одно событие. Список событий — в [README.md](README.md), раздел «События» |
| Что выполняет хук | [скрипт / условие обычными словами] | Скрипт — Command-based hook. Условие, которое проверяет AI-модель, — Prompt-based hook. Облачные агенты выполняют только скрипты |
| Имя скрипта | [имя файла, например `block-git-push.sh`] | Только для скрипта. На Windows к имени без расширения `.ps1`, `.bat` или `.cmd` Cursor добавит `.ps1` |
| Операционная система | [все / macOS / Linux / Windows] | Скрипт на bash подходит для macOS и Linux. Для Windows создают отдельный хук со скриптом PowerShell |
| **Block until hooks are ready** | [включено / выключено] | Общая настройка хуков команды. Выключено — Cursor недолго ждёт загрузки хуков и может отправить первый запрос без них. Включено — Cursor ждёт, пока загрузятся все хуки, и они срабатывают на каждом запросе, включая первый после перезапуска |

## Содержимое хука

Оставьте один из двух вариантов.

### Вариант 1. Скрипт

```bash
#!/usr/bin/env bash
# [Что проверяет или делает хук — одной строкой.]
set -euo pipefail

# Сведения о событии приходят в формате JSON через стандартный ввод.
input="$(cat)"

# [Проверка. Настройки matcher у Team hook нет, поэтому условие проверяет
# сам скрипт. Пример для события beforeShellExecution: запретить команды,
# в которых есть «git push». Для разбора JSON нужна программа jq.]
#
# command="$(printf '%s' "$input" | jq -r '.command // empty')"
# if [[ "$command" == *"git push"* ]]; then
#   printf '%s\n' '{"permission": "deny", "user_message": "[причина запрета]"}'
#   exit 0
# fi

# Ответ — один JSON-объект и больше ничего. Здесь: разрешить действие.
# Какой ответ нужен другим событиям, описано в README.md.
printf '%s\n' '{"permission": "allow"}'
```

### Вариант 2. Условие обычными словами

```text
[Условие, которое проверит AI-модель. Например: «Проверь команду перед
запуском. Разрешай только команды, которые ничего не изменяют и не удаляют.
Данные о команде: $ARGUMENTS».]
```
