# Шаблон плагина Cursor

Папка-шаблон для создания плагина в формате **Cursor Plugin** по официальной
документации:

- [Plugins](https://cursor.com/docs/plugins) — обзор;
- [Plugins reference](https://cursor.com/docs/reference/plugins) — схема манифеста,
  форматы компонентов, чек-лист публикации.

Каждый файл содержит все параметры конфигурации, описанные в документации.
У каждого параметра есть комментарий: для чего он нужен и обязателен ли он
(`[ОБЯЗАТЕЛЬНЫЙ]` или `[необязательный]`).

> Этот README — заготовка. В настоящем плагине опишите здесь, что делает плагин,
> как им пользоваться и какие переменные нужно настроить: наличие такого README —
> пункт чек-листа публикации.

## Структура

```text
templates/plugin/
├── .cursor-plugin/
│   ├── plugin.json                          # ОБЯЗАТЕЛЬНЫЙ: манифест плагина
│   ├── plugin.annotated.jsonc               # комментарии к plugin.json
│   ├── marketplace.example.json             # пример манифеста маркетплейса
│   └── marketplace.example.annotated.jsonc  # комментарии к нему
├── rules/                                   # правила (.mdc)
│   └── coding-standards.mdc
├── skills/                                  # навыки (папка с SKILL.md на каждый)
│   └── code-reviewer/
│       └── SKILL.md
├── agents/                                  # агенты (субагенты)
│   └── security-reviewer.md
├── commands/                                # команды
│   └── deploy-staging.md
├── hooks/
│   ├── hooks.json                           # конфигурация хуков
│   └── hooks.annotated.jsonc                # комментарии к hooks.json
├── mcp.json                                 # MCP-серверы
├── mcp.annotated.jsonc                      # комментарии к mcp.json
├── assets/
│   └── logo.svg                             # логотип
├── scripts/                                 # скрипты хуков
│   ├── permission-hook.sh
│   ├── observe-hook.sh
│   └── before-submit-prompt-hook.sh
└── README.md
```

Обязателен только `.cursor-plugin/plugin.json`, а в нём — только поле `name`.
Всё остальное необязательно: оставьте нужные компоненты, лишние папки удалите.

## Где искать комментарии

| Тип файла | Где комментарии |
| --- | --- |
| `*.json` | В соседнем файле `*.annotated.jsonc` с тем же содержимым |
| `*.md`, `*.mdc` | В самом файле, в YAML-frontmatter (строки с `#`) |
| `*.sh` | В самом файле |
| `*.svg` | В самом файле |

**Почему у JSON-файлов отдельные копии.** Формат JSON не допускает комментариев,
а Cursor читает `plugin.json`, `hooks.json` и `marketplace.json` как строгий JSON:
файл с комментариями считается невалидным, и плагин не загрузится. Поэтому
рабочие файлы оставлены чистыми, а пояснения вынесены в копии `*.annotated.jsonc`.
Cursor эти копии не читает. Меняя рабочий JSON, обновите копию или удалите её;
перед публикацией копии можно удалить.

## Как пользоваться шаблоном

1. Скопируйте папку и переименуйте её в имя плагина (например, `my-plugin`).
2. В `.cursor-plugin/plugin.json` задайте `name` и остальные поля. Поля путей
   (`rules`, `agents`, `skills`, `commands`, `hooks`, `mcpServers`) нужны только
   при нестандартной структуре: при стандартной их можно удалить.
3. Замените примеры компонентов своими. Ненужные папки удалите.
4. В `hooks/hooks.json` оставьте только нужные события. В шаблоне подключены все
   21, чтобы показать полный список; каждый хук — отдельный процесс на каждое
   срабатывание события.
5. В `mcp.json` замените примеры серверов. Каждый плейсхолдер `${ИМЯ}` объявите
   в поле `variables` манифеста. Секреты в репозиторий не кладите.
6. Сделайте скрипты исполняемыми: `chmod +x scripts/*.sh`.
7. Перепишите этот README.

## Компоненты

| Компонент | Расположение по умолчанию | Что обнаруживается | Поля frontmatter |
| --- | --- | --- | --- |
| Правила | `rules/` | файлы `.md`, `.mdc`, `.markdown` | `description`, `alwaysApply`, `globs` |
| Навыки | `skills/` | подпапки с файлом `SKILL.md` | `name`, `description`, `paths`, `disable-model-invocation`, `icon`, `color`, `metadata` |
| Агенты | `agents/` | файлы `.md`, `.mdc`, `.markdown` | `name`, `description`, `model`, `readonly`, `is_background` |
| Команды | `commands/` | файлы `.md`, `.mdc`, `.markdown`, `.txt` | `name`, `description` |
| Хуки | `hooks/hooks.json` | имена событий | — |
| MCP-серверы | `mcp.json` | записи серверов | — |

Если в манифесте указан путь для компонента, он заменяет поиск по умолчанию:
стандартная папка дополнительно не сканируется.

## Локальная проверка

1. Скопируйте папку плагина в `~/.cursor/plugins/local/my-plugin`.
2. Перезапустите Cursor или выполните команду **Developer: Reload Window**.
3. Откройте **Customize** и убедитесь, что правила, навыки, агенты, команды,
   хуки и MCP-серверы плагина появились.

Символические ссылки в `~/.cursor/plugins/local` работают, только если указывают
на папку внутри этой же директории. На тарифе Enterprise локальный импорт
плагинов по умолчанию выключен: его включает администратор.

## Несколько плагинов в одном репозитории

Один плагин манифеста маркетплейса не требует. Если в репозитории несколько
плагинов, в его корень кладут `.cursor-plugin/marketplace.json` со списком
плагинов. Пример со всеми полями — в `.cursor-plugin/marketplace.example.json`,
пояснения — в `.cursor-plugin/marketplace.example.annotated.jsonc`.

## Чек-лист перед публикацией

Публикация: [cursor.com/marketplace/publish](https://cursor.com/marketplace/publish),
плагин должен лежать в публичном Git-репозитории.

- [ ] Есть валидный манифест `.cursor-plugin/plugin.json`.
- [ ] `name` уникален, в нижнем регистре, kebab-case.
- [ ] `description` ясно объясняет назначение плагина.
- [ ] У всех компонентов валидные файлы и frontmatter.
- [ ] Логотип закоммичен и указан относительным путём (если он есть).
- [ ] `README.md` описывает использование и настройку.
- [ ] Каждая переменная `${ИМЯ}` из `mcp.json` объявлена в `variables` манифеста.
- [ ] Все пути в манифесте относительные, без `..` и без абсолютных путей.
- [ ] Плагин проверен локально.
- [ ] В репозитории с несколькими плагинами есть `.cursor-plugin/marketplace.json`
      с уникальными именами плагинов.
