<!--
  ШАБЛОН TEAM RULE: правило для всей команды во всех её проектах.
  Документация: https://cursor.com/docs/rules#team-rules

  Team Rule хранится не в файле проекта: его создаёт администратор команды
  в дашборде Cursor (https://cursor.com/dashboard/team-content). Доступно
  на тарифах Team и Enterprise. Текст правила пишется в свободной форме,
  без блока настроек.

  Как пользоваться:
    1. Заполните таблицу настроек и текст правила: замените текст
       в квадратных скобках.
    2. Передайте заполненный файл администратору команды.
    3. Администратор создаёт правило в дашборде, выставляет настройки
       из таблицы и вставляет только текст из раздела «Текст правила».

  Правило действует во всех проектах команды, поэтому не пишите в нём то,
  что верно только для одного проекта. Правило не заменяет другие меры
  контроля безопасности.
-->

# Team Rule: [название правила]

## Настройки в дашборде

| Настройка | Значение | Пояснение |
| --- | --- | --- |
| Название правила | [короткое название] | Под ним правило видно в списке Team Rules |
| Glob-шаблон файлов | [пусто или шаблон, например `**/*.py`] | Необязательная настройка. Пусто — правило действует в каждом чате. С шаблоном — только когда агент работает с подходящими файлами |
| **Enable this rule immediately** | [включено / выключено] | Включено — правило действует сразу после создания. Выключено — сохраняется как черновик, пока его не включат |
| **Enforce this rule** | [включено / выключено] | Включено — правило обязательно, участники не могут его отключить. Выключено — участник может отключить правило в Customize, раздел Team Rules |

## Текст правила

- [Требование, единое для всех проектов команды. Например: «Не добавляй
  в код, логи и сообщения коммитов пароли, токены и ключи доступа».]
- [Что делать в спорной ситуации. Например: «Если для задачи нужен секрет,
  попроси пользователя задать его через переменную окружения».]
- [Запрет. Например: «Не отключай проверки безопасности, чтобы тесты
  прошли».]
