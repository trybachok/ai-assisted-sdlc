# =============================================================================
# ШАБЛОН BACKGROUND SUBAGENT: субагент работает в фоне. Основной агент не ждёт
# его и продолжает работу. Режим включает настройка is_background
# со значением true.
# Документация: https://cursor.com/docs/subagents#foreground-vs-background
#
# Как пользоваться:
#   1. Скопируйте файл в папку .cursor/agents своего проекта (субагент для
#      проекта) или в ~/.cursor/agents (личный субагент для всех проектов)
#      и переименуйте: имя файла — это имя субагента, например
#      test-runner.md.
#   2. Впишите свои name и description. Строку is_background не изменяйте.
#   3. Под блоком настроек замените текст в квадратных скобках своим заданием.
#      Субагент не видит переписку основного агента: всё, что ему нужно
#      знать, напишите в задании или укажите, какие файлы прочитать.
#   4. Строки с пояснениями (они начинаются с #) можно удалить.
#
# Подходит для долгих задач и параллельной работы. Субагент работает в той же
# копии проекта, что и основной агент, и может затереть его изменения.
# Поэтому поручайте ему проверки и отчёты. Если он должен менять файлы,
# попросите агента запускать субагентов в отдельных копиях проекта.
#
# Как записывать настройки: каждая — в одну строку и без кавычек. Не
# дописывайте пояснение после значения: Cursor прочитает настройку неверно,
# и режим Background не включится.
# =============================================================================

# [указывайте всегда] Имя субагента: строчные латинские буквы и дефисы. По нему
# субагента вызывают в чате, например /test-runner. Должно совпадать с именем
# файла; без этой настройки Cursor возьмёт имя из имени файла.
name: background-subagent

# [указывайте всегда] Что делает субагент и когда основной агент должен
# передавать ему задачу: по описанию агент решает, поручать ли работу. Пишите
# конкретно, в одну строку, без двоеточий и символа #. Слова «используй
# проактивно» подталкивают агента передавать задачу без напоминаний.
description: Какую долгую работу выполняет субагент и в каких задачах основной агент должен передавать ему работу

# [необязательный] Модель. inherit — та же, что у основного агента (значение
# по умолчанию). Вместо inherit можно указать ID модели из справочника:
# https://cursor.com/docs/models-and-pricing
model: inherit

# [необязательный] true — только чтение: субагент не изменяет файлы
# и не выполняет команды, меняющие состояние. По умолчанию false.
readonly: false

# [ОБЯЗАТЕЛЬНЫЙ для этого типа] true — режим Background: субагент работает
# в фоне и не задерживает основного агента. Строка должна выглядеть
# в точности так. Со значением false основной агент ждёт результат (режим
# Foreground).
is_background: true
---

Ты — [роль субагента. Например: «специалист по тестированию: запускаешь
полный набор тестов и разбираешь сбои»].

При вызове:

1. [Что запустить. Например: «Запусти все тесты проекта: команды описаны
   в `README.md`».]
2. [Как разобрать результат. Например: «Для каждого упавшего теста изучи
   вывод и найди причину сбоя».]
3. [Чем закончить. Например: «Составь список сбоев с причинами
   и предложениями по исправлению».]

Ты работаешь в фоне, пока основной агент занят другой задачей:

- [Ограничение. Например: «Не изменяй файлы проекта: с ними одновременно
  работает основной агент».]
- [Самостоятельность. Например: «Если данных не хватает, не останавливайся:
  сделай возможное и опиши в отчёте, чего не хватило».]

В итоговом отчёте сообщи:

- [Первый пункт отчёта. Например: «Сколько тестов прошло и сколько упало».]
- [Второй пункт отчёта. Например: «Причину каждого сбоя».]
- [Третий пункт отчёта. Например: «Что рекомендуется исправить».]
