# Шаблоны субагентов Cursor

Заготовки для субагентов (subagents) всех типов по официальной документации:
[Subagents](https://cursor.com/docs/subagents).

Субагент — отдельный AI-помощник, которому основной агент передаёт часть
работы. Как выбрать тип субагента и как им пользоваться, простыми словами
описано в [`docs/cursor-subagents.md`](../../docs/cursor-subagents.md).

## Структура

```text
templates/subagent/
├── project-subagent.md     # Project subagent: субагент одного проекта
├── user-subagent.md        # User subagent: личный субагент для всех проектов
├── readonly-subagent.md    # Read-only subagent: только чтение
├── background-subagent.md  # Background subagent: работа в фоне
├── cloud-subagent.md       # Cloud subagent: задача для запуска в облаке
└── README.md               # этот файл (в проект не копируется)
```

## Какой шаблон выбрать

| Тип субагента | Шаблон | Чем отличается | Куда поместить | Промпт |
| --- | --- | --- | --- | --- |
| Project subagent | [`project-subagent.md`](project-subagent.md) | Работает в одном проекте и доступен всем, кто работает с репозиторием | `.cursor/agents/` проекта | [создать](../../prompts/create-subagent-project.md) |
| User subagent | [`user-subagent.md`](user-subagent.md) | Личный: работает во всех ваших проектах | `~/.cursor/agents/` | [создать](../../prompts/create-subagent-user.md) |
| Read-only subagent | [`readonly-subagent.md`](readonly-subagent.md) | Только изучает и сообщает: не изменяет файлы | `.cursor/agents/` или `~/.cursor/agents/` | [создать](../../prompts/create-subagent-readonly.md) |
| Background subagent | [`background-subagent.md`](background-subagent.md) | Работает в фоне: основной агент его не ждёт | `.cursor/agents/` или `~/.cursor/agents/` | [создать](../../prompts/create-subagent-background.md) |
| Cloud subagent | [`cloud-subagent.md`](cloud-subagent.md) | Работает в облаке, на отдельной виртуальной машине и в отдельной ветке | Не файл: текст задачи отправляют в чат после команды `/in-cloud` | [создать](../../prompts/create-subagent-cloud.md) |

Типы взяты из документации. Субагенты бывают встроенными, своими и облачными.
Свой субагент хранится в проекте (Project) или у пользователя (User), работает
в режиме Foreground или Background, с обычными правами или только на чтение.

- **Foreground** — режим по умолчанию: основной агент ждёт результат. В нём
  работают шаблоны Project, User и Read-only subagent.
- **Встроенные субагенты** Explore (поиск по коду) и Browser (работа
  с браузером) создавать и настраивать не нужно: агент использует их сам.
  Шаблона для них нет.
- Если у двух субагентов одинаковое имя, главнее Project subagent.
- По документации Cursor читает субагентов также из папок `.claude/agents/`
  и `.codex/agents/` — для совместимости с другими инструментами. Новых
  субагентов создавайте в `.cursor/agents/`: при совпадении имён главнее она.

## Настройки субагента

Свой субагент — файл Markdown (`.md`). Он начинается с блока настроек
(frontmatter) между двумя строками `---`, ниже идёт задание для субагента
обычным текстом. Субагент начинает работу с чистым контекстом и не видит
переписку основного агента, поэтому задание должно быть понятно само по себе.

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `name` | имя файла | Имя субагента: строчные латинские буквы и дефисы. По нему субагента вызывают в чате: `/имя` |
| `description` | — | Что делает субагент и когда ему передавать задачу. По описанию основной агент решает, поручать ли работу |
| `model` | `inherit` | `inherit` — та же модель, что у основного агента. Вместо него можно указать ID конкретной модели |
| `readonly` | `false` | `true` — только чтение: субагент не изменяет файлы и не выполняет команды, меняющие состояние |
| `is_background` | `false` | `false` — режим Foreground: основной агент ждёт результат. `true` — режим Background: субагент работает в фоне |

По документации все поля необязательные, но `name` и `description` указывайте
всегда: имя должно совпадать с именем файла, а без описания агент не поймёт,
когда передавать задачу.

Шаблоны отличаются значениями двух полей и папкой:

| Шаблон | `readonly` | `is_background` | Папка |
| --- | --- | --- | --- |
| `project-subagent.md` | `false` | `false` | `.cursor/agents/` |
| `user-subagent.md` | `false` | `false` | `~/.cursor/agents/` |
| `readonly-subagent.md` | **`true`** | `false` | любая из двух |
| `background-subagent.md` | `false` | **`true`** | любая из двух |

Настройки можно сочетать. Например, личный субагент только для чтения — это
`user-subagent.md` со строкой `readonly: true`.

### Как записывать настройки

Cursor читает блок настроек построчно и понимает не все возможности YAML.
Соблюдайте простые правила — иначе субагент получит не те настройки или
пропадёт из списка в Customize:

- файл начинается со строки `---`, а под блоком настроек есть текст задания;
- каждая настройка — в одну строку, её имя — строчными буквами;
- значения — без кавычек;
- `description` — обычный текст: начинается с буквы, без двоеточий
  и символа `#`;
- `readonly` и `is_background` — только `true` или `false`;
- пояснение — только отдельной строкой, которая начинается с `#`. Не
  дописывайте его после значения: строка `readonly: true # только чтение`
  ограничение не включит.

### Модель

Значение `inherit` подходит большинству субагентов. ID конкретной модели
берут из [справочника моделей](https://cursor.com/docs/models-and-pricing);
после ID в квадратных скобках можно указать её параметры, например
`claude-opus-5[effort=high]`. Cursor заменит модель на совместимую, если
указанная заблокирована администратором команды или недоступна на вашем
тарифе. Запросы субагента оплачиваются по цене той модели, которая их
выполнила. Подробнее — в разделе
[Model configuration](https://cursor.com/docs/subagents#model-configuration).

## Как пользоваться шаблоном

### Project subagent

1. Скопируйте шаблон в папку `.cursor/agents/` своего проекта под именем
   субагента, например из корня этого репозитория:

   ```bash
   mkdir -p ~/my-project/.cursor/agents
   cp templates/subagent/project-subagent.md ~/my-project/.cursor/agents/verifier.md
   ```

2. Впишите в блок настроек свои `name` и `description`. Значение `name`
   должно совпадать с именем файла: в примере это `verifier`.
3. Замените текст в квадратных скобках своим заданием.
4. Сохраните файл в git вместе с проектом.

### User subagent

1. Скопируйте шаблон в папку `.cursor/agents` в домашней папке пользователя:

   ```bash
   mkdir -p ~/.cursor/agents
   cp templates/subagent/user-subagent.md ~/.cursor/agents/debugger.md
   ```

2. Впишите свои `name` и `description`, замените текст в квадратных скобках.
3. Не пишите в задании то, что верно только для одного проекта.

### Read-only subagent и Background subagent

Скопируйте шаблон в `.cursor/agents/` проекта или в `~/.cursor/agents/` — так
же, как Project или User subagent. Строки `readonly: true`
и `is_background: true` не изменяйте: они задают тип субагента.

### Cloud subagent

Это не файл проекта: текст из шаблона отправляют в чат.

1. Заполните [`cloud-subagent.md`](cloud-subagent.md) и скопируйте текст под
   комментарием.
2. В приложении Cursor откройте Agents Window, наберите `/in-cloud`
   и отправьте текст задачи.

## Проверка

1. Откройте **Customize** в боковой панели и перейдите в раздел
   **Subagents**: субагент должен быть в списке.
2. В новом чате вызовите субагента явно: наберите `/` и его имя, например
   `/verifier проверь, что вход в систему работает`.
3. Дайте задачу, не называя субагента: основной агент должен передать её сам.
4. Если субагент не появился или не вызывается, проверьте:
   - файл лежит в `.cursor/agents/` проекта или в `~/.cursor/agents/` и имеет
     расширение `.md`;
   - настройки записаны по правилам из раздела «Как записывать настройки»;
   - `description` называет задачи, для которых нужен субагент;
   - нет другого субагента с таким же именем.

## Как поделиться субагентами

Project subagent достаточно сохранить в git вместе с проектом: его получит
каждый, кто работает с репозиторием. User subagent остаётся только на вашем
компьютере.

В другие проекты субагентов переносят плагином: их упаковывают в плагин
и публикуют через маркетплейс. Шаблон плагина —
[`templates/plugin/`](../plugin/README.md), инструкция —
[`docs/cursor-plugin.md`](../../docs/cursor-plugin.md).

У субагента внутри плагина свой шаблон —
[`agents/security-reviewer.md`](../plugin/agents/security-reviewer.md). В папку
`.cursor/agents/` его не копируйте: описание в нём занимает несколько строк,
и Cursor прочитает его неверно.
