# Промпт для создания Cursor Hook: Command-based hooks

**Command-based hooks** — хуки, которые запускают скрипт. Это способ выполнения по умолчанию: Cursor передаёт скрипту сведения о событии, а скрипт отвечает, что делать дальше — разрешить действие, запретить его или ничего не менять. Хороший промпт на создание такого хука называет событие, точное условие, ответ скрипта и поведение при сбое.

Тип подходит, если условие можно проверить программой, а ответ должен быть одинаковым каждый раз. Такой хук работает везде: в приложении Cursor, в облачных агентах и в плагинах. В остальных случаях выберите другой тип:

- условие проще описать словами, чем запрограммировать, — [Prompt-based hooks](create-hook-prompt-based.md);
- нужно не автоматическое действие, а указание для агента — вместо хука создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Где хранится хук: [Project hooks](create-hook-project.md), [User hooks](create-hook-user.md), [Team hooks](create-hook-team.md), [Enterprise hooks](create-hook-enterprise.md). Событие: [Agent hooks](create-hook-agent.md), [Tab hooks](create-hook-tab.md), [App lifecycle hooks](create-hook-app-lifecycle.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks#command-based-hooks). Шаблон — [`templates/hook/command-based-hooks.json`](../templates/hook/command-based-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- В записи хука обязательна настройка `command`: путь к скрипту или команда оболочки. Настройку `"type": "command"` можно не писать: это значение по умолчанию.
- Cursor передаёт скрипту сведения о событии в формате JSON через stdin. Скрипт печатает ответ в формате JSON в stdout.
- Код выхода `0` — хук сработал, Cursor использует ответ. Код `2` — запретить действие, как при ответе `"permission": "deny"`. Любой другой код — хук не сработал, и действие выполняется.
- Для событий, которые разрешают или запрещают действие (`beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `beforeTabFileRead`, `subagentStart`, `preToolUse`), непонятный ответ при коде `0` — не JSON или с неверными значениями — запрещает действие.
- Необязательные настройки: `timeout` — сколько секунд ждать ответа; `matcher` — условие запуска, регулярное выражение; `failClosed` — при значении `true` сбой хука (падение, превышение времени, ненулевой код выхода, пустой ответ) запрещает действие; `loop_limit` — только для `stop` и `subagentStop`.
- С чем сравнивается `matcher`, зависит от события: для `beforeShellExecution` — с текстом команды, для `preToolUse` — с типом инструмента, для `subagentStart` — с типом субагента. Пустая строка или `"*"` — запускать всегда.
- Папка, из которой запускается скрипт, зависит от уровня хука: Project hooks — корень проекта (путь `.cursor/hooks/имя.sh`), User hooks — папка `~/.cursor/` (путь `./hooks/имя.sh`).
- Скрипту доступны переменные окружения, в том числе `CURSOR_PROJECT_DIR` — корень проекта и `CURSOR_VERSION` — версия Cursor.
- На Windows приложение Cursor запускает команды хуков через PowerShell: скрипт PowerShell читает входной JSON из переменной `$input`.

## Структура запроса

```text
Цель:
Что должно происходить автоматически и зачем?

Где хранится хук:
В проекте (Project hooks) или лично у вас (User hooks)?

Событие:
В какой момент срабатывает хук?

Условие запуска:
Для каких именно команд, инструментов, файлов срабатывает хук?

Ответ скрипта:
Что решает скрипт: разрешить, запретить, спросить пользователя, ничего
не менять?

Сообщения:
Что увидит пользователь и что узнает агент?

Если хук не сработал:
Выполнить действие или запретить его? Сколько секунд ждать ответа?

Не входит в задачу хука:
Что остаётся правилам, CI и другим средствам контроля?

Проверка:
В каких случаях хук должен сработать, а в каких — нет?
```

## Шаблон промпта

```text
Создай Cursor Hook типа Command-based hooks.

Цель:


Где хранится хук:
В проекте (Project hooks) / лично у меня (User hooks).


Событие:


Условие запуска:
Всегда / только для (каких команд, инструментов, файлов).


Ответ скрипта:
Разрешить / запретить / спросить пользователя / ничего не менять.


Сообщения пользователю и агенту:


Если хук не сработал:
Выполнить действие / запретить действие.


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks, раздел
   Command-Based Hooks и описание выбранного события:
   https://cursor.com/docs/hooks#command-based-hooks
2. Прочитай шаблон `templates/hook/command-based-hooks.json`, его копию
   с пояснениями `templates/hook/command-based-hooks.annotated.jsonc`,
   скрипты в `templates/hook/hooks/`, существующие `.cursor/hooks.json`
   и `.cursor/hooks/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен хук со скриптом. Если условие
   нельзя надёжно проверить программой, предложи Prompt-based hooks. Если
   нужно указание для агента, а не автоматическое действие, предложи
   правило. Объясни причину и не создавай хук без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Команды, пути и инструменты бери из репозитория, а не придумывай.
   Проверь, что программы, которые нужны скрипту (например, `jq`),
   установлены.
5. Предложи:
   - событие и условие `matcher` или объясни, почему условие проверяет
     сам скрипт;
   - поля ответа скрипта и тексты сообщений;
   - настройки `timeout`, `failClosed` и `loop_limit`, если они нужны;
   - полный текст записи для `hooks.json` и текст скрипта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись в `hooks.json` выбранного уровня
   и создай скрипт в папке `hooks` рядом с ним. Сохрани существующие
   хуки. Файл — обычный JSON без комментариев, со строкой `"version": 1`
   и точными именами событий; в значениях не используй две косые черты
   подряд. Путь к скрипту запиши от папки, из которой он запускается.
   Сделай скрипт исполняемым. Скрипт читает stdin целиком, печатает
   в stdout один JSON-объект и больше ничего: вывод вызванных программ
   направляй в файл или в `/dev/null`.
8. Проверь, что `hooks.json` — корректный JSON. Запусти скрипт с примерами
   входных данных для позитивных и негативных сценариев и убедись, что
   он отвечает ожидаемым JSON-объектом и завершается с кодом `0`.
   Убедись, что скрипт не делает ничего сверх описанного, не содержит
   секретов и не противоречит правилам проекта.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа Command-based hooks.

Цель:
В Laravel-приложении бронирований агент однажды выполнил команду
`php artisan migrate:fresh` и стёр локальную базу данных. Нужно
спрашивать подтверждение перед командами, которые удаляют данные.

Где хранится хук:
В проекте.

Событие:
Агент собирается выполнить команду в терминале.

Условие запуска:
В команде есть `migrate:fresh`, `migrate:reset` или `db:wipe`.

Ответ скрипта:
Спросить пользователя.

Сообщения пользователю и агенту:
Пользователю: «Команда удалит данные в базе. Выполнить?»
Агенту: «Команда удаляет данные и требует подтверждения пользователя».

Если хук не сработал:
Запретить действие.

Не входит в задачу хука:
- проверка обычных миграций `php artisan migrate`;
- защита боевой базы данных: к ней у агента нет доступа.

Позитивные сценарии проверки:
- перед командой `php artisan migrate:fresh --seed` появляется запрос
  подтверждения.

Негативные сценарии проверки:
- команды `php artisan migrate` и `php artisan test` выполняются без
  вопросов.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи событие, условие, запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что запись добавлена в `hooks.json`, а скрипт лежит по указанному в ней пути и является исполняемым.
2. Запустить скрипт вручную с примером входных данных, например `echo '{"command": "php artisan migrate:fresh"}' | .cursor/hooks/имя.sh`: он должен напечатать один JSON-объект.
3. Открыть **Customize → Hooks** и убедиться, что хук есть в списке.
4. Выполнить позитивные сценарии: хук должен сработать.
5. Выполнить негативные сценарии: хук не должен срабатывать или не должен ничего менять.
6. Открыть панель **Output**, выбрать канал **Hooks** и убедиться, что хук запускался без ошибок.
7. Если хук не срабатывает, проверить имя события, путь к скрипту и условие `matcher`; при необходимости перезапустить Cursor.
