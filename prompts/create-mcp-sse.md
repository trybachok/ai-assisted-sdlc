# Промпт для создания конфигурации Cursor MCP: SSE server

**SSE server** — удалённый MCP-сервер с подключением по SSE: сервер развёрнут отдельно от Cursor — в интернете, в сети компании или на вашем компьютере, — и Cursor подключается к нему по адресу (URL) для SSE. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт на подключение называет сервис, источник и адрес сервера, способ входа и права, которые получит сервер.

Тип подходит, если сервер уже развёрнут, им пользуются несколько человек и он доступен только по адресу для SSE. В остальных случаях выберите другой тип:

- сервер доступен по адресу для HTTP или предлагает оба адреса — [Streamable HTTP server](create-mcp-streamable-http.md);
- сервер — программа, которую нужно запускать на вашем компьютере, — [stdio server](create-mcp-stdio.md);
- серверу нужны заранее выданные Client ID и Client Secret — [Remote server with Static OAuth](create-mcp-static-oauth.md);
- сервер нужен облачным агентам — SSE не подойдёт: выберите [Streamable HTTP server](create-mcp-streamable-http.md) или [stdio server](create-mcp-stdio.md);
- нужен не внешний сервис, а указание для агента — вместо MCP создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У подключения есть ещё одно свойство — место, где хранится конфигурация, и для каждого — свой промпт: файл проекта — [Project Configuration](create-mcp-project.md), личный файл — [Global Configuration](create-mcp-global.md), дашборд команды — [Team MCP server](create-mcp-team.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#how-it-works). Шаблон — [`templates/mcp/sse-server.json`](../templates/mcp/sse-server.json), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Удалённый сервер описывают записью в файле `mcp.json`: в `.cursor/mcp.json` проекта или в `~/.cursor/mcp.json`. Запись находится в списке `mcpServers` под именем сервера.
- Настройки записи: `url` — адрес сервера для SSE, обязательная; `headers` — заголовки, которые Cursor отправляет серверу, необязательная.
- SSE и Streamable HTTP записывают одинаково — настройкой `url`. Различается только адрес: его сообщает владелец сервера.
- Удалённые серверы поддерживают вход через OAuth. Если сервер проверяет доступ по ключу, ключ передают в `headers`.
- В значениях `url` и `headers` работает подстановка `${env:ИМЯ}` — переменная окружения системы. Настройки `envFile` у удалённых серверов нет.
- Собственные серверы с подключением по SSE облачные агенты не поддерживают.
- После изменения `mcp.json` файл сохраняют и перезапускают Cursor. Серверы включают и выключают в разделе **Customize → MCPs**.
- По умолчанию Cursor спрашивает разрешение перед вызовом инструмента MCP.
- MCP-сервер получает данные, которые передаёт ему агент, и выполняет действия от имени пользователя. Документация советует подключать серверы только из проверенных источников и выдавать ключи с наименьшими правами.

## Структура запроса

```text
Цель:
Какой сервис или какие данные нужны агенту и зачем?

Сервер:
Какой MCP-сервер подключить и кто его владелец? Где его официальная
документация?

Адрес:
По какому адресу для SSE доступен сервер? Есть ли у него адрес для HTTP?

Вход в сервис:
Через OAuth, по ключу доступа или без входа? Где хранится ключ?

Права сервера:
Что серверу разрешено: только читать данные или также изменять их?

Где хранится конфигурация:
В проекте, для всей команды, или лично у вас, во всех проектах?

Не входит в задачу:
Чего сервер делать не должен?

Проверка:
Какой запрос к агенту покажет, что сервер работает?
```

## Шаблон промпта

```text
Создай конфигурацию Cursor MCP типа SSE server.

Цель:


Сервер, его владелец и официальная документация:


Адрес сервера для SSE:


Вход в сервис:
OAuth / ключ доступа в переменной окружения (какой) / не нужен.


Права сервера:
Только чтение / чтение и изменение (чего именно).


Где хранится конфигурация:
В проекте (Project Configuration) / лично у меня (Global Configuration).


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP:
   https://cursor.com/docs/mcp
2. Прочитай шаблон `templates/mcp/sse-server.json`, его копию
   с пояснениями `templates/mcp/sse-server.annotated.jsonc`,
   существующий `.cursor/mcp.json`, `AGENTS.md`, правила и другие
   инструкции репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен сервер с подключением по SSE.
   Если у сервера есть адрес для HTTP или сервер нужен облачным агентам,
   предложи Streamable HTTP server. Если нужно указание для агента,
   а не внешний сервис, предложи правило. Объясни причину и не создавай
   конфигурацию без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Адрес сервера, имя заголовка и способ входа бери из официальной
   документации сервера, а не придумывай.
5. Предложи:
   - имя сервера;
   - адрес сервера;
   - способ входа и, если нужен ключ, переменную окружения для него;
   - файл для записи: `.cursor/mcp.json` проекта или `~/.cursor/mcp.json`;
   - полный текст записи;
   - что сервер сможет читать и изменять;
   - сценарии проверки.
6. До подтверждения не изменяй файлы и не обращайся к серверу.
7. После подтверждения добавь запись в выбранный `mcp.json`. Если файл
   уже есть, сохрани в нём существующие серверы. Файл — обычный JSON без
   комментариев. Значения `headers` — строки. Ключи доступа в файл
   не записывай: используй подстановку `${env:ИМЯ}`. Если сервер
   использует вход через OAuth, настройку `headers` не добавляй.
   Настройку `envFile` не добавляй: у удалённых серверов её нет.
8. Проверь, что `mcp.json` — корректный JSON, что у сервера есть `url`,
   что в файле нет секретов и что запись не противоречит правилам
   проекта.
9. Не утверждай, что сервер подключён и работает в Cursor, если проверка
   фактически не выполнялась. В таком случае предоставь ручной чек-лист
   проверки.
```

## Пример

```text
Создай конфигурацию Cursor MCP типа SSE server.

Цель:
В Laravel-приложении бронирований агент не знает правил отмены брони
и возврата денег. Они описаны в базе знаний службы поддержки. Нужно,
чтобы агент сверялся с ней, когда меняет код отмены бронирования.

Сервер, его владелец и официальная документация:
Внутренний MCP-сервер базы знаний. Его поддерживает команда службы
поддержки, описание — во внутренней документации компании.

Адрес сервера для SSE:
`https://kb.booking.example.com/sse`. Адреса для HTTP у сервера нет.

Вход в сервис:
Ключ доступа в переменной окружения `BOOKING_KB_TOKEN`, заголовок
`Authorization` со словом `Bearer`.

Права сервера:
Только чтение.

Где хранится конфигурация:
В проекте.

Не входит в задачу:
- изменение статей базы знаний;
- подключение сервера к облачным агентам.

Позитивные сценарии проверки:
- на вопрос «За сколько часов до начала можно отменить бронь без
  штрафа?» агент вызывает инструмент сервера и отвечает по статье базы
  знаний.

Негативные сценарии проверки:
- в `.cursor/mcp.json` нет ключа доступа;
- без переменной `BOOKING_KB_TOKEN` сервер не подключается, и причина
  видна в журнале MCP Logs.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи имя сервера и полный текст записи.
До моего подтверждения не изменяй файлы.
```

## Проверка готовой конфигурации

1. Убедиться, что запись сервера находится в нужном файле `mcp.json`, а в файле нет ключей доступа.
2. Перезапустить Cursor, открыть **Customize → MCPs** и убедиться, что сервер есть в списке и включён. Если сервер требует входа, войти в сервис там же.
3. Выполнить позитивные сценарии: агент должен вызвать инструмент сервера. По умолчанию Cursor спросит разрешение на вызов.
4. Выполнить негативные сценарии: сервер не должен делать того, что не входит в задачу.
5. Открыть панель **Output**, выбрать в списке **MCP Logs** и убедиться, что сервер подключился без ошибок.
6. Если сервер не подключается, проверить адрес, имя заголовка и переменную окружения с ключом; после изменений перезапустить Cursor.
