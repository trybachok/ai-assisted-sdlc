# Промпт для создания Cursor Subagent: Background subagent

**Background subagent** — субагент, который работает в фоне: основной агент передаёт ему задачу и, не дожидаясь результата, продолжает свою работу. Режим включает настройка `is_background: true` в файле субагента. Хороший промпт на его создание описывает долгую работу, которую субагент способен выполнить самостоятельно, и итоговый отчёт, понятный без дополнительных вопросов.

Тип подходит для долгих задач и параллельной работы: полный запуск тестов, большой поиск, сбор сведений. В остальных случаях выберите другой тип:

- результат нужен сразу, чтобы продолжить работу, — [Project subagent](create-subagent-project.md) или [User subagent](create-subagent-user.md): они работают в режиме Foreground;
- помощник должен только проверять и ничего не изменять — [Read-only subagent](create-subagent-readonly.md);
- задачу нужно выполнить в облаке, не занимая ваш компьютер, — [Cloud subagent](create-subagent-cloud.md);
- задача простая и выполняется за один шаг — вместо субагента создайте [Cursor Skill](create-skill.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/subagents#foreground-vs-background). Шаблон субагента — [`templates/subagent/background-subagent.md`](../templates/subagent/background-subagent.md), простая инструкция — [`docs/cursor-subagents.md`](../docs/cursor-subagents.md).

## Требования Cursor

- Субагент — файл Markdown в папке `.cursor/agents/` проекта (субагент для проекта) или в `~/.cursor/agents/` (личный субагент для всех проектов).
- Файл состоит из блока настроек (YAML frontmatter) и текста задания под ним.
- Тип задаёт строка `is_background: true`: субагент работает в фоне и не задерживает основного агента. По умолчанию `is_background` равно `false` — это режим Foreground.
- Строка должна выглядеть в точности как `is_background: true` — без кавычек и без пояснения после значения. Иначе режим Background не включится, а сообщения об ошибке не будет.
- Остальные поля: `name` — имя из строчных латинских букв и дефисов; по умолчанию оно берётся из имени файла; `description`; `model` (по умолчанию `inherit`); `readonly` (по умолчанию `false`).
- Основной агент читает `description` и по нему решает, передавать ли задачу. Описание должно быть конкретным; слова «используй проактивно» или «всегда используй для…» поощряют автоматическую передачу.
- Субагент начинает работу с чистым контекстом и не видит историю переписки. В фоне ему некого переспросить, поэтому задание должно быть полным.
- По умолчанию субагент работает в той же копии проекта, что и основной агент: при одновременном изменении файлов они могут затереть изменения друг друга. Субагенту, который должен менять файлы, нужна отдельная копия проекта — её запрашивают при запуске.
- Субагент в фоне записывает ход работы в папку `~/.cursor/subagents/`: по этим файлам основной агент проверяет, как идёт работа. Каждый запуск получает идентификатор, по которому работу можно продолжить.
- Субагент расходует токены отдельно от основного агента.

Режимы работы субагента:

| Режим | Как работает | Для чего подходит |
| --- | --- | --- |
| Foreground | Основной агент ждёт, пока субагент закончит, и сразу получает результат | Последовательные задачи, где результат нужен для следующего шага |
| Background | Основной агент сразу продолжает работу, субагент работает независимо | Долгие задачи и параллельная работа |

## Структура запроса

```text
Цель:
Какую долгую работу основной агент должен передавать субагенту и зачем?

Когда вызывать:
При каких задачах и запросах агент должен запускать субагента в фоне?

Когда не вызывать:
Когда результат нужен сразу или задача слишком мала для фоновой работы?

Порядок работы:
Что субагент делает по шагам? Какие команды и файлы проекта использует?

Работа в фоне:
Можно ли субагенту изменять файлы? Что делать, если данных не хватает?

Итоговый отчёт:
Что субагент должен сообщить, когда закончит?

Настройки:
Где хранить субагента: в проекте или у пользователя?
Нужна ли другая модель? Достаточно ли прав только на чтение?

Не входит в задачу субагента:
Что остаётся основному агенту или другим субагентам?

Проверка:
По каким запросам субагент должен запускаться, а по каким — нет?
```

```text
Настройки:

Модель: та же, что у основного агента / другая (какая).
Права: обычные / только чтение.


Не входит в задачу субагента:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Subagents:
   https://cursor.com/docs/subagents
2. Прочитай шаблон `templates/subagent/background-subagent.md`, существующих
   субагентов в `.cursor/agents/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат из официальной
   документации.
3. Проверь, что задаче действительно нужен Background subagent. Если
   результат нужен сразу, чтобы продолжить работу, предложи режим Foreground
   (Project или User subagent). Если задача простая и выполняется за один
   шаг, предложи skill. Объясни причину и не создавай субагента без
   подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Команды, пути и инструменты бери из репозитория, а не придумывай.
5. Предложи:
   - имя субагента: строчные латинские буквы и дефисы;
   - значение `description`: одной строкой, какую долгую работу выполняет
     субагент и когда передавать ему задачу;
   - расположение файла и значения `model` и `readonly`;
   - полный текст задания: порядок работы, поведение в фоне и состав
     итогового отчёта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл `.cursor/agents/<имя>.md` или
   `~/.cursor/agents/<имя>.md` по шаблону. Значение `name` должно совпадать
   с именем файла. Строку `is_background: true` запиши в точности так. Каждую
   настройку запиши в одну строку, без кавычек и без пояснений после
   значения; в `description` не используй двоеточия и символ `#`.
8. Проверь расположение и расширение файла, блок настроек, отсутствие
   субагента с таким же именем, существование упомянутых команд и путей,
   отсутствие секретов. Убедись, что задание можно выполнить без уточняющих
   вопросов, что субагент не изменяет файлы, с которыми одновременно
   работает основной агент, а `description` отличает позитивные сценарии
   от негативных.
9. Не утверждай, что субагент проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Subagent типа Background subagent.

Цель:
Полный набор тестов Laravel-приложения бронирований идёт около десяти минут.
Пока тесты выполняются, основной агент должен продолжать работу над задачей,
а результаты получить в виде короткого отчёта.

Когда вызывать субагента:
- «Запусти все тесты в фоне»;
- перед созданием pull request;
- после крупных изменений в `app/Services`.

Когда не вызывать:
- запуск одного теста, результат которого нужен сразу;
- изменения только в документации.

Порядок работы субагента:
1. Запустить весь набор тестов PHPUnit командой из README.
2. Для каждого упавшего теста изучить вывод и найти причину сбоя.
3. Составить список сбоев с причинами и предложениями по исправлению.

Работа в фоне:
Изменение файлов проекта запрещено: с ними одновременно работает основной
агент.
Если данных не хватает, не останавливаться: сделать возможное и описать
в отчёте, чего не хватило.

Что субагент должен сообщить в итоговом отчёте:
- сколько тестов прошло и сколько упало;
- причину каждого сбоя;
- что рекомендуется исправить.

Настройки:
Режим: Background.
Расположение: проект, чтобы субагент был у всей команды.
Модель — та же, что у основного агента.
Права обычные: субагент запускает тесты.

Не входит в задачу субагента:
- исправление кода и тестов: это делает основной агент;
- проверка оформления кода.

Позитивные сценарии проверки:
- на запрос «/test-runner запусти все тесты» субагент начинает работу,
  а основной агент сразу продолжает отвечать в чате;
- по окончании работы субагент сообщает число пройденных и упавших тестов
  и причины сбоев.

Негативные сценарии проверки:
- на просьбу «Запусти тест BookingTest и скажи результат» основной агент
  запускает тест сам;
- после изменений только в README субагент не запускается.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи имя, description, настройки и текст задания.
До моего подтверждения не изменяй файлы.
```

## Проверка готового субагента

1. Убедиться, что файл лежит в `.cursor/agents/` или `~/.cursor/agents/`, имеет расширение `.md`, а его имя совпадает со значением `name`.
2. Убедиться, что в блоке настроек есть строка `is_background: true` — без кавычек и без пояснения после значения.
3. Открыть **Customize → Subagents** и убедиться, что субагент есть в списке.
4. В новом чате вызвать субагента явно, например `/test-runner запусти все тесты`: основной агент должен продолжить работу, не дожидаясь результата.
5. Дождаться окончания работы и убедиться, что итоговый отчёт понятен без дополнительных вопросов.
6. Выполнить позитивные и негативные сценарии: основной агент должен передавать субагенту только подходящие задачи.
7. Если агент не передаёт задачу сам, уточнить `description`: назвать в нём задачи, для которых нужен субагент.
8. Project subagent сохранить в git, чтобы субагента получила вся команда.
