# Промпт для создания Cursor Hook: Agent hooks

**Agent hooks** — хуки, которые срабатывают во время работы агента в чате. Это самая большая категория: 18 событий — команды в терминале, чтение и правка файлов, инструменты, субагенты, запросы пользователя и ответы агента. Одни события позволяют запретить действие, другие — только наблюдать или продолжить работу агента. Хороший промпт на создание такого хука описывает нужный момент и действие так, чтобы можно было выбрать одно подходящее событие.

Тип подходит, если хук связан с работой агента в чате. В остальных случаях выберите другой тип:

- хук относится к автодополнению Tab — подсказкам в редакторе — [Tab hooks](create-hook-tab.md);
- хук должен срабатывать, когда Cursor открывает проект, — [App lifecycle hooks](create-hook-app-lifecycle.md);
- нужно не автоматическое действие, а указание для агента — вместо хука создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Где хранится хук: [Project hooks](create-hook-project.md), [User hooks](create-hook-user.md), [Team hooks](create-hook-team.md), [Enterprise hooks](create-hook-enterprise.md). Способ выполнения: скрипт — [Command-based hooks](create-hook-command-based.md), условие для AI-модели — [Prompt-based hooks](create-hook-prompt-based.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks#hook-events). Шаблон — [`templates/hook/agent-hooks.json`](../templates/hook/agent-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- События чата: `sessionStart` — создан новый чат, хук может добавить в него сведения; `sessionEnd` — чат завершён, хук только наблюдает.
- События любых инструментов: `preToolUse` — перед использованием инструмента, хук может разрешить или запретить его и изменить аргументы; `postToolUse` — инструмент отработал; `postToolUseFailure` — инструмент завершился ошибкой. После двух последних хук может передать агенту текст.
- События субагентов: `subagentStart` — перед запуском субагента, хук может разрешить или запретить запуск; `subagentStop` — субагент закончил работу, хук может продолжить её новым сообщением.
- События терминала: `beforeShellExecution` — перед командой, хук может разрешить, запретить или спросить пользователя; `afterShellExecution` — команда выполнена.
- События MCP-серверов: `beforeMCPExecution` — перед вызовом инструмента сервера, хук может разрешить, запретить или спросить пользователя; `afterMCPExecution` — инструмент отработал.
- События файлов: `beforeReadFile` — перед чтением файла, хук может разрешить или запретить чтение; `afterFileEdit` — агент изменил файл.
- События запроса и ответа: `beforeSubmitPrompt` — запрос отправлен, но ещё не ушёл, хук может его не отправить; `preCompact` — перед сжатием длинного чата; `stop` — агент закончил работу, хук может продолжить её новым сообщением; `afterAgentResponse` — агент написал ответ; `afterAgentThought` — агент закончил блок размышлений.
- Условие `matcher` сравнивается с разными значениями: для `preToolUse`, `postToolUse` и `postToolUseFailure` — с типом инструмента (`Shell`, `Read`, `Write`, `Grep`, `Delete`, `Task`, `MCP:<имя инструмента>`); для `subagentStart` и `subagentStop` — с типом субагента; для `beforeShellExecution` и `afterShellExecution` — с текстом команды. Путь к файлу условие `matcher` не проверяет: его проверяет сам скрипт.
- Ответ «спросить пользователя» (`"permission": "ask"`) работает только для `beforeShellExecution` и `beforeMCPExecution`.
- Хуки `stop` и `subagentStop` продолжают работу не больше пяти раз подряд; предел меняет настройка `loop_limit`.
- В облачных агентах не выполняются `sessionStart`, `sessionEnd`, `beforeMCPExecution` и `afterMCPExecution`.

## Структура запроса

```text
Цель:
Что должно происходить автоматически во время работы агента и зачем?

Момент срабатывания:
Что делает агент в этот момент: выполняет команду, читает или изменяет
файл, вызывает инструмент, запускает субагента, заканчивает работу?
До действия или после него?

Условие запуска:
Для каких именно команд, инструментов, файлов срабатывает хук?

Действие хука:
Что делает хук: наблюдает, запрещает, спрашивает пользователя, изменяет
действие, передаёт агенту текст, продолжает работу?

Сообщения:
Что увидит пользователь и что узнает агент?

Где хранится хук и как выполняется:
В проекте или лично у вас? Скрипт или условие для AI-модели?

Не входит в задачу хука:
Что остаётся правилам, CI и другим средствам контроля?

Проверка:
В каких случаях хук должен сработать, а в каких — нет?
```

## Шаблон промпта

```text
Создай Cursor Hook типа Agent hooks.

Цель:


Момент срабатывания:
Агент (что делает). До действия / после действия.


Условие запуска:
Всегда / только для (каких команд, инструментов, файлов).


Действие хука:
Наблюдать / запретить / спросить пользователя / изменить действие /
передать агенту текст / продолжить работу.


Сообщения пользователю и агенту:


Где хранится хук:
В проекте (Project hooks) / лично у меня (User hooks).


Способ выполнения:
Скрипт (Command-based hooks) / условие для AI-модели (Prompt-based hooks).


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks, разделы
   Hook categories и Hook events:
   https://cursor.com/docs/hooks#hook-events
2. Прочитай шаблон `templates/hook/agent-hooks.json`, его копию
   с пояснениями `templates/hook/agent-hooks.annotated.jsonc`, скрипты
   в `templates/hook/hooks/`, существующие `.cursor/hooks.json`
   и `.cursor/hooks/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Выбери одно событие, которое точнее всего соответствует моменту
   срабатывания, и объясни выбор. Если подходят несколько событий, назови
   различия. Если нужного действия событие не позволяет (например,
   наблюдающее событие не может запретить действие), скажи об этом
   и предложи другое событие. Если хук относится к Tab или к открытию
   проекта, предложи Tab hooks или App lifecycle hooks. Не создавай хук
   без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Команды, пути и инструменты бери из репозитория, а не придумывай.
   Проверь, что программы, которые нужны скрипту (например, `jq`),
   установлены.
5. Предложи:
   - событие и условие `matcher` или объясни, почему условие проверяет
     сам скрипт;
   - поля ответа хука и тексты сообщений;
   - настройки `timeout`, `failClosed` и `loop_limit`, если они нужны;
   - полный текст записи для `hooks.json` и текст скрипта;
   - сценарии проверки;
   - будет ли хук работать в облачных агентах.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись в `hooks.json` выбранного уровня
   и создай скрипт в папке `hooks` рядом с ним. Сохрани существующие
   хуки. Файл — обычный JSON без комментариев, со строкой `"version": 1`
   и точными именами событий; в значениях не используй две косые черты
   подряд. Путь к скрипту запиши от папки, из которой он запускается:
   для хуков проекта — от корня проекта. Сделай скрипт исполняемым.
   Скрипт печатает в stdout один JSON-объект и больше ничего.
8. Проверь, что `hooks.json` — корректный JSON. Запусти скрипт с примерами
   входных данных для позитивных и негативных сценариев и убедись, что
   он отвечает ожидаемым JSON-объектом. Для хуков `stop` и `subagentStop`
   убедись, что работа не продолжается бесконечно. Убедись, что скрипт
   не делает ничего сверх описанного, не содержит секретов
   и не противоречит правилам проекта.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа Agent hooks.

Цель:
В Laravel-приложении бронирований агент иногда заканчивает работу,
не запустив тесты. Нужно, чтобы после изменения PHP-файлов он сам
запускал тесты PHPUnit и исправлял ошибки.

Момент срабатывания:
Агент закончил работу над запросом. После действия.

Условие запуска:
Только если в проекте есть изменённые PHP-файлы, которые ещё
не сохранены в git.

Действие хука:
Продолжить работу агента сообщением: «Запусти тесты PHPUnit и исправь
ошибки, если они есть». Не больше одного продолжения подряд.

Сообщения пользователю и агенту:
Других сообщений не нужно.

Где хранится хук:
В проекте.

Способ выполнения:
Скрипт.

Не входит в задачу хука:
- запуск тестов самим хуком: тесты запускает агент;
- проверка стиля кода.

Позитивные сценарии проверки:
- после правки `app/Services/BookingService.php` агент получает сообщение
  и запускает тесты PHPUnit.

Негативные сценарии проверки:
- после ответа на вопрос «Как устроена авторизация?» сообщение
  не приходит: файлы не менялись;
- после запуска тестов сообщение не приходит повторно.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи событие, запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что запись добавлена в `hooks.json` под точным именем события, а скрипт лежит по указанному в ней пути и является исполняемым.
2. Открыть **Customize → Hooks** и убедиться, что хук есть в списке.
3. Выполнить позитивные сценарии: хук должен сработать.
4. Выполнить негативные сценарии: хук не должен срабатывать или не должен ничего менять.
5. Для хуков `stop` и `subagentStop` убедиться, что агент не продолжает работу бесконечно.
6. Открыть панель **Output**, выбрать канал **Hooks** и убедиться, что хук запускался без ошибок.
7. Если хук не срабатывает, проверить имя события, путь к скрипту и условие `matcher`; при необходимости перезапустить Cursor.
