# Промпт для создания конфигурации Cursor MCP: Project Configuration

**Project Configuration** — MCP-серверы одного проекта: файл `.cursor/mcp.json`, который хранится вместе с проектом, и серверы из него получают все, кто открыл проект в Cursor. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт на создание конфигурации называет серверы, их источник, способ подключения, ключи доступа и то, что должен сделать каждый участник команды.

Тип подходит, если серверы нужны всем, кто работает с проектом, и относятся к его сервисам и данным. В остальных случаях выберите другой тип:

- сервер нужен лично вам во всех проектах — [Global Configuration](create-mcp-global.md);
- сервер нужен всей команде во всех её проектах или облачным агентам — [Team MCP server](create-mcp-team.md);
- нужен не внешний сервис, а указание для агента — вместо MCP создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У подключения есть ещё одно свойство — способ связи с сервером, и для каждого — свой промпт: локальная программа — [stdio server](create-mcp-stdio.md), удалённый сервер — [Streamable HTTP server](create-mcp-streamable-http.md) или [SSE server](create-mcp-sse.md), удалённый сервер с заранее выданным Client ID — [Remote server with Static OAuth](create-mcp-static-oauth.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#configuration-locations). Шаблон — [`templates/mcp/project-mcp.json`](../templates/mcp/project-mcp.json), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Конфигурацию проекта хранят в файле `.cursor/mcp.json` в корне проекта. Файл сохраняют в git, чтобы серверы получила вся команда.
- Файл содержит список `mcpServers`: имя сервера → настройки сервера. Серверов может быть несколько: локальный сервер записывают настройкой `command`, удалённый — настройкой `url`.
- Cursor объединяет серверы проекта и личные серверы из `~/.cursor/mcp.json`. Если имя сервера совпадает, действует запись проекта.
- В значениях работают подстановки: `${workspaceFolder}` — корень проекта, то есть папка, в которой лежит `.cursor/mcp.json`; `${env:ИМЯ}` — переменная окружения системы.
- Файл видят все, у кого есть доступ к репозиторию, поэтому ключи доступа и пароли в него не записывают. Каждый участник задаёт их на своём компьютере: в переменных окружения или в файле из настройки `envFile`.
- После изменения файла его сохраняют и перезапускают Cursor. Серверы включают и выключают в разделе **Customize → MCPs**.
- Для облачных агентов серверы настраивают отдельно: на странице cursor.com/agents или в дашборде команды.
- По умолчанию Cursor спрашивает разрешение перед вызовом инструмента MCP.
- MCP-сервер обращается к внешним сервисам и выполняет действия от имени пользователя. Документация советует подключать серверы только из проверенных источников и выдавать ключи с наименьшими правами.

## Структура запроса

```text
Цель:
Какие сервисы или данные нужны агенту в этом проекте и зачем?

Серверы:
Какие MCP-серверы подключить? Где их официальная документация или
исходный код?

Способ подключения:
Для каждого сервера: команда запуска или адрес?

Ключи и настройки:
Какие ключи доступа нужны серверам? Где участники команды их хранят?

Права серверов:
Что серверам разрешено: только читать данные или также изменять их?

Команда:
Какие программы установлены у участников? Какие у них операционные
системы?

Не входит в задачу:
Чего серверы делать не должны?

Проверка:
Какие запросы к агенту покажут, что серверы работают?
```

## Шаблон промпта

```text
Создай конфигурацию Cursor MCP типа Project Configuration.

Цель:


Серверы и их официальная документация:


Способ подключения каждого сервера:
Команда запуска (stdio server) / адрес (Streamable HTTP server или
SSE server) / адрес и Client ID (Remote server with Static OAuth).


Ключи доступа и настройки:
Нет / переменные окружения (какие) / файл с переменными (какой).


Права серверов:
Только чтение / чтение и изменение (чего именно).


Программы и операционные системы участников команды:


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP:
   https://cursor.com/docs/mcp
2. Прочитай шаблон `templates/mcp/project-mcp.json`, его копию
   с пояснениями `templates/mcp/project-mcp.annotated.jsonc`,
   существующий `.cursor/mcp.json`, `AGENTS.md`, правила и другие
   инструкции репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что серверы действительно нужны всем, кто работает
   с проектом. Если сервер нужен одному человеку, предложи Global
   Configuration. Если сервер нужен всей команде во всех проектах или
   облачным агентам, предложи Team MCP server. Объясни причину
   и не создавай конфигурацию без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Имена пакетов, команды запуска и адреса серверов бери из официальной
   документации серверов или из репозитория, а не придумывай. Проверь,
   что программы, которые нужны серверам, есть у участников команды.
5. Предложи:
   - имена серверов и способ подключения каждого;
   - переменные окружения для ключей доступа;
   - полный текст файла `.cursor/mcp.json`;
   - что каждый сервер сможет читать и изменять;
   - что должен сделать каждый участник команды: какие программы
     установить и какие переменные окружения задать;
   - сценарии проверки.
6. До подтверждения не изменяй файлы, не устанавливай пакеты
   и не запускай серверы.
7. После подтверждения создай или дополни `.cursor/mcp.json`. Если файл
   уже есть, сохрани в нём существующие серверы. Файл — обычный JSON без
   комментариев. `args` — список строк, значения `env` и `headers` —
   строки. Пути к файлам проекта записывай через `${workspaceFolder}`.
   Ключи доступа и пароли в файл не записывай: используй подстановку
   `${env:ИМЯ}` или настройку `envFile`.
8. Проверь, что `.cursor/mcp.json` — корректный JSON, что у каждого
   сервера есть `command` или `url`, что в файле нет секретов и что
   запись не противоречит правилам проекта. Если в `envFile` указан файл
   с секретами, проверь, что он не попадает в git.
9. Не утверждай, что серверы подключены и работают в Cursor, если
   проверка фактически не выполнялась. В таком случае предоставь ручной
   чек-лист проверки.
```

## Пример

```text
Создай конфигурацию Cursor MCP типа Project Configuration.

Цель:
Всем, кто работает с Laravel-приложением бронирований, нужны два
источника данных для агента: структура тестовой базы и задачи проекта
на GitHub. Сейчас каждый настраивает их по-своему.

Серверы и их официальная документация:
1. Собственный MCP-сервер проекта `tools/booking-mcp/server.js`: отдаёт
   структуру тестовой базы. Описание — в `tools/booking-mcp/README.md`.
2. Официальный удалённый MCP-сервер GitHub. Адрес возьми из его
   официальной документации.

Способ подключения каждого сервера:
1. Команда запуска: `node tools/booking-mcp/server.js`.
2. Адрес.

Ключи доступа и настройки:
1. Строка подключения к тестовой базе — в переменной окружения
   `BOOKING_TEST_DATABASE_URL`.
2. Персональный токен GitHub с правами только на чтение — в переменной
   окружения `GITHUB_MCP_TOKEN`.

Права серверов:
Только чтение.

Программы и операционные системы участников команды:
macOS и Linux, у всех установлен Node.js.

Не входит в задачу:
- доступ к рабочей базе данных;
- создание и закрытие задач на GitHub.

Позитивные сценарии проверки:
- на вопрос «Какие столбцы есть в таблице bookings?» агент вызывает
  инструмент первого сервера;
- на запрос «Перескажи задачу о двойном бронировании» агент вызывает
  инструмент второго сервера;
- серверы работают на компьютере другого участника без правки файла.

Негативные сценарии проверки:
- в `.cursor/mcp.json` нет строки подключения и токена;
- запрос на изменение данных тестовой базы сервер не выполняет.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи текст файла и памятку для участников команды.
До моего подтверждения не изменяй файлы и ничего не запускай.
```

## Проверка готовой конфигурации

1. Убедиться, что файл `.cursor/mcp.json` лежит в корне проекта и в нём нет ключей доступа и паролей.
2. Перезапустить Cursor, открыть **Customize → MCPs** и убедиться, что серверы есть в списке и включены: сервер из файла проекта может ждать, пока вы его включите.
3. Выполнить позитивные сценарии: агент должен вызвать инструменты серверов. По умолчанию Cursor спросит разрешение на вызов.
4. Выполнить негативные сценарии: серверы не должны делать того, что не входит в задачу.
5. Открыть панель **Output**, выбрать в списке **MCP Logs** и убедиться, что серверы запустились без ошибок.
6. Сохранить `.cursor/mcp.json` в git и передать участникам команды памятку: какие программы установить и какие переменные окружения задать.
7. Попросить другого участника открыть проект и повторить проверку на своём компьютере.
