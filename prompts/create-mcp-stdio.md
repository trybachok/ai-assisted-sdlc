# Промпт для создания конфигурации Cursor MCP: stdio server

**stdio server** — локальный MCP-сервер: программа, которую Cursor сам запускает на вашем компьютере и которой сам управляет. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт на подключение называет сервис, источник сервера, команду запуска, ключи доступа и права, которые получит сервер.

Тип подходит, если сервер поставляется как программа или пакет, работает на вашем компьютере и нужен одному человеку — в том числе для работы с закрытыми данными. В остальных случаях выберите другой тип:

- сервер развёрнут отдельно и доступен по адресу для HTTP — [Streamable HTTP server](create-mcp-streamable-http.md);
- сервер развёрнут отдельно и доступен только по адресу для SSE — [SSE server](create-mcp-sse.md);
- удалённому серверу нужны заранее выданные Client ID и Client Secret — [Remote server with Static OAuth](create-mcp-static-oauth.md);
- нужен не внешний сервис, а указание для агента — вместо MCP создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У подключения есть ещё одно свойство — место, где хранится конфигурация, и для каждого — свой промпт: файл проекта — [Project Configuration](create-mcp-project.md), личный файл — [Global Configuration](create-mcp-global.md), дашборд команды — [Team MCP server](create-mcp-team.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#stdio-server-configuration). Шаблон — [`templates/mcp/stdio-server.json`](../templates/mcp/stdio-server.json), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Локальный сервер описывают записью в файле `mcp.json`: в `.cursor/mcp.json` проекта или в `~/.cursor/mcp.json`. Запись находится в списке `mcpServers` под именем сервера.
- Настройки записи: `type` со значением `"stdio"` и `command` — обязательные по документации; `args`, `env` и `envFile` — необязательные.
- `command` — команда запуска сервера: программа, доступная в системном пути (PATH), или полный путь к ней, например `npx`, `node`, `python`, `docker`.
- `args` — аргументы команды, список строк. `env` — переменные окружения для сервера. `envFile` — путь к файлу с дополнительными переменными окружения; эта настройка есть только у локальных серверов.
- В значениях работают подстановки: `${env:ИМЯ}` — переменная окружения системы, `${userHome}` — домашняя папка, `${workspaceFolder}` — корень проекта.
- Cursor сам запускает сервер и управляет им. Ключи доступа передают серверу через переменные окружения.
- После изменения `mcp.json` файл сохраняют и перезапускают Cursor. Серверы включают и выключают в разделе **Customize → MCPs**.
- По умолчанию Cursor спрашивает разрешение перед вызовом инструмента MCP.
- MCP-сервер обращается к внешним сервисам и выполняет код от имени пользователя. Документация советует подключать серверы только из проверенных источников, выдавать ключи с наименьшими правами, а с закрытыми данными работать через локальные серверы.

## Структура запроса

```text
Цель:
Какой сервис или какие данные нужны агенту и зачем?

Сервер:
Какой MCP-сервер подключить? Где его официальная документация или
исходный код?

Запуск:
Какой командой запускается сервер? Какие программы для этого нужны?

Ключи и настройки:
Какие ключи доступа и настройки нужны серверу? Где они хранятся?

Права сервера:
Что серверу разрешено: только читать данные или также изменять их?

Где хранится конфигурация:
В проекте, для всей команды, или лично у вас, во всех проектах?

Не входит в задачу:
Чего сервер делать не должен?

Проверка:
Какой запрос к агенту покажет, что сервер работает?
```

## Шаблон промпта

```text
Создай конфигурацию Cursor MCP типа stdio server.

Цель:


Сервер и его официальная документация:


Команда запуска и необходимые программы:


Ключи доступа и настройки:
Нет / переменные окружения (какие) / файл с переменными (какой).


Права сервера:
Только чтение / чтение и изменение (чего именно).


Где хранится конфигурация:
В проекте (Project Configuration) / лично у меня (Global Configuration).


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP:
   https://cursor.com/docs/mcp
2. Прочитай шаблон `templates/mcp/stdio-server.json`, его копию
   с пояснениями `templates/mcp/stdio-server.annotated.jsonc`,
   существующий `.cursor/mcp.json`, `AGENTS.md`, правила и другие
   инструкции репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен локальный сервер. Если сервер
   доступен по адресу, предложи Streamable HTTP server или SSE server.
   Если нужно указание для агента, а не внешний сервис, предложи правило.
   Объясни причину и не создавай конфигурацию без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Имя пакета, команду запуска и настройки бери из официальной
   документации сервера или из репозитория, а не придумывай: команда
   вроде `npx -y` загружает пакет из интернета и запускает его. Проверь,
   что программы, которые нужны серверу, установлены.
5. Предложи:
   - имя сервера;
   - команду запуска и аргументы;
   - переменные окружения и способ, которым пользователь задаст ключи
     доступа;
   - файл для записи: `.cursor/mcp.json` проекта или `~/.cursor/mcp.json`;
   - полный текст записи;
   - что сервер сможет читать и изменять;
   - сценарии проверки.
6. До подтверждения не изменяй файлы, не устанавливай пакеты
   и не запускай сервер.
7. После подтверждения добавь запись в выбранный `mcp.json`. Если файл
   уже есть, сохрани в нём существующие серверы. Файл — обычный JSON без
   комментариев. `args` — список строк, значения `env` — строки. Пути
   к файлам проекта записывай через `${workspaceFolder}`, пути в домашней
   папке — через `${userHome}`. Ключи доступа и пароли в файл
   не записывай: используй подстановку `${env:ИМЯ}` или настройку
   `envFile`.
8. Проверь, что `mcp.json` — корректный JSON, что у сервера есть
   `command`, что в файле нет секретов и что запись не противоречит
   правилам проекта. Если в `envFile` указан файл с секретами, проверь,
   что он не попадает в git и не содержит лишних паролей.
9. Не утверждай, что сервер подключён и работает в Cursor, если проверка
   фактически не выполнялась. В таком случае предоставь ручной чек-лист
   проверки.
```

## Пример

```text
Создай конфигурацию Cursor MCP типа stdio server.

Цель:
В Laravel-приложении бронирований агент ошибается в названиях таблиц
и столбцов. Нужно, чтобы при работе с миграциями и запросами он сверялся
со структурой тестовой базы данных.

Сервер и его официальная документация:
Собственный MCP-сервер проекта: `tools/booking-mcp/server.js`. Описание —
в `tools/booking-mcp/README.md`.

Команда запуска и необходимые программы:
`node tools/booking-mcp/server.js`. На компьютерах команды установлен
Node.js.

Ключи доступа и настройки:
Строка подключения к тестовой базе — в переменной окружения
`BOOKING_TEST_DATABASE_URL`. В файл её не записывай.

Права сервера:
Только чтение. Пользователь базы данных — с правами только на чтение.

Где хранится конфигурация:
В проекте.

Не входит в задачу:
- доступ к рабочей базе данных;
- изменение данных и структуры базы.

Позитивные сценарии проверки:
- на вопрос «Какие столбцы есть в таблице bookings?» агент вызывает
  инструмент сервера и отвечает по данным тестовой базы.

Негативные сценарии проверки:
- запрос на удаление строк сервер не выполняет;
- в `.cursor/mcp.json` нет строки подключения и пароля.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи имя сервера, команду запуска и полный текст записи.
До моего подтверждения не изменяй файлы и ничего не запускай.
```

## Проверка готовой конфигурации

1. Убедиться, что запись сервера находится в нужном файле `mcp.json`, а в файле нет ключей доступа и паролей.
2. Перезапустить Cursor, открыть **Customize → MCPs** и убедиться, что сервер есть в списке и включён.
3. Выполнить позитивные сценарии: агент должен вызвать инструмент сервера. По умолчанию Cursor спросит разрешение на вызов.
4. Выполнить негативные сценарии: сервер не должен делать того, что не входит в задачу.
5. Открыть панель **Output**, выбрать в списке **MCP Logs** и убедиться, что сервер запустился без ошибок.
6. Если сервер не запускается, проверить, что программа из `command` установлена, имя пакета и путь указаны точно, а переменные окружения заданы; после изменений перезапустить Cursor.
