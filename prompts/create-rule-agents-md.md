# Промпт для создания Cursor Rule: AGENTS.md

**`AGENTS.md`** — простой файл Markdown с указаниями для агента. У него нет блока настроек и условий применения, поэтому он подходит проектам, которым нужна короткая понятная памятка. Хороший промпт на его создание перечисляет разделы памятки, место файла в проекте и уже существующие инструкции, с которыми нельзя разойтись.

`AGENTS.md` подходит, если указания простые и относятся ко всему проекту или к целой папке. В остальных случаях выберите Project Rule или другой тип:

- нужно управлять тем, когда правило подключается, — [Always Apply](create-rule-always-apply.md), [Apply Intelligently](create-rule-apply-intelligently.md), [Apply to Specific Files](create-rule-apply-to-specific-files.md) или [Apply Manually](create-rule-apply-manually.md);
- пожелание личное или общее для всей команды — [User Rule](create-rule-user.md) или [Team Rule](create-rule-team.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/rules#agentsmd). Шаблон — [`templates/rule/AGENTS.template.md`](../templates/rule/AGENTS.template.md), простая инструкция — [`docs/cursor-rules.md`](../docs/cursor-rules.md).

## Требования Cursor

- `AGENTS.md` — обычный файл Markdown без метаданных: блока настроек (frontmatter) у него нет.
- Файл размещают в корне проекта. Это простая альтернатива папке `.cursor/rules`.
- Файлы `AGENTS.md` поддерживаются и в подпапках. Вложенный файл автоматически применяется, когда агент работает с файлами своей папки и её подпапок.
- Указания из вложенных файлов объединяются с указаниями из родительских папок. При противоречии приоритет у более конкретных, то есть у файла из более близкой папки.
- Указания должны быть конкретными и короткими. Не нужно пересказывать руководства по стилю (для этого есть линтер), общеизвестные команды, редкие случаи и код, который уже есть в проекте.

## Структура запроса

```text
Цель:
Какие ошибки агента должна предотвращать памятка?

Содержание:
Какие разделы нужны: стиль кода, архитектура, проверки, ограничения?
Какие указания входят в каждый раздел?

Расположение:
Только корень проекта или ещё подпапки? Какие именно?

Существующие инструкции:
Есть ли уже AGENTS.md и правила в .cursor/rules, с которыми нельзя разойтись?

Не входит в памятку:
Что остаётся линтеру, правилам или документации?

Проверка:
По каким запросам в новом чате будет видно, что агент следует памятке?
```

## Шаблон промпта

```text
Создай AGENTS.md для проекта.

Цель:


Содержание по разделам:


Расположение:
Только корень проекта / корень и подпапки (какие).


Существующие инструкции:


Не входит в памятку:


Сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Rules, раздел AGENTS.md:
   https://cursor.com/docs/rules#agentsmd
2. Прочитай шаблон `templates/rule/AGENTS.template.md`, существующие файлы
   `AGENTS.md` в корне и подпапках, правила в `.cursor/rules/`, README
   и другие инструкции репозитория. Если шаблона в проекте нет, используй
   формат из официальной документации.
3. Проверь, что задаче подходит AGENTS.md. Если указания должны применяться
   только к части задач или файлов, предложи Project Rule нужного типа,
   объясни причину и не создавай файл без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Команды, пути и инструменты бери из репозитория, а не придумывай.
5. Предложи:
   - расположение каждого файла `AGENTS.md`;
   - полный текст каждого файла;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл с точным именем `AGENTS.md`, без
   frontmatter. Если файл уже существует, не перезаписывай его целиком:
   покажи предлагаемые изменения и дождись подтверждения.
8. Проверь имя и расположение файла, отсутствие frontmatter, существование
   упомянутых команд и путей, отсутствие секретов, повторов и противоречий
   с правилами в `.cursor/rules/` и с другими файлами `AGENTS.md`.
9. Не утверждай, что указания проверены в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай AGENTS.md для проекта.

Цель:
Дать агенту короткую памятку по Laravel-приложению бронирований, чтобы он
не нарушал базовые договорённости команды.

Содержание по разделам:
- Стиль кода: оформление проверяет Laravel Pint; имена классов и методов —
  на английском языке.
- Архитектура: бизнес-логика находится в сервисах `app/Services`,
  контроллеры остаются тонкими; доступ проверяется через policies.
- Проверки: после изменений запускать релевантные тесты PHPUnit
  и Laravel Pint.
- Ограничения: не добавлять зависимости без согласования; миграции должны
  быть обратимыми.

Расположение:
Только корень проекта.

Существующие инструкции:
`AGENTS.md` и правил в `.cursor/rules/` пока нет.

Не входит в памятку:
- описание бизнес-процессов;
- инструкции по развёртыванию.

Сценарии проверки:
- на просьбу «Добавь страницу со списком бронирований» агент размещает
  логику в сервисе и запускает тесты и Laravel Pint;
- на просьбу «Подключи пакет для экспорта в Excel» агент сначала
  спрашивает подтверждение.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи расположение и полный текст файла.
До моего подтверждения не изменяй файлы.
```

## Проверка готового файла

1. Убедиться, что файл называется именно `AGENTS.md` и лежит в корне проекта или в нужной подпапке.
2. Убедиться, что в файле нет блока настроек: только обычный Markdown.
3. Открыть новый чат и выполнить сценарии проверки: агент должен следовать указаниям без напоминаний.
4. Для вложенного `AGENTS.md` дать задачу по файлу из его папки и по файлу из другой папки: указания должны применяться только в первом случае.
5. Убедиться, что указания не противоречат правилам в `.cursor/rules/` и другим файлам `AGENTS.md`.
6. Сохранить файл в git, чтобы указания получила вся команда.
