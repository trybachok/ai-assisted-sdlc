# Промпт для создания Cursor Rule: Team Rule

**Team Rule** — правило для всей команды, которое действует во всех её проектах. Оно хранится не в файлах проекта: его создаёт администратор команды в [дашборде Cursor](https://cursor.com/dashboard/team-content) на тарифах Team и Enterprise. Поэтому промпт просит агента подготовить текст правила и рекомендации по настройкам, а в дашборд их переносит администратор. Хороший промпт определяет, кого и какие проекты затрагивает правило, должно ли оно быть обязательным и как проверить результат.

Team Rule подходит для стандартов, единых для всех проектов команды. В остальных случаях выберите другой тип:

- требование относится к одному проекту — Project Rule подходящего типа (как выбрать тип, описано в [`docs/cursor-rules.md`](../docs/cursor-rules.md)) или [`AGENTS.md`](create-rule-agents-md.md);
- пожелание личное — [User Rule](create-rule-user.md).

Требования и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/rules#team-rules). Шаблон — [`templates/rule/team-rule.md`](../templates/rule/team-rule.md), простая инструкция — [`docs/cursor-rules.md`](../docs/cursor-rules.md).

## Требования Cursor

- Team Rules доступны на тарифах Team и Enterprise. Их создаёт и изменяет администратор команды в дашборде Cursor.
- Текст Team Rule пишется в свободной форме. Структура папок Project Rules не используется.
- Для правила можно задать glob-шаблон, например `**/*.py`. С шаблоном правило применяется, только когда в контексте есть подходящие файлы; без шаблона — в каждом чате.
- **Enable this rule immediately**: с отметкой правило действует сразу после создания; без неё сохраняется как черновик и не применяется, пока его не включат.
- **Enforce this rule**: с отметкой правило обязательно для всех участников, и отключить его в Customize нельзя. Правило без отметки участник может отключить в Customize, раздел Team Rules.
- Включённое правило попадает в контекст агента в чате во всех репозиториях и проектах команды.
- Правила применяются в порядке Team Rules → Project Rules → User Rules. При противоречии главнее более ранний источник.
- Обязательные правила можно использовать в процессах контроля соответствия, но указания для AI не должны быть единственной мерой контроля безопасности.

## Структура запроса

```text
Цель:
Какой единый стандарт команды закрепляет правило?

Аудитория:
Каких участников и какие проекты затрагивает правило?

Требования:
Что агент должен делать и чего не должен? Формулировки подходят для любого проекта команды.

Область действия:
Каждый чат или только работа с определёнными файлами? Какой нужен glob-шаблон?

Обязательность:
Могут ли участники отключать правило?

Запуск:
Включить правило сразу или сохранить как черновик?

Не входит в правило:
Что относится к отдельным проектам или обеспечивается другими средствами?

Проверка:
По каким запросам в новом чате будет видно, что правило работает?
```

## Шаблон промпта

```text
Подготовь Team Rule для Cursor.

Цель:


Аудитория и проекты:


Требования, которые должен соблюдать агент:


Область действия:
Каждый чат / только файлы (какие).


Обязательность:
Обязательное для всех / участники могут отключать.


Запуск:
Сразу после создания / сначала черновик.


Не входит в правило:


Сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Rules, раздел Team Rules:
   https://cursor.com/docs/rules#team-rules
2. Прочитай шаблон `templates/rule/team-rule.md`. Если шаблона в проекте
   нет, используй формат из официальной документации.
3. Проверь, что требования подходят для всех проектов команды. Требования
   одного проекта не включай в текст: предложи оформить их как Project Rule
   и объясни причину.
4. Перечисли предположения и задай уточняющие вопросы.
5. Подготовь по шаблону:
   - название правила;
   - текст правила в свободной форме, без frontmatter;
   - glob-шаблон или указание, что он не нужен;
   - рекомендации по настройкам Enable this rule immediately
     и Enforce this rule с обоснованием.
6. Не создавай и не изменяй файлы: Team Rule хранится в дашборде Cursor.
   Выведи результат в чат так, чтобы текст правила можно было скопировать
   целиком.
7. Если правило касается безопасности, укажи, какими средствами требование
   должно обеспечиваться помимо правила.
8. Не утверждай, что правило создано или действует: создать и проверить
   его может только администратор команды. Предоставь ручной чек-лист
   проверки.
```

## Пример

```text
Подготовь Team Rule для Cursor.

Цель:
Исключить попадание паролей, токенов и ключей доступа в код, логи
и сообщения коммитов во всех проектах команды.

Аудитория и проекты:
Все участники команды, все репозитории.

Требования, которые должен соблюдать агент:
- не записывать секреты в код, конфигурацию, тесты, логи и сообщения
  коммитов;
- если для задачи нужен секрет, просить пользователя задать его через
  переменную окружения;
- обнаружив секрет в коде, сообщить об этом пользователю и не копировать
  значение в ответ;
- не отключать проверки безопасности, чтобы тесты прошли.

Область действия:
Каждый чат, glob-шаблон не нужен.

Обязательность:
Обязательное для всех.

Запуск:
Сначала черновик: правило включим после согласования текста.

Не входит в правило:
- правила хранения секретов в отдельных проектах;
- поиск секретов в истории git.

Сценарии проверки:
- на просьбу «Запиши ключ API прямо в конфигурационный файл» агент
  предлагает переменную окружения и не записывает значение в файл;
- на просьбу «Отключи проверку секретов, чтобы CI прошёл» агент
  отказывается и объясняет причину.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Подготовь название, текст правила и рекомендации по настройкам.
Файлы не создавай и не изменяй.
```

## Проверка готового правила

1. Администратор команды открывает [дашборд Cursor](https://cursor.com/dashboard/team-content) и создаёт правило из подготовленного текста.
2. Убедиться, что glob-шаблон и настройки **Enable this rule immediately** и **Enforce this rule** выставлены как задумано.
3. Участник команды открывает **Customize**, раздел Team Rules: необязательное правило можно отключить, обязательное — нельзя.
4. Открыть новый чат в любом проекте команды и выполнить сценарии проверки.
5. Для правила с glob-шаблоном проверить работу с подходящим и с неподходящим файлом: правило должно применяться только в первом случае.
6. Если правило касается безопасности, убедиться, что требование обеспечивается не только правилом.
