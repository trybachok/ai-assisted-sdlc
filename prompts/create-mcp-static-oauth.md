# Промпт для создания конфигурации Cursor MCP: Remote server with Static OAuth

**Remote server with Static OAuth** — удалённый MCP-сервер с входом через OAuth, для которого Cursor использует заранее выданные данные приложения — Client ID и Client Secret, — а не регистрирует приложение сам. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт на подключение называет сервис, адрес сервера, место хранения Client ID и Client Secret, нужные права и адреса возврата, которые нужно разрешить у владельца сервера.

Тип подходит, если владелец сервера выдаёт постоянный Client ID, требует заранее внести адрес возврата (redirect URL) в список разрешённых или не поддерживает автоматическую регистрацию приложений. В остальных случаях выберите другой тип:

- удалённый сервер с обычным входом через OAuth или по ключу доступа — [Streamable HTTP server](create-mcp-streamable-http.md) или [SSE server](create-mcp-sse.md);
- сервер — программа, которую нужно запускать на вашем компьютере, — [stdio server](create-mcp-stdio.md);
- нужен не внешний сервис, а указание для агента — вместо MCP создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У подключения есть ещё одно свойство — место, где хранится конфигурация, и для каждого — свой промпт: файл проекта — [Project Configuration](create-mcp-project.md), личный файл — [Global Configuration](create-mcp-global.md), дашборд команды — [Team MCP server](create-mcp-team.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#static-oauth-for-remote-servers). Шаблон — [`templates/mcp/static-oauth-server.json`](../templates/mcp/static-oauth-server.json), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Данные приложения OAuth записывают в настройку `auth` записи сервера в файле `mcp.json`. Настройка `auth` работает только у удалённых серверов — тех, что заданы через `url`.
- Настройки `auth`: `CLIENT_ID` — обязательная; `CLIENT_SECRET` — необязательная, нужна, если владелец сервера её выдаёт; `scopes` — необязательная, список прав, которые Cursor запросит у сервера. Без `scopes` Cursor сам узнаёт у сервера список прав.
- Cursor использует постоянные адреса возврата: `https://www.cursor.com/agents/mcp/oauth/callback` — вход из браузера и из Cursor Agents, `http://localhost:8787/callback` — вход из приложения Cursor. Их вносят в настройки приложения у владельца сервера; если участники входят и из браузера, и из приложения, вносят оба адреса.
- В значениях `auth` работает подстановка `${env:ИМЯ}`. Документация советует хранить Client ID и Client Secret в переменных окружения, а не в файле.
- Некоторые серверы продлевают вход без участия пользователя, только если запрошено право вроде `offline_access`: тогда его добавляют в `scopes`.
- После изменения `mcp.json` файл сохраняют и перезапускают Cursor. Серверы включают и выключают в разделе **Customize → MCPs**.
- По умолчанию Cursor спрашивает разрешение перед вызовом инструмента MCP.
- MCP-сервер получает данные, которые передаёт ему агент, и выполняет действия от имени пользователя. Документация советует подключать серверы только из проверенных источников и запрашивать наименьшие права.

## Структура запроса

```text
Цель:
Какой сервис или какие данные нужны агенту и зачем?

Сервер:
Какой MCP-сервер подключить и кто его владелец? Где его официальная
документация?

Почему нужен Static OAuth:
Владелец сервера выдаёт постоянный Client ID, требует заранее разрешить
адрес возврата или не поддерживает автоматическую регистрацию приложений?

Данные приложения:
Где хранятся Client ID и Client Secret? Кто регистрирует приложение
у владельца сервера?

Права:
Какие права (scopes) нужны серверу: только чтение или также изменение?

Откуда входят пользователи:
Из приложения Cursor, из браузера или из обоих?

Где хранится конфигурация:
В проекте, для всей команды, или лично у вас, во всех проектах?

Не входит в задачу:
Чего сервер делать не должен?

Проверка:
Какой запрос к агенту покажет, что сервер работает?
```

## Шаблон промпта

```text
Создай конфигурацию Cursor MCP типа Remote server with Static OAuth.

Цель:


Сервер, его владелец и официальная документация:


Почему нужен Static OAuth:


Переменные окружения для Client ID и Client Secret:


Права (scopes):
Только чтение / чтение и изменение (чего именно).


Откуда входят пользователи:
Приложение Cursor / браузер и Cursor Agents / оба варианта.


Где хранится конфигурация:
В проекте (Project Configuration) / лично у меня (Global Configuration).


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP, раздел
   Static OAuth for remote servers:
   https://cursor.com/docs/mcp#static-oauth-for-remote-servers
2. Прочитай шаблон `templates/mcp/static-oauth-server.json`, его копию
   с пояснениями `templates/mcp/static-oauth-server.annotated.jsonc`,
   существующий `.cursor/mcp.json`, `AGENTS.md`, правила и другие
   инструкции репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что серверу действительно нужен Static OAuth. Если сервер
   поддерживает обычный вход через OAuth или вход по ключу доступа,
   предложи Streamable HTTP server без настройки `auth`. Объясни причину
   и не создавай конфигурацию без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Адрес сервера, названия прав и порядок регистрации приложения бери
   из официальной документации сервера, а не придумывай.
5. Предложи:
   - имя сервера и адрес сервера;
   - имена переменных окружения для Client ID и Client Secret;
   - список прав (scopes) или объяснение, почему он не нужен;
   - адреса возврата Cursor, которые нужно внести в настройки приложения
     у владельца сервера;
   - файл для записи: `.cursor/mcp.json` проекта или `~/.cursor/mcp.json`;
   - полный текст записи;
   - сценарии проверки.
6. До подтверждения не изменяй файлы и не обращайся к серверу.
7. После подтверждения добавь запись в выбранный `mcp.json`. Если файл
   уже есть, сохрани в нём существующие серверы. Файл — обычный JSON без
   комментариев. `scopes` — список строк. Значения Client ID и Client
   Secret не запрашивай у пользователя и в файл не записывай: используй
   подстановку `${env:ИМЯ}`.
8. Проверь, что `mcp.json` — корректный JSON, что у сервера есть `url`,
   а в `auth` — `CLIENT_ID`, что в файле нет секретов и что запрошены
   только нужные права.
9. Не утверждай, что вход выполнен и сервер работает в Cursor, если
   проверка фактически не выполнялась: зарегистрировать приложение
   и войти в сервис может только пользователь. Предоставь ручной чек-лист
   проверки.
```

## Пример

```text
Создай конфигурацию Cursor MCP типа Remote server with Static OAuth.

Цель:
Экраны Laravel-приложения бронирований нарисованы в Figma. Нужно, чтобы
агент сверял с макетом шаблоны страницы бронирования: названия полей,
порядок шагов и тексты кнопок.

Сервер, его владелец и официальная документация:
Официальный удалённый MCP-сервер Figma. Адрес сервера и порядок
регистрации приложения возьми из официальной документации Figma.

Почему нужен Static OAuth:
Figma требует заранее внести адрес возврата в список разрешённых
и выдаёт постоянный Client ID.

Переменные окружения для Client ID и Client Secret:
`FIGMA_MCP_CLIENT_ID` и `FIGMA_MCP_CLIENT_SECRET`. Приложение в Figma
регистрирую я; переменные задам на своём компьютере.

Права (scopes):
Только чтение макетов.

Откуда входят пользователи:
Приложение Cursor.

Где хранится конфигурация:
Лично у меня.

Не входит в задачу:
- изменение макетов и комментариев в Figma;
- подключение сервера другим участникам команды.

Позитивные сценарии проверки:
- на запрос «Сравни поля формы бронирования с макетом» агент вызывает
  инструмент сервера и перечисляет расхождения.

Негативные сценарии проверки:
- в `mcp.json` нет значений Client ID и Client Secret;
- сервер не запрашивает права на изменение макетов.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Предложи текст записи и список того, что мне нужно сделать в Figma.
До моего подтверждения не изменяй файлы.
```

## Проверка готовой конфигурации

1. Убедиться, что в настройках приложения у владельца сервера разрешены адреса возврата Cursor: для приложения, для браузера или оба.
2. Убедиться, что переменные окружения с Client ID и Client Secret заданы, а в `mcp.json` их значений нет.
3. Перезапустить Cursor, открыть **Customize → MCPs**, убедиться, что сервер есть в списке и включён, и войти в сервис.
4. Выполнить позитивные сценарии: агент должен вызвать инструмент сервера. По умолчанию Cursor спросит разрешение на вызов.
5. Выполнить негативные сценарии: сервер не должен получать прав сверх задуманных.
6. Открыть панель **Output**, выбрать в списке **MCP Logs** и убедиться, что вход и подключение прошли без ошибок.
7. Если вход не проходит, проверить адреса возврата, значения переменных окружения и названия прав; после изменений перезапустить Cursor.
