# Промпт для создания Cursor Rule: User Rule

**User Rule** — личное правило, которое действует во всех ваших проектах. Оно хранится не в файлах проекта, а в настройках Cursor: **Customize → Rules**. Поэтому промпт просит агента подготовить текст правила, а в настройки его добавляете вы. Хороший промпт описывает ваши предпочтения по общению и общие привычки в работе и отделяет их от требований отдельных проектов.

User Rule подходит для стиля общения и общих соглашений, которые нужны вам в любом проекте. В остальных случаях выберите другой тип:

- требование относится к одному проекту — Project Rule подходящего типа (как выбрать тип, описано в [`docs/cursor-rules.md`](../docs/cursor-rules.md)) или [`AGENTS.md`](create-rule-agents-md.md);
- требование должно действовать для всей команды — [Team Rule](create-rule-team.md).

Требования и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/rules#user-rules). Шаблон — [`templates/rule/user-rule.md`](../templates/rule/user-rule.md), простая инструкция — [`docs/cursor-rules.md`](../docs/cursor-rules.md).

## Требования Cursor

- User Rules — глобальные предпочтения. Их задают в **Customize → Rules**, и они действуют во всех проектах.
- User Rules использует агент в чате (Agent). На автодополнение Cursor Tab и другие AI-функции правила не влияют.
- User Rule пишут обычным текстом, как в примере из документации: «Please reply in a concise style. Avoid unnecessary repetition or filler language».
- User Rules подходят для стиля общения и общих соглашений по коду.
- Правила применяются в порядке Team Rules → Project Rules → User Rules. При противоречии главнее более ранний источник, поэтому личное правило не отменяет правила команды и проекта.

## Структура запроса

```text
Цель:
Что вас не устраивает в ответах или действиях агента во всех проектах?

Общение:
На каком языке и в каком стиле агент должен отвечать?

Работа:
Какие общие привычки нужны в любом проекте?
Что агент должен делать только после вашего подтверждения?

Не входит в правило:
Что относится к отдельным проектам и должно остаться в Project Rule или AGENTS.md?

Проверка:
По каким запросам в новом чате будет видно, что правило работает?
```

## Шаблон промпта

```text
Подготовь текст User Rule для Cursor.

Цель:


Предпочтения по общению:


Предпочтения по работе:


Не входит в правило:


Сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Rules, раздел User Rules:
   https://cursor.com/docs/rules#user-rules
2. Прочитай шаблон `templates/rule/user-rule.md`. Если шаблона в проекте
   нет, используй формат из официальной документации.
3. Проверь, что каждое пожелание подходит для любых проектов. Требования
   одного проекта не включай в текст: предложи оформить их как Project Rule
   или AGENTS.md и объясни причину.
4. Перечисли предположения и задай уточняющие вопросы.
5. Подготовь текст правила: короткий, конкретный, без повторов
   и противоречий, без frontmatter.
6. Не создавай и не изменяй файлы: User Rule хранится в настройках Cursor.
   Выведи готовый текст в чат одним блоком, чтобы его можно было
   скопировать целиком.
7. Напомни, как добавить правило: Customize → Rules.
8. Не утверждай, что правило добавлено или работает: добавить и проверить
   его может только пользователь. Предоставь ручной чек-лист проверки.
```

## Пример

```text
Подготовь текст User Rule для Cursor.

Цель:
Агент отвечает слишком длинно и на английском языке, а объяснения
перегружены терминами.

Предпочтения по общению:
- отвечать на русском языке;
- сначала давать вывод, затем подробности;
- обходиться без вводных фраз и повторов;
- термины пояснять простыми словами.

Предпочтения по работе:
- перед большими изменениями показывать план и ждать подтверждения;
- не удалять файлы без подтверждения;
- в конце работы кратко перечислять, что изменено и что не проверено.

Не входит в правило:
- всё, что относится к одному проекту: технологии, пути, команды запуска.

Сценарии проверки:
- на вопрос «Что делает эта функция?» агент отвечает по-русски, начиная
  с вывода;
- на просьбу «Перепиши модуль оплаты» агент сначала показывает план.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Подготовь текст правила и выведи его в чат одним блоком.
Файлы не создавай и не изменяй.
```

## Проверка готового правила

1. Открыть **Customize → Rules** и добавить подготовленный текст в User Rules.
2. Открыть новый чат и выполнить сценарии проверки: агент должен следовать предпочтениям без напоминаний.
3. Повторить проверку в другом проекте: User Rule действует во всех проектах.
4. Убедиться, что в тексте нет требований отдельных проектов.
5. Если агент не следует правилу, проверить, не противоречит ли оно правилам проекта или команды: при противоречии главнее они.
