# Промпт для создания Cursor Subagent: Cloud subagent

**Cloud subagent** — субагент, который выполняет задачу в облаке: на отдельной виртуальной машине и в отдельной ветке, пока вы продолжаете работать на своём компьютере. Это не файл проекта: его запускают в приложении Cursor, в окне Agents Window, командой `/in-cloud`. Поэтому промпт просит агента подготовить текст задачи, а запускаете её вы. Хороший промпт даёт задачу, которую можно выполнить без уточняющих вопросов: цель, контекст, ограничения и способ проверки.

Тип подходит для долгой или параллельной работы, которую удобно выполнять отдельно от вашего компьютера: починить сборку, разобраться в проблеме, изучить код. В остальных случаях выберите другой тип:

- помощник нужен постоянно и работает на вашем компьютере — [Project subagent](create-subagent-project.md) или [User subagent](create-subagent-user.md);
- помощник должен только проверять и ничего не изменять — [Read-only subagent](create-subagent-readonly.md);
- долгая работа должна идти в фоне на вашем компьютере — [Background subagent](create-subagent-background.md).

Требования и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/subagents#cloud-subagents). Шаблон задачи — [`templates/subagent/cloud-subagent.md`](../templates/subagent/cloud-subagent.md), простая инструкция — [`docs/cursor-subagents.md`](../docs/cursor-subagents.md).

## Требования Cursor

- Cloud subagent запускают из окна Agents Window в приложении Cursor.
- После команды `/in-cloud` следующая отправленная задача выполняется как Cloud subagent: для неё создаются отдельная виртуальная машина и отдельная ветка.
- Команда `/autopilot` поручает Cloud subagent уже открытый pull request: субагент дорабатывает его в облаке и готовит к слиянию.
- Cloud subagent использует облачное окружение, настроенное для репозитория, и подчиняется тем же правилам о моделях и возможностях, что и остальные облачные агенты (Cloud Agents).
- MCP-серверы Cloud subagent берёт из настроек команды на [cursor.com/agents](https://cursor.com/agents), а не из вашей локальной сессии.
- Облачные агенты клонируют репозиторий из GitHub, GitLab, Azure DevOps или Bitbucket и работают в отдельной ветке. Изменения, которые не отправлены в удалённый репозиторий, им недоступны.
- Для запуска нужны репозиторий, подключённый к Cursor, и тариф, в который входят облачные агенты. Подробнее — [Cloud Agents](https://cursor.com/docs/cloud-agent).
- Субагент начинает работу с чистым контекстом, поэтому всё необходимое должно быть в тексте задачи.

## Структура запроса

```text
Цель:
Какой результат должен получиться?

Контекст:
Где искать? Что уже известно? Какие файлы, ветка или pull request
относятся к задаче?

Что сделать:
Какие шаги обязательны?

Ограничения:
Что нельзя менять и чего нельзя делать?

Как проверить:
По каким признакам понятно, что задача выполнена?

Результат:
В каком виде нужен итог: ветка, pull request, отчёт?
```

## Шаблон промпта

```text
Подготовь задачу для Cloud subagent.

Цель:


Контекст:


Что сделать:


Ограничения:


Как проверить:


Результат:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Subagents, раздел
   Cloud subagents:
   https://cursor.com/docs/subagents#cloud-subagents
2. Прочитай шаблон `templates/subagent/cloud-subagent.md`. Если шаблона
   в проекте нет, составь задачу из разделов: цель, контекст, шаги,
   ограничения, проверка, результат.
3. Проверь, что задаче действительно нужен Cloud subagent: работа долгая
   или параллельная и не зависит от изменений, которых нет в удалённом
   репозитории. Если задача короткая, предложи выполнить её локально
   и объясни причину.
4. Изучи репозиторий: найди файлы, команды и ветки, которые относятся
   к задаче. Перечисли найденные факты, неизвестные детали и необходимые
   уточнения. Команды и пути бери из репозитория, а не придумывай.
5. Подготовь текст задачи по шаблону: понятный без истории переписки,
   с конкретными файлами, командами и признаками готовности, без секретов.
6. Не запускай субагента и не изменяй файлы. Выведи готовый текст в чат
   одним блоком, чтобы его можно было скопировать целиком.
7. Перечисли, что нужно сделать до запуска: какие локальные изменения
   отправить в удалённый репозиторий.
8. Напомни, как запустить задачу: Agents Window → `/in-cloud` → отправить
   текст задачи.
9. Не утверждай, что задача запущена или выполнена: запустить и проверить
   её может только пользователь. Предоставь ручной чек-лист проверки.
```

## Пример

```text
Подготовь задачу для Cloud subagent.

Цель:
В Laravel-приложении бронирований тест оплаты время от времени падает.
Нужно найти причину и исправить её, не отвлекаясь от текущей работы.

Контекст:
- тест лежит в `tests/Feature/PaymentTest.php`;
- сбой происходит примерно в одном запуске из пяти;
- в последний раз тест падал в ветке `main`.

Что сделать:
- воспроизвести сбой;
- найти причину;
- внести минимальное исправление.

Ограничения:
- не изменять публичные методы сервисов в `app/Services`;
- не отключать и не удалять тесты.

Как проверить:
- тест проходит двадцать запусков подряд;
- остальные тесты PHPUnit проходят.

Результат:
Отдельная ветка с исправлением и краткий отчёт: в чём была причина
и что изменено.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Подготовь текст задачи и выведи его в чат одним блоком.
Субагента не запускай, файлы не создавай и не изменяй.
```

## Проверка готовой задачи

1. Убедиться, что задача понятна без истории переписки: в ней названы файлы, команды и признаки готовности.
2. Отправить в удалённый репозиторий изменения, которые нужны для задачи.
3. В приложении Cursor открыть Agents Window, набрать `/in-cloud` и отправить текст задачи.
4. Дождаться результата: субагент работает в отдельной ветке и не изменяет файлы на вашем компьютере.
5. Проверить результат по признакам готовности из задачи.
6. Если субагент не запускается, проверить, что репозиторий подключён к Cursor, а облачные агенты входят в тариф: [Cloud Agents](https://cursor.com/docs/cloud-agent).
