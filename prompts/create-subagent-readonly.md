# Промпт для создания Cursor Subagent: Read-only subagent

**Read-only subagent** — субагент только для чтения: он изучает проект и сообщает о находках, но не изменяет файлы и не выполняет команды, которые меняют состояние. Ограничение включает настройка `readonly: true` в файле субагента. Хороший промпт на его создание определяет, что субагент проверяет, по каким признакам оценивает находки и в каком виде возвращает отчёт.

Тип подходит для ревью, аудита и поиска — задач, результат которых — отчёт, а не изменения. В остальных случаях выберите другой тип:

- помощник должен исправлять код или запускать команды, которые записывают файлы, — [Project subagent](create-subagent-project.md);
- помощник с обычными правами нужен лично вам во всех проектах — [User subagent](create-subagent-user.md);
- работа долгая, и основной агент не должен её ждать — [Background subagent](create-subagent-background.md);
- задачу нужно выполнить в облаке, не занимая ваш компьютер, — [Cloud subagent](create-subagent-cloud.md);
- задача простая и выполняется за один шаг — вместо субагента создайте [Cursor Skill](create-skill.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/subagents#configuration-fields). Шаблон субагента — [`templates/subagent/readonly-subagent.md`](../templates/subagent/readonly-subagent.md), простая инструкция — [`docs/cursor-subagents.md`](../docs/cursor-subagents.md).

## Требования Cursor

- Субагент — файл Markdown в папке `.cursor/agents/` проекта (субагент для проекта) или в `~/.cursor/agents/` (личный субагент для всех проектов).
- Файл состоит из блока настроек (YAML frontmatter) и текста задания под ним.
- Тип задаёт строка `readonly: true`: субагент работает с ограниченными правами на запись — не изменяет файлы и не выполняет команды, меняющие состояние. По умолчанию `readonly` равно `false`.
- Строка должна выглядеть в точности как `readonly: true` — без кавычек и без пояснения после значения. Иначе ограничение не включится, а сообщения об ошибке не будет.
- Остальные поля: `name` — имя из строчных латинских букв и дефисов; по умолчанию оно берётся из имени файла; `description`; `model` (по умолчанию `inherit`); `is_background` (по умолчанию `false`).
- Основной агент читает `description` и по нему решает, передавать ли задачу. Описание должно быть конкретным; слова «используй проактивно» или «всегда используй для…» поощряют автоматическую передачу.
- Субагент начинает работу с чистым контекстом и не видит историю переписки: всё необходимое он получает из своего задания и из запроса основного агента.
- У субагента должна быть одна чёткая зона ответственности, а задание должно быть коротким и конкретным. Для простой задачи, которая выполняется за один шаг, вместо субагента используют skill.
- Субагент возвращает основному агенту только итоговое сообщение, поэтому в задании описывают состав отчёта: что найдено, где и что с этим делать.

## Структура запроса

```text
Цель:
Что субагент должен проверять или искать и зачем?

Когда вызывать:
При каких задачах и запросах агент должен передавать работу субагенту?

Когда не вызывать:
Какие похожие задачи субагенту не передаются?

Что проверять:
Какие части проекта изучать? По каким признакам искать проблемы?

Отчёт:
Как делить находки по важности? Что указывать для каждой находки?

Настройки:
Где хранить субагента: в проекте или у пользователя?
Нужна ли другая модель? Ждать результат или работать в фоне?

Не входит в задачу субагента:
Кто исправляет найденное? Какие проверки выполняют другие инструменты?

Проверка:
По каким запросам субагент должен вызываться, а по каким — нет?
```

## Шаблон промпта

```text
Создай Cursor Subagent типа Read-only subagent.

Цель:


Когда вызывать субагента:


Когда не вызывать:


Что субагент проверяет:


Что субагент должен вернуть:


Настройки:
Права: только чтение (`readonly: true`) — не изменять.
Расположение: проект (`.cursor/agents/`) / пользователь (`~/.cursor/agents/`).
Модель: та же, что у основного агента / другая (какая).
Режим: Foreground (агент ждёт результат) / Background (работа в фоне).


Не входит в задачу субагента:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Subagents:
   https://cursor.com/docs/subagents
2. Прочитай шаблон `templates/subagent/readonly-subagent.md`, существующих
   субагентов в `.cursor/agents/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат из официальной
   документации.
3. Проверь, что задаче действительно нужен Read-only subagent. Если субагент
   должен исправлять код или запускать команды, которые записывают файлы,
   предложи Project subagent. Если задача простая и выполняется за один шаг,
   предложи skill. Объясни причину и не создавай субагента без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Пути и названия бери из репозитория, а не придумывай.
5. Предложи:
   - имя субагента: строчные латинские буквы и дефисы;
   - значение `description`: одной строкой, что проверяет субагент и когда
     передавать ему задачу;
   - расположение файла и значения `model` и `is_background`;
   - полный текст задания: что изучить, что проверить и каким должен быть
     отчёт;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл `.cursor/agents/<имя>.md` или
   `~/.cursor/agents/<имя>.md` по шаблону. Значение `name` должно совпадать
   с именем файла. Строку `readonly: true` запиши в точности так. Каждую
   настройку запиши в одну строку, без кавычек и без пояснений после
   значения; в `description` не используй двоеточия и символ `#`.
8. Проверь расположение и расширение файла, блок настроек, отсутствие
   субагента с таким же именем, существование упомянутых путей, отсутствие
   секретов. Убедись, что задание не требует изменять файлы и запускать
   команды, которые что-либо записывают, что `description` отличает
   позитивные сценарии от негативных, а задание понятно без истории
   переписки.
9. Не утверждай, что субагент проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Subagent типа Read-only subagent.

Цель:
Перед выкладкой изменений в Laravel-приложении бронирований нужна
независимая проверка безопасности. Проверяющий не должен ничего изменять:
решение об исправлениях принимает разработчик.

Когда вызывать субагента:
- изменения в авторизации, оплате и обработке персональных данных;
- «Проверь безопасность модуля оплаты»;
- перед выкладкой изменений.

Когда не вызывать:
- проверка оформления кода;
- задачи, в которых нужно исправить код.

Что субагент проверяет:
1. Код входа в систему, оплаты и работы с данными клиентов.
2. Типовые уязвимости: инъекции, XSS, обход авторизации.
3. Проверку прав доступа в policy-классах.
4. Отсутствие паролей, токенов и ключей доступа в коде.
5. Проверку и очистку входных данных.

Что субагент должен вернуть:
Находки по важности: критические (исправить до выкладки), высокие (исправить
в ближайшее время), средние (исправить по возможности). Для каждой находки —
файл, строка и способ исправления.

Настройки:
Права: только чтение.
Расположение: проект, чтобы субагент был у всей команды.
Модель — та же, что у основного агента.
Режим Foreground: основной агент ждёт отчёт.

Не входит в задачу субагента:
- исправление найденных проблем;
- запуск тестов и проверка оформления кода.

Позитивные сценарии проверки:
- на запрос «/security-auditor проверь модуль оплаты» субагент возвращает
  список находок по важности и не изменяет файлы;
- после изменений в авторизации основной агент сам передаёт проверку
  субагенту.

Негативные сценарии проверки:
- на просьбу «Переименуй переменную в контроллере» субагент не вызывается;
- просьбу «Исправь найденную уязвимость» выполняет основной агент:
  субагент файлы не изменяет.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи имя, description, настройки и текст задания.
До моего подтверждения не изменяй файлы.
```

## Проверка готового субагента

1. Убедиться, что файл лежит в `.cursor/agents/` или `~/.cursor/agents/`, имеет расширение `.md`, а его имя совпадает со значением `name`.
2. Убедиться, что в блоке настроек есть строка `readonly: true` — без кавычек и без пояснения после значения.
3. Открыть **Customize → Subagents** и убедиться, что субагент есть в списке.
4. В новом чате вызвать субагента явно, например `/security-auditor проверь модуль оплаты`: он должен вернуть отчёт.
5. Проверить ограничение: явно попросить субагента изменить любой файл. Он должен ответить, что работает только на чтение, и не изменить файл сам.
6. Выполнить позитивные и негативные сценарии: основной агент должен передавать субагенту только подходящие задачи.
7. Если агент не передаёт задачу сам, уточнить `description`: назвать в нём задачи, для которых нужен субагент.
8. Project subagent сохранить в git, чтобы субагента получила вся команда.
