# Промпт для создания Cursor Rule: Apply Manually

Правило типа **Apply Manually** — это Project Rule, которое подключается, только когда его упомянули в чате через `@`, например `@my-rule`. Хороший промпт на его создание объясняет, в каких ситуациях вы будете вызывать правило, как оно должно называться и чем ответ агента с правилом отличается от ответа без него.

Тип подходит, если указания нужны редко и вы хотите сами решать, когда их применять. В остальных случаях выберите другой тип или механизм:

- указание нужно в любой задаче проекта — [Always Apply](create-rule-always-apply.md);
- агент должен сам подключать правило для отдельных видов задач — [Apply Intelligently](create-rule-apply-intelligently.md);
- указание относится к определённым файлам или папкам — [Apply to Specific Files](create-rule-apply-to-specific-files.md);
- нужна многошаговая процедура со скриптами или шаблонами — [Cursor Skill](create-skill.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/rules). Шаблон правила — [`templates/rule/apply-manually.mdc`](../templates/rule/apply-manually.mdc), простая инструкция — [`docs/cursor-rules.md`](../docs/cursor-rules.md).

## Требования Cursor

- Правило — файл с расширением `.mdc` в папке `.cursor/rules/` проекта. Имя файла произвольное; файл `.md` в этой папке игнорируется.
- Файл состоит из блока настроек (frontmatter) и текста правила в формате Markdown.
- Для типа Apply Manually в frontmatter указывают только `alwaysApply: false`. Поля `description` и `globs` не указывают: с ними правило начнёт подключаться само, по описанию или по файлам.
- Правило попадает в контекст, только когда его упомянули в чате через `@`.
- Правило вызывают по имени файла без расширения: файл `plain-language.mdc` — это `@plain-language`. Поэтому имя должно быть коротким и понятным.
- Правило должно быть короче 500 строк, конкретным и посвящённым одной теме. Большое правило делят на несколько.
- На файлы ссылаются упоминанием `@имя-файла` вместо копирования их содержимого. Агент читает такой файл сам, когда он понадобится; в контекст файл автоматически не попадает.
- Не нужно пересказывать руководства по стилю (для этого есть линтер), общеизвестные команды, редкие случаи и код, который уже есть в проекте.

## Структура запроса

```text
Цель:
Какой результат должно давать правило, когда его вызвали?

Когда вызывать:
В каких ситуациях вы будете упоминать правило в чате?

Имя для вызова:
Как правило будет называться в чате после символа @?

Требования:
Что агент должен делать и чего не должен? Формулировки конкретные и проверяемые.

Эталонные файлы:
На какие файлы проекта сослаться как на образец вместо копирования их содержимого?

Не входит в правило:
Что остаётся другим правилам или документации?

Проверка:
Чем ответ агента с упоминанием правила должен отличаться от ответа без него?
```

## Шаблон промпта

```text
Создай Cursor Rule типа Apply Manually.

Цель:


Когда вызывать:


Имя для вызова через @:


Требования, которые должен соблюдать агент:


Эталонные файлы для ссылок через @:


Не входит в правило:


Сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Rules:
   https://cursor.com/docs/rules
2. Прочитай шаблон `templates/rule/apply-manually.mdc`, существующие правила
   в `.cursor/rules/`, `AGENTS.md` и другие инструкции репозитория. Если
   шаблона в проекте нет, используй формат из официальной документации.
3. Проверь, что правилу действительно нужен тип Apply Manually. Если правило
   должно подключаться само или задаче лучше подходит Skill, объясни причину
   и не создавай правило без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
5. Предложи:
   - имя файла в `.cursor/rules/`: короткое, понятное, не совпадающее
     с именами других правил;
   - frontmatter;
   - полный текст правила;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл `.cursor/rules/<имя>.mdc` по шаблону.
   Frontmatter должен содержать только строку `alwaysApply: false`,
   без `description`, `globs` и комментариев.
8. Проверь расширение `.mdc`, frontmatter, длину правила, существование
   упомянутых файлов, отсутствие секретов, повторов и противоречий
   с другими правилами.
9. Не утверждай, что правило проверено в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Rule типа Apply Manually.

Цель:
Иногда мне нужно объяснение кода для коллег без технической подготовки.
Обычно такой стиль не нужен, поэтому правило должно подключаться только
по моему запросу.

Когда вызывать:
Когда нужно простое объяснение, например:
«@plain-language объясни, что делает модуль бронирований».

Имя для вызова через @:
`plain-language`

Требования, которые должен соблюдать агент:
- объяснять без терминов; неизбежный термин пояснять в скобках;
- начинать с одного предложения о назначении кода, затем давать 3–5 пунктов;
- не приводить фрагменты кода, если о них не просили;
- использовать бытовую аналогию, когда она помогает;
- в конце простыми словами перечислить, что может пойти не так.

Эталонные файлы для ссылок через @:
Не нужны.

Не входит в правило:
- изменение кода;
- оформление технической документации.

Сценарии проверки:
- запрос с `@plain-language` даёт объяснение без терминов и фрагментов кода;
- тот же запрос без упоминания даёт обычный технический ответ.

Процесс создания:
Сначала изучи официальную документацию, шаблон и существующие правила.
Предложи имя файла, frontmatter и текст правила.
До моего подтверждения не изменяй файлы.
```

## Проверка готового правила

1. Убедиться, что файл лежит в `.cursor/rules/` и имеет расширение `.mdc`.
2. Открыть **Customize → Rules** и убедиться, что правило есть в списке, а его тип — **Apply Manually**.
3. В новом чате набрать `@` и имя правила: правило должно найтись по имени файла.
4. Выполнить запрос с упоминанием правила: агент должен соблюдать его требования.
5. Выполнить тот же запрос без упоминания: правило не должно применяться.
6. Убедиться, что в frontmatter нет `description` и `globs`: с ними правило начнёт подключаться само.
7. Сохранить файл в git, чтобы правило получила вся команда.
