# Промпт для создания Cursor Hook: App lifecycle hooks

**App lifecycle hooks** — хуки, которые срабатывают не в чате, а при событиях самого приложения. В этой категории одно событие — `workspaceOpen`: Cursor открыл проект или изменился набор его папок. В ответ хук может назвать папки с плагинами, которые Cursor загрузит для открытого проекта. Хороший промпт на создание такого хука называет, что должно происходить при открытии проекта и какие плагины нужно подключить.

Тип подходит, если действие нужно один раз при открытии проекта: подключить плагины, которые лежат в самом проекте или на компьютере. В остальных случаях выберите другой тип:

- хук связан с работой агента в чате, например должен добавлять сведения в каждый новый чат, — [Agent hooks](create-hook-agent.md);
- хук относится к автодополнению Tab — [Tab hooks](create-hook-tab.md);
- плагин нужно установить из маркетплейса, а не подключить из папки — хук не нужен: [`docs/cursor-plugin.md`](../docs/cursor-plugin.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Где хранится хук: [Project hooks](create-hook-project.md), [User hooks](create-hook-user.md), [Team hooks](create-hook-team.md), [Enterprise hooks](create-hook-enterprise.md). Способ выполнения: скрипт — [Command-based hooks](create-hook-command-based.md), условие для AI-модели — [Prompt-based hooks](create-hook-prompt-based.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks#workspaceopen). Шаблон — [`templates/hook/app-lifecycle-hooks.json`](../templates/hook/app-lifecycle-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- Событие `workspaceOpen` срабатывает один раз, когда Cursor открывает проект, и ещё раз при каждом изменении набора папок проекта. Если в окне нет ни одной папки, событие не срабатывает.
- Событие работает в приложении Cursor и в Cursor CLI. В облачных агентах оно не выполняется.
- Событие не связано с чатом, поэтому на вход не приходят сведения о чате и модели. Приходят имя события (`hook_event_name`), версия Cursor (`cursor_version`), папки проекта (`workspace_roots`) и e-mail пользователя (`user_email`).
- Ответ — необязательное поле `pluginPaths`: список абсолютных путей к папкам плагинов, которые Cursor загрузит для открытого проекта.
- Условие `matcher` для этого события не используется.
- Запись хранят в `hooks.json`: в `.cursor/hooks.json` проекта или в `~/.cursor/hooks.json`. Хуки проекта запускаются из корня проекта и только в проекте, которому пользователь доверяет.
- Скрипту доступна переменная окружения `CURSOR_PROJECT_DIR` — корень проекта. По ней удобно строить абсолютный путь к папке внутри проекта.

## Структура запроса

```text
Цель:
Что должно происходить при открытии проекта и зачем?

Плагины:
Какие папки с плагинами нужно подключить? Где они лежат: в проекте или
на компьютере?

Условия:
Подключать всегда или только если папка существует, для определённого
проекта или пользователя?

Где хранится хук:
В проекте или лично у вас?

Не входит в задачу хука:
Что делается вручную или другими средствами?

Проверка:
Что должно быть видно после открытия проекта?
```

## Шаблон промпта

```text
Создай Cursor Hook типа App lifecycle hooks.

Цель:


Плагины, которые нужно подключить:


Условия:
Всегда / только если (условие).


Где хранится хук:
В проекте (Project hooks) / лично у меня (User hooks).


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks, раздел
   workspaceOpen:
   https://cursor.com/docs/hooks#workspaceopen
2. Прочитай шаблон `templates/hook/app-lifecycle-hooks.json`, его копию
   с пояснениями `templates/hook/app-lifecycle-hooks.annotated.jsonc`,
   скрипт `templates/hook/hooks/workspace-open-hook.sh`, существующие
   `.cursor/hooks.json` и `.cursor/hooks/`, `AGENTS.md`, правила и другие
   инструкции репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен хук открытия проекта. Если
   действие нужно в начале каждого чата, предложи Agent hooks: событие
   `sessionStart`. Объясни причину и не создавай хук без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Пути к папкам плагинов бери из репозитория, а не придумывай. Убедись,
   что папки существуют и содержат плагины. Проверь, что программы,
   которые нужны скрипту (например, `jq`), установлены.
5. Предложи:
   - как скрипт строит абсолютные пути к папкам плагинов;
   - что отвечает скрипт, если папки нет: пустой список `pluginPaths`;
   - полный текст записи для `hooks.json` и текст скрипта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись `workspaceOpen` в `hooks.json`
   выбранного уровня и создай скрипт в папке `hooks` рядом с ним. Сохрани
   существующие хуки. Файл — обычный JSON без комментариев, со строкой
   `"version": 1`; в значениях не используй две косые черты подряд. Путь
   к скрипту запиши от папки, из которой он запускается: для хуков
   проекта — от корня проекта. Сделай скрипт исполняемым. Скрипт печатает
   в stdout один JSON-объект и больше ничего; пути в `pluginPaths` —
   только абсолютные.
8. Проверь, что `hooks.json` — корректный JSON. Запусти скрипт с примером
   входных данных и убедись, что он отвечает JSON-объектом со списком
   `pluginPaths`: с путём, когда папка есть, и пустым, когда её нет.
   Убедись, что скрипт не делает ничего сверх описанного и не содержит
   секретов.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа App lifecycle hooks.

Цель:
В репозитории Laravel-приложения бронирований в папке
`tools/booking-plugin` лежит плагин команды с правилами и навыками. Нужно,
чтобы Cursor подключал его сам, когда кто-то открывает проект.

Плагины, которые нужно подключить:
Папка `tools/booking-plugin` в корне проекта.

Условия:
Только если папка существует.

Где хранится хук:
В проекте.

Не входит в задачу хука:
- установка плагинов из маркетплейса;
- изменение самого плагина.

Позитивные сценарии проверки:
- после открытия проекта плагин из `tools/booking-plugin` загружен.

Негативные сценарии проверки:
- если папки `tools/booking-plugin` нет, хук возвращает пустой список,
  и проект открывается без ошибок.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что запись `workspaceOpen` добавлена в `hooks.json`, а скрипт лежит по указанному в ней пути и является исполняемым.
2. Запустить скрипт вручную из корня проекта, например `echo '{}' | CURSOR_PROJECT_DIR="$PWD" .cursor/hooks/имя.sh`: он должен напечатать JSON-объект со списком `pluginPaths` из абсолютных путей.
3. Закрыть и снова открыть проект в Cursor.
4. Открыть **Customize** и убедиться, что хук есть на вкладке **Hooks**, а возможности плагина появились в списках.
5. Открыть панель **Output**, выбрать канал **Hooks** и убедиться, что хук запускался без ошибок.
6. Проверить негативный сценарий: проект открывается без ошибок, даже если папки плагина нет.
