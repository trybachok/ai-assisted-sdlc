# Промпт для создания Cursor Rule: Always Apply

Правило типа **Always Apply** — это Project Rule, текст которого Cursor добавляет в контекст агента в каждом чате проекта. Хороший промпт на его создание объясняет, какое поведение агента нужно закрепить, почему правило нужно всегда и как проверить результат.

Тип подходит, если указание короткое и нужно агенту в любой задаче проекта. В остальных случаях выберите другой тип:

- указание нужно только для отдельных видов задач — [Apply Intelligently](create-rule-apply-intelligently.md);
- указание относится к определённым файлам или папкам — [Apply to Specific Files](create-rule-apply-to-specific-files.md);
- указание нужно редко и только по вашему запросу — [Apply Manually](create-rule-apply-manually.md);
- проекту достаточно простой памятки без настроек — [`AGENTS.md`](create-rule-agents-md.md);
- пожелание личное или общее для всей команды — [User Rule](create-rule-user.md) или [Team Rule](create-rule-team.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/rules). Шаблон правила — [`templates/rule/always-apply.mdc`](../templates/rule/always-apply.mdc), простая инструкция — [`docs/cursor-rules.md`](../docs/cursor-rules.md).

## Требования Cursor

- Правило — файл с расширением `.mdc` в папке `.cursor/rules/` проекта. Имя файла произвольное; файл `.md` в этой папке игнорируется.
- Файл состоит из блока настроек (frontmatter) и текста правила в формате Markdown.
- Для типа Always Apply в frontmatter указывают `alwaysApply: true`. Поля `description` и `globs` при этом игнорируются.
- Текст правила включается в начало контекста модели в каждом чате, поэтому в нём оставляют только то, что нужно всегда.
- Правило должно быть короче 500 строк, конкретным и посвящённым одной теме. Большое правило делят на несколько.
- На файлы ссылаются упоминанием `@имя-файла` вместо копирования их содержимого. Агент читает такой файл сам, когда он понадобится; в контекст файл автоматически не попадает. Всё, что должно быть в контексте всегда, пишут прямо в тексте правила.
- Не нужно пересказывать руководства по стилю (для этого есть линтер), общеизвестные команды, редкие случаи и код, который уже есть в проекте.

## Структура запроса

```text
Цель:
Какую повторяющуюся ошибку агента исправляет правило или какое поведение закрепляет?

Почему всегда:
Почему правило нужно в каждом чате, а не только для отдельных задач или файлов?

Требования:
Что агент должен делать и чего не должен? Формулировки конкретные и проверяемые.

Эталонные файлы:
На какие файлы проекта сослаться как на образец вместо копирования их содержимого?

Не входит в правило:
Что остаётся линтеру, другим правилам или документации?

Проверка:
По каким запросам в новом чате будет видно, что правило работает?
```

## Шаблон промпта

```text
Создай Cursor Rule типа Always Apply.

Цель:


Почему правило нужно в каждом чате:


Требования, которые должен соблюдать агент:


Эталонные файлы для ссылок через @:


Не входит в правило:


Сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Rules:
   https://cursor.com/docs/rules
2. Прочитай шаблон `templates/rule/always-apply.mdc`, существующие правила
   в `.cursor/rules/`, `AGENTS.md` и другие инструкции репозитория. Если
   шаблона в проекте нет, используй формат из официальной документации.
3. Проверь, что правилу действительно нужен тип Always Apply. Если указания
   относятся только к части задач или файлов, предложи другой тип правила,
   объясни причину и не создавай правило без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
5. Предложи:
   - имя файла в `.cursor/rules/`;
   - frontmatter;
   - полный текст правила;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл `.cursor/rules/<имя>.mdc` по шаблону.
   Frontmatter должен содержать только строку `alwaysApply: true`,
   без комментариев.
8. Проверь расширение `.mdc`, frontmatter, длину правила, существование
   упомянутых файлов, отсутствие секретов, повторов и противоречий
   с другими правилами.
9. Не утверждай, что правило проверено в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Rule типа Always Apply.

Цель:
Агент время от времени добавляет новые зависимости и правит сгенерированные
файлы. Нужно закрепить базовые ограничения проекта.

Почему правило нужно в каждом чате:
Ограничения относятся к любой задаче и к любым файлам проекта.

Требования, которые должен соблюдать агент:
- не добавлять зависимости в `composer.json` без моего подтверждения;
- не изменять файлы в папках `vendor/` и `public/build/`;
- если детали реализации неясны, сначала прочитать связанные исходные файлы;
- после изменения PHP-кода запускать релевантные тесты PHPUnit и Laravel Pint.

Эталонные файлы для ссылок через @:
Не нужны.

Не входит в правило:
- оформление кода: его проверяет Laravel Pint;
- требования к миграциям и тестам: для них будут отдельные правила.

Сценарии проверки:
- на просьбу «Добавь экспорт бронирований в Excel» агент не устанавливает
  пакет без подтверждения;
- на просьбу «Исправь ошибку в собранном JS» агент не правит файлы
  в `public/build/`.

Процесс создания:
Сначала изучи официальную документацию, шаблон и существующие правила.
Предложи имя файла, frontmatter и текст правила.
До моего подтверждения не изменяй файлы.
```

## Проверка готового правила

1. Убедиться, что файл лежит в `.cursor/rules/` и имеет расширение `.mdc`.
2. Открыть **Customize → Rules** и убедиться, что правило есть в списке, а его тип — **Always Apply**.
3. Открыть новый чат и выполнить сценарии проверки: агент должен соблюдать правило без напоминаний.
4. Убедиться, что правило не повторяет другие правила и `AGENTS.md` и не противоречит им.
5. Перечитать правило: всё ли в нём нужно в каждом чате. Лишнее вынести в правила других типов.
6. Сохранить файл в git, чтобы правило получила вся команда.
