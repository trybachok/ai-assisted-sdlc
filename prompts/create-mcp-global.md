# Промпт для создания конфигурации Cursor MCP: Global Configuration

**Global Configuration** — личные MCP-серверы: файл `~/.cursor/mcp.json` в домашней папке пользователя, серверы из которого доступны во всех проектах, открытых на этом компьютере. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт на создание конфигурации называет серверы, их источник, способ подключения, ключи доступа и права, которые получат серверы.

Тип подходит, если серверы нужны лично вам и не зависят от конкретного проекта: заметки, документация, личные инструменты. В остальных случаях выберите другой тип:

- сервер относится к одному проекту и нужен всем, кто с ним работает, — [Project Configuration](create-mcp-project.md);
- сервер нужен всей команде во всех её проектах или облачным агентам — [Team MCP server](create-mcp-team.md);
- нужен не внешний сервис, а указание для агента — вместо MCP создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У подключения есть ещё одно свойство — способ связи с сервером, и для каждого — свой промпт: локальная программа — [stdio server](create-mcp-stdio.md), удалённый сервер — [Streamable HTTP server](create-mcp-streamable-http.md) или [SSE server](create-mcp-sse.md), удалённый сервер с заранее выданным Client ID — [Remote server with Static OAuth](create-mcp-static-oauth.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#configuration-locations). Шаблон — [`templates/mcp/global-mcp.json`](../templates/mcp/global-mcp.json), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Личную конфигурацию хранят в файле `~/.cursor/mcp.json` — в папке `.cursor` домашней папки пользователя. Серверы из неё доступны во всех проектах.
- Файл содержит список `mcpServers`: имя сервера → настройки сервера. Серверов может быть несколько: локальный сервер записывают настройкой `command`, удалённый — настройкой `url`.
- Cursor объединяет личные серверы и серверы проекта из `.cursor/mcp.json`. Если имя сервера совпадает, действует запись проекта.
- В значениях работают подстановки: `${userHome}` — домашняя папка пользователя, `${env:ИМЯ}` — переменная окружения системы.
- Файл хранится только на компьютере пользователя: в git он не попадает, и другие участники команды эти серверы не получают. Ключи доступа всё равно передают через переменные окружения, а не записывают в файл.
- После изменения файла его сохраняют и перезапускают Cursor. Серверы включают и выключают в разделе **Customize → MCPs**.
- Для облачных агентов серверы настраивают отдельно: на странице cursor.com/agents или в дашборде команды.
- По умолчанию Cursor спрашивает разрешение перед вызовом инструмента MCP.
- MCP-сервер обращается к внешним сервисам и выполняет действия от имени пользователя. Документация советует подключать серверы только из проверенных источников и выдавать ключи с наименьшими правами.

## Структура запроса

```text
Цель:
Какие сервисы или данные нужны агенту во всех ваших проектах и зачем?

Серверы:
Какие MCP-серверы подключить? Где их официальная документация или
исходный код?

Способ подключения:
Для каждого сервера: команда запуска или адрес?

Ключи и настройки:
Какие ключи доступа нужны серверам? Где они хранятся?

Права серверов:
Что серверам разрешено: только читать данные или также изменять их?

Не входит в задачу:
Чего серверы делать не должны? Какие серверы относятся к отдельным
проектам?

Проверка:
Какие запросы к агенту покажут, что серверы работают?
```

## Шаблон промпта

```text
Создай конфигурацию Cursor MCP типа Global Configuration.

Цель:


Серверы и их официальная документация:


Способ подключения каждого сервера:
Команда запуска (stdio server) / адрес (Streamable HTTP server или
SSE server) / адрес и Client ID (Remote server with Static OAuth).


Ключи доступа и настройки:
Нет / вход через OAuth / переменные окружения (какие).


Права серверов:
Только чтение / чтение и изменение (чего именно).


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP:
   https://cursor.com/docs/mcp
2. Прочитай шаблон `templates/mcp/global-mcp.json`, его копию
   с пояснениями `templates/mcp/global-mcp.annotated.jsonc`
   и существующий `~/.cursor/mcp.json`. Если шаблона в проекте нет,
   используй формат из официальной документации.
3. Проверь, что серверы действительно нужны пользователю во всех
   проектах. Если сервер относится к одному проекту, предложи Project
   Configuration. Если сервер нужен всей команде, предложи Team MCP
   server. Объясни причину и не создавай конфигурацию без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Имена пакетов, команды запуска и адреса серверов бери из официальной
   документации серверов, а не придумывай. Проверь, что программы,
   которые нужны серверам, установлены.
5. Предложи:
   - имена серверов и способ подключения каждого;
   - способ входа и, если нужны ключи, переменные окружения для них;
   - полный текст записи для `~/.cursor/mcp.json`;
   - что каждый сервер сможет читать и изменять;
   - сценарии проверки.
6. До подтверждения не изменяй файлы, не устанавливай пакеты
   и не запускай серверы. Файл `~/.cursor/mcp.json` находится вне
   проекта: изменяй его только с явного разрешения пользователя.
7. После подтверждения создай или дополни `~/.cursor/mcp.json`. Если файл
   уже есть, сохрани в нём существующие серверы. Файл — обычный JSON без
   комментариев. `args` — список строк, значения `env` и `headers` —
   строки. Пути записывай через `${userHome}`, а не от корня проекта.
   Ключи доступа и пароли в файл не записывай: используй подстановку
   `${env:ИМЯ}`.
8. Проверь, что `~/.cursor/mcp.json` — корректный JSON, что у каждого
   сервера есть `command` или `url`, что в файле нет секретов и что
   имена серверов не совпадают с именами в `.cursor/mcp.json` проектов
   пользователя, если это известно.
9. Не утверждай, что серверы подключены и работают в Cursor, если
   проверка фактически не выполнялась. В таком случае предоставь ручной
   чек-лист проверки.
```

## Пример

```text
Создай конфигурацию Cursor MCP типа Global Configuration.

Цель:
Свои рабочие заметки и решения по разным проектам я веду в Notion. Нужно,
чтобы агент в любом проекте мог найти заметку и свериться с ней, например
с решениями по Laravel-приложению бронирований.

Серверы и их официальная документация:
Официальный удалённый MCP-сервер Notion. Адрес возьми из его официальной
документации.

Способ подключения каждого сервера:
Адрес.

Ключи доступа и настройки:
Вход через OAuth. Ключей доступа нет.

Права серверов:
Только чтение моих заметок.

Не входит в задачу:
- создание и изменение страниц в Notion;
- подключение сервера другим участникам команды.

Позитивные сценарии проверки:
- на запрос «Найди в заметках решение о сроках отмены брони» агент
  вызывает инструмент сервера и пересказывает заметку;
- сервер доступен в двух разных проектах.

Негативные сценарии проверки:
- в `~/.cursor/mcp.json` нет ключей доступа;
- просьбу изменить страницу сервер не выполняет.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Предложи имя сервера и полный текст записи.
До моего подтверждения не изменяй файлы.
```

## Проверка готовой конфигурации

1. Убедиться, что файл называется `mcp.json`, лежит в папке `.cursor` домашней папки пользователя и в нём нет ключей доступа и паролей.
2. Перезапустить Cursor, открыть **Customize → MCPs** и убедиться, что серверы есть в списке и включены. Если сервер требует входа, войти в сервис там же.
3. Выполнить позитивные сценарии в двух разных проектах: агент должен вызвать инструмент сервера. По умолчанию Cursor спросит разрешение на вызов.
4. Выполнить негативные сценарии: серверы не должны делать того, что не входит в задачу.
5. Открыть панель **Output**, выбрать в списке **MCP Logs** и убедиться, что серверы подключились без ошибок.
6. Если сервер не работает в одном из проектов, проверить, нет ли в `.cursor/mcp.json` этого проекта сервера с тем же именем: действует запись проекта.
