# Промпт для создания Cursor Hook: User hooks

**User hooks** — личные хуки: файл `~/.cursor/hooks.json` и скрипты в папке `~/.cursor/hooks/` в домашней папке пользователя. Они действуют во всех проектах, которые вы открываете на этом компьютере, и не попадают в git. Хук — действие, которое Cursor выполняет сам в определённый момент: перед командой в терминале, после правки файла, при отправке запроса. Хороший промпт на его создание называет событие, условие запуска, действие хука и не содержит требований отдельного проекта.

Тип подходит для личных привычек и личной защиты, которые нужны вам в любом проекте. В остальных случаях выберите другой тип:

- хук опирается на команды и файлы одного проекта или нужен всей команде проекта — [Project hooks](create-hook-project.md);
- хук нужен всей команде во всех её проектах — [Team hooks](create-hook-team.md);
- хук нужен на всех компьютерах организации — [Enterprise hooks](create-hook-enterprise.md);
- нужно не автоматическое действие, а личное пожелание к агенту — вместо хука создайте [User Rule](create-rule-user.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Способ выполнения: скрипт — [Command-based hooks](create-hook-command-based.md), условие для AI-модели — [Prompt-based hooks](create-hook-prompt-based.md). Событие: [Agent hooks](create-hook-agent.md), [Tab hooks](create-hook-tab.md), [App lifecycle hooks](create-hook-app-lifecycle.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks). Шаблон — [`templates/hook/user-hooks.json`](../templates/hook/user-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- Личные хуки описывают в файле `~/.cursor/hooks.json`. Скрипты хранят рядом, в папке `~/.cursor/hooks/`.
- Файл содержит строку `"version": 1` и список `hooks`: имя события → хуки. Формат такой же, как у хуков проекта.
- Личные хуки запускаются из папки `~/.cursor/`, поэтому путь к скрипту пишут от неё: `./hooks/имя.sh`.
- Скрипт получает сведения о событии в формате JSON через stdin и печатает ответ в формате JSON в stdout. Код выхода `0` — использовать ответ, `2` — запретить действие, любой другой — хук не сработал, и действие выполняется.
- Личные хуки действуют во всех проектах пользователя на этом компьютере.
- Облачные агенты личные хуки не выполняют: у них нет доступа к домашней папке пользователя.
- Cursor выполняет все подходящие хуки всех уровней: Enterprise, Team, Project и User. Если ответы разные, запрет главнее вопроса, а вопрос главнее разрешения. Поэтому личный хук не может отменить запрет хука проекта, команды или организации.
- Cursor следит за файлом `hooks.json` и перечитывает его после сохранения. Если хуки не загрузились, Cursor перезапускают.

## Структура запроса

```text
Цель:
Что должно происходить автоматически во всех ваших проектах и зачем?

Событие:
В какой момент срабатывает хук: перед командой в терминале, после правки
файла, при отправке запроса, в начале нового чата?

Условие запуска:
Хук срабатывает всегда или только для определённых команд, инструментов,
файлов?

Действие хука:
Что делает хук: наблюдает, запрещает, спрашивает пользователя, изменяет
действие, добавляет сведения в чат?

Сообщения:
Что вы увидите и что узнает агент, если действие запрещено?

Если хук не сработал:
Выполнить действие или запретить его?

Способ выполнения:
Скрипт или условие обычными словами, которое проверяет AI-модель?

Не входит в задачу хука:
Что относится к отдельным проектам и оформляется как Project hooks?

Проверка:
В каких случаях хук должен сработать, а в каких — нет?
```

## Шаблон промпта

```text
Создай Cursor Hook типа User hooks.

Цель:


Событие:


Условие запуска:
Всегда / только для (каких команд, инструментов, файлов).


Действие хука:
Наблюдать / запретить / спросить пользователя / изменить действие /
добавить сведения в чат.


Сообщения пользователю и агенту:


Если хук не сработал:
Выполнить действие / запретить действие.


Способ выполнения:
Скрипт (Command-based hooks) / условие для AI-модели (Prompt-based hooks).


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks:
   https://cursor.com/docs/hooks
2. Прочитай шаблон `templates/hook/user-hooks.json`, его копию
   с пояснениями `templates/hook/user-hooks.annotated.jsonc`, скрипты
   в `templates/hook/hooks/` и существующие `~/.cursor/hooks.json`
   и `~/.cursor/hooks/`. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен личный хук. Если хук опирается
   на команды и файлы одного проекта, предложи Project hooks. Если нужно
   пожелание к агенту, а не автоматическое действие, предложи User Rule.
   Объясни причину и не создавай хук без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Проверь, что программы, которые нужны скрипту (например, `jq`),
   установлены. Не используй команды и пути одного проекта.
5. Предложи:
   - событие и условие `matcher` или объясни, почему условие не нужно;
   - способ выполнения: скрипт или условие для AI-модели;
   - ответ хука и тексты сообщений для пользователя и агента;
   - настройки `timeout`, `failClosed` и `loop_limit`, если они нужны;
   - полный текст записи для `~/.cursor/hooks.json` и текст скрипта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись в `~/.cursor/hooks.json` и создай
   скрипт в `~/.cursor/hooks/`. Эти файлы лежат вне проекта: если записать
   их не удаётся, выведи в чат содержимое файлов и команды для установки.
   Если `~/.cursor/hooks.json` уже есть, сохрани в нём существующие хуки.
   Файл — обычный JSON без комментариев, со строкой `"version": 1`
   и точными именами событий; в значениях не используй две косые черты
   подряд. Путь к скрипту запиши от папки `~/.cursor/`: `./hooks/имя.sh`.
   Сделай скрипт исполняемым. Скрипт печатает в stdout один JSON-объект
   и больше ничего.
8. Проверь, что `~/.cursor/hooks.json` — корректный JSON. Запусти скрипт
   с примерами входных данных для позитивных и негативных сценариев
   и убедись, что он отвечает ожидаемым JSON-объектом. Убедись, что
   скрипт не делает ничего сверх описанного и не содержит секретов.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа User hooks.

Цель:
Я иногда вставляю в запрос текст из терминала вместе с ключами доступа.
Нужно не отправлять запрос, если в нём есть закрытый ключ, — в любом
проекте.

Событие:
Я отправляю запрос агенту.

Условие запуска:
Всегда.

Действие хука:
Не отправлять запрос, если в его тексте есть строка
`-----BEGIN PRIVATE KEY-----` или `-----BEGIN RSA PRIVATE KEY-----`.

Сообщения пользователю и агенту:
Мне: «В запросе найден закрытый ключ. Удалите его и отправьте запрос
снова».

Если хук не сработал:
Выполнить действие: отправить запрос.

Способ выполнения:
Скрипт.

Не входит в задачу хука:
- поиск ключей в файлах проекта;
- проверка ответов агента.

Позитивные сценарии проверки:
- запрос со строкой `-----BEGIN PRIVATE KEY-----` не отправляется, и я вижу
  сообщение.

Негативные сценарии проверки:
- запрос «Объясни, как устроена авторизация» отправляется как обычно.

Процесс создания:
Сначала изучи официальную документацию, шаблон и мои текущие хуки.
Предложи событие, запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что файл `~/.cursor/hooks.json` лежит в домашней папке пользователя, а скрипт — в папке `~/.cursor/hooks/` и является исполняемым.
2. Открыть **Customize → Hooks** и убедиться, что хук есть в списке.
3. Выполнить позитивные сценарии в двух разных проектах: хук должен сработать в обоих.
4. Выполнить негативные сценарии: хук не должен срабатывать или не должен ничего менять.
5. Открыть панель **Output**, выбрать канал **Hooks** и убедиться, что хук запускался без ошибок.
6. Если хук не срабатывает, проверить имя события, путь к скрипту (`./hooks/имя.sh`) и условие `matcher`; при необходимости перезапустить Cursor.
7. Помнить, что облачные агенты личные хуки не выполняют.
