# Промпт для создания Cursor Hook: Tab hooks

**Tab hooks** — хуки для автодополнения Tab: подсказок, которые Cursor предлагает прямо в редакторе, пока вы печатаете. В этой категории два события: Tab собирается прочитать файл и Tab изменил файл. К агенту в чате эти хуки не относятся, поэтому для Tab можно задать свои правила. Хороший промпт на создание такого хука называет файлы, которые Tab не должен читать, или действие после правки Tab.

Тип подходит, если нужно ограничить доступ Tab к файлам или обработать его правки. В остальных случаях выберите другой тип:

- хук связан с работой агента в чате — [Agent hooks](create-hook-agent.md);
- хук должен срабатывать, когда Cursor открывает проект, — [App lifecycle hooks](create-hook-app-lifecycle.md);
- требование относится и к Tab, и к агенту — создайте два хука: по этому промпту и по промпту [Agent hooks](create-hook-agent.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Где хранится хук: [Project hooks](create-hook-project.md), [User hooks](create-hook-user.md), [Team hooks](create-hook-team.md), [Enterprise hooks](create-hook-enterprise.md). Способ выполнения: скрипт — [Command-based hooks](create-hook-command-based.md), условие для AI-модели — [Prompt-based hooks](create-hook-prompt-based.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks#beforetabfileread). Шаблон — [`templates/hook/tab-hooks.json`](../templates/hook/tab-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- `beforeTabFileRead` срабатывает перед тем, как Tab прочитает файл. На вход приходят путь к файлу (`file_path`) и его содержимое (`content`). Ответ — `"permission": "allow"` (разрешить) или `"permission": "deny"` (запретить).
- `afterTabFileEdit` срабатывает после того, как Tab изменил файл. На вход приходят путь к файлу и список правок: для каждой — место в файле (`range`), строка до правки (`old_line`) и после неё (`new_line`). Полей ответа у события нет.
- Эти события запускает только Tab. Чтение и правку файлов агентом в чате отслеживают события `beforeReadFile` и `afterFileEdit` из Agent hooks.
- Условие `matcher` сравнивается с постоянным значением: `TabRead` для `beforeTabFileRead` и `TabWrite` для `afterTabFileEdit`. Путь к файлу проверяет сам скрипт.
- Если скрипт `beforeTabFileRead` при коде выхода `0` отвечает не JSON или неверным значением, чтение запрещается. При сбое скрипта чтение разрешается, если не задано `"failClosed": true`.
- В облачных агентах Tab hooks не выполняются: автодополнение Tab работает только в приложении Cursor.
- Записи хранят в `hooks.json`: в `.cursor/hooks.json` проекта или в `~/.cursor/hooks.json`.

## Структура запроса

```text
Цель:
Что должно происходить автоматически при работе Tab и зачем?

Событие:
Tab собирается прочитать файл или Tab изменил файл?

Файлы:
Каких файлов касается хук: папки, имена, расширения?

Действие хука:
Запретить чтение? Обработать правку: отформатировать, записать в журнал?

Если хук не сработал:
Разрешить чтение или запретить его?

Где хранится хук:
В проекте или лично у вас?

Не входит в задачу хука:
Что относится к агенту в чате и оформляется как Agent hooks?

Проверка:
Для каких файлов хук должен сработать, а для каких — нет?
```

## Шаблон промпта

```text
Создай Cursor Hook типа Tab hooks.

Цель:


Событие:
Tab собирается прочитать файл / Tab изменил файл.


Файлы:


Действие хука:
Запретить чтение / обработать правку (как).


Если хук не сработал:
Разрешить чтение / запретить чтение.


Где хранится хук:
В проекте (Project hooks) / лично у меня (User hooks).


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks, разделы
   beforeTabFileRead и afterTabFileEdit:
   https://cursor.com/docs/hooks#beforetabfileread
2. Прочитай шаблон `templates/hook/tab-hooks.json`, его копию
   с пояснениями `templates/hook/tab-hooks.annotated.jsonc`, скрипты
   в `templates/hook/hooks/`, существующие `.cursor/hooks.json`
   и `.cursor/hooks/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен хук для Tab. Если требование
   относится к агенту в чате, предложи Agent hooks: события
   `beforeReadFile` и `afterFileEdit`. Если требование относится и к Tab,
   и к агенту, предложи оба хука. Объясни причину и не создавай хук без
   подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Пути к файлам и папкам бери из репозитория, а не придумывай. Проверь,
   что программы, которые нужны скрипту (например, `jq`), установлены.
5. Предложи:
   - событие;
   - как скрипт определяет нужные файлы по полю `file_path`;
   - ответ хука: для `beforeTabFileRead` — `permission` со значением
     `allow` или `deny`;
   - настройки `timeout` и `failClosed`, если они нужны;
   - полный текст записи для `hooks.json` и текст скрипта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись в `hooks.json` выбранного уровня
   и создай скрипт в папке `hooks` рядом с ним. Сохрани существующие
   хуки. Файл — обычный JSON без комментариев, со строкой `"version": 1`
   и точными именами событий; в значениях не используй две косые черты
   подряд. Путь к скрипту запиши от папки, из которой он запускается:
   для хуков проекта — от корня проекта. Сделай скрипт исполняемым.
   Скрипт печатает в stdout один JSON-объект и больше ничего.
8. Проверь, что `hooks.json` — корректный JSON. Запусти скрипт с примерами
   входных данных для позитивных и негативных сценариев и убедись, что
   он отвечает ожидаемым JSON-объектом. Убедись, что скрипт не делает
   ничего сверх описанного, не содержит секретов и не записывает
   содержимое файлов в журнал.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа Tab hooks.

Цель:
В Laravel-приложении бронирований в папке `storage/app/exports` лежат
выгрузки с персональными данными клиентов. Нужно, чтобы автодополнение
Tab не читало эти файлы и файлы `.env`.

Событие:
Tab собирается прочитать файл.

Файлы:
- любые файлы в папке `storage/app/exports`;
- файлы, имя которых начинается с `.env`.

Действие хука:
Запретить чтение.

Если хук не сработал:
Запретить чтение.

Где хранится хук:
В проекте.

Не входит в задачу хука:
- запрет чтения этих файлов агентом в чате: для него нужен отдельный
  хук `beforeReadFile`;
- удаление выгрузок.

Позитивные сценарии проверки:
- Tab не читает файл `storage/app/exports/clients.csv`;
- Tab не читает файл `.env`.

Негативные сценарии проверки:
- Tab читает файл `app/Services/BookingService.php` и предлагает
  подсказки как обычно.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи событие, запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что запись добавлена в `hooks.json` под именем `beforeTabFileRead` или `afterTabFileEdit`, а скрипт лежит по указанному в ней пути и является исполняемым.
2. Запустить скрипт вручную с примером входных данных, например `echo '{"file_path": "/project/.env", "content": ""}' | .cursor/hooks/имя.sh`: он должен напечатать один JSON-объект.
3. Открыть **Customize → Hooks** и убедиться, что хук есть в списке.
4. Открыть в редакторе файлы из позитивных и негативных сценариев и поработать с автодополнением Tab.
5. Открыть панель **Output**, выбрать канал **Hooks** и проверить, что хук запускался для нужных файлов и отвечал как задумано.
6. Если требование относится и к агенту в чате, убедиться, что для него создан отдельный хук из Agent hooks.
