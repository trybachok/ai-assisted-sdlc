# Промпт для создания Cursor Hook: Project hooks

**Project hooks** — хуки одного проекта: файл `.cursor/hooks.json` и скрипты в папке `.cursor/hooks/`, которые хранятся вместе с проектом и действуют у всех, кто его открыл. Хук — действие, которое Cursor выполняет сам в определённый момент: перед командой в терминале, после правки файла, при отправке запроса. Хороший промпт на его создание называет событие, условие запуска, действие хука и то, что увидят пользователь и агент.

Тип подходит, если автоматическое действие нужно в одном проекте и опирается на его команды и файлы. В остальных случаях выберите другой тип:

- хук нужен лично вам во всех проектах — [User hooks](create-hook-user.md);
- хук нужен всей команде во всех её проектах — [Team hooks](create-hook-team.md);
- хук нужен на всех компьютерах организации — [Enterprise hooks](create-hook-enterprise.md);
- нужно не автоматическое действие, а указание для агента — вместо хука создайте правило: [`docs/cursor-rules.md`](../docs/cursor-rules.md).

У хука есть ещё два свойства, и для каждого — свой промпт. Способ выполнения: скрипт — [Command-based hooks](create-hook-command-based.md), условие для AI-модели — [Prompt-based hooks](create-hook-prompt-based.md). Событие: [Agent hooks](create-hook-agent.md), [Tab hooks](create-hook-tab.md), [App lifecycle hooks](create-hook-app-lifecycle.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/hooks). Шаблон — [`templates/hook/project-hooks.json`](../templates/hook/project-hooks.json), простая инструкция — [`docs/cursor-hooks.md`](../docs/cursor-hooks.md).

## Требования Cursor

- Хуки проекта описывают в файле `.cursor/hooks.json` в корне проекта. Скрипты хранят рядом, в папке `.cursor/hooks/`.
- Файл содержит строку `"version": 1` и список `hooks`: имя события → хуки. У одного события может быть несколько хуков.
- Хуки проекта запускаются из корня проекта, поэтому путь к скрипту пишут от корня: `.cursor/hooks/имя.sh`, а не `./hooks/имя.sh`.
- Скрипт получает сведения о событии в формате JSON через stdin и печатает ответ в формате JSON в stdout. Код выхода `0` — использовать ответ, `2` — запретить действие, любой другой — хук не сработал, и действие выполняется.
- Хуки проекта работают только в проекте, которому пользователь доверяет (trusted workspace), и загружаются у каждого, кто открыл проект.
- Облачные агенты тоже выполняют хуки проекта, но только Command-based hooks и не все события.
- Cursor выполняет все подходящие хуки всех уровней: Enterprise, Team, Project и User. Если ответы разные, запрет главнее вопроса, а вопрос главнее разрешения.
- Cursor следит за файлом `hooks.json` и перечитывает его после сохранения. Если хуки не загрузились, Cursor перезапускают.
- Файл `.cursor/hooks.json` и папку `.cursor/hooks/` сохраняют в git, чтобы хук получила вся команда.

## Структура запроса

```text
Цель:
Что должно происходить автоматически и зачем?

Событие:
В какой момент срабатывает хук: перед командой в терминале, после правки
файла, при отправке запроса, в конце работы агента?

Условие запуска:
Хук срабатывает всегда или только для определённых команд, инструментов,
файлов?

Действие хука:
Что делает хук: наблюдает, запрещает, спрашивает пользователя, изменяет
действие, продолжает работу агента?

Сообщения:
Что увидит пользователь и что узнает агент, если действие запрещено?

Если хук не сработал:
Выполнить действие или запретить его?

Способ выполнения:
Скрипт или условие обычными словами, которое проверяет AI-модель?

Не входит в задачу хука:
Что остаётся правилам, CI и другим средствам контроля?

Проверка:
В каких случаях хук должен сработать, а в каких — нет?
```

## Шаблон промпта

```text
Создай Cursor Hook типа Project hooks.

Цель:


Событие:


Условие запуска:
Всегда / только для (каких команд, инструментов, файлов).


Действие хука:
Наблюдать / запретить / спросить пользователя / изменить действие /
продолжить работу агента.


Сообщения пользователю и агенту:


Если хук не сработал:
Выполнить действие / запретить действие.


Способ выполнения:
Скрипт (Command-based hooks) / условие для AI-модели (Prompt-based hooks).


Не входит в задачу хука:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Hooks:
   https://cursor.com/docs/hooks
2. Прочитай шаблон `templates/hook/project-hooks.json`, его копию
   с пояснениями `templates/hook/project-hooks.annotated.jsonc`, скрипты
   в `templates/hook/hooks/`, существующие `.cursor/hooks.json`
   и `.cursor/hooks/`, `AGENTS.md`, правила и другие инструкции
   репозитория. Если шаблона в проекте нет, используй формат
   из официальной документации.
3. Проверь, что задаче действительно нужен хук проекта. Если нужно
   указание для агента, а не автоматическое действие, предложи правило.
   Если хук нужен пользователю во всех проектах, предложи User hooks.
   Объясни причину и не создавай хук без подтверждения.
4. Перечисли найденные факты, неизвестные детали и необходимые уточнения.
   Команды, пути и инструменты бери из репозитория, а не придумывай.
   Проверь, что программы, которые нужны скрипту (например, `jq`),
   установлены.
5. Предложи:
   - событие и условие `matcher` или объясни, почему условие не нужно;
   - способ выполнения: скрипт или условие для AI-модели;
   - ответ хука и тексты сообщений для пользователя и агента;
   - настройки `timeout`, `failClosed` и `loop_limit`, если они нужны;
   - полный текст записи для `.cursor/hooks.json` и текст скрипта;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения добавь запись в `.cursor/hooks.json` и создай
   скрипт в `.cursor/hooks/`. Если `.cursor/hooks.json` уже есть, сохрани
   в нём существующие хуки. Файл — обычный JSON без комментариев,
   со строкой `"version": 1` и точными именами событий; в значениях
   не используй две косые черты подряд. Путь к скрипту запиши от корня
   проекта. Сделай скрипт исполняемым. Скрипт печатает в stdout один
   JSON-объект и больше ничего.
8. Проверь, что `.cursor/hooks.json` — корректный JSON. Запусти скрипт
   с примерами входных данных для позитивных и негативных сценариев
   и убедись, что он отвечает ожидаемым JSON-объектом. Убедись, что
   скрипт не делает ничего сверх описанного, не содержит секретов
   и не противоречит правилам проекта.
9. Не утверждай, что хук проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Hook типа Project hooks.

Цель:
В Laravel-приложении бронирований агент иногда оставляет PHP-файлы
неотформатированными, и проверка стиля в CI падает. Нужно форматировать
файл сразу после того, как агент его изменил.

Событие:
Агент изменил файл.

Условие запуска:
Только для файлов с расширением `.php`.

Действие хука:
Запустить Laravel Pint для изменённого файла. Ничего не запрещать.

Сообщения пользователю и агенту:
Не нужны.

Если хук не сработал:
Выполнить действие: сбой форматирования не должен мешать работе.

Способ выполнения:
Скрипт.

Не входит в задачу хука:
- запуск тестов;
- форматирование файлов, которые агент не изменял.

Позитивные сценарии проверки:
- после правки `app/Services/BookingService.php` файл отформатирован
  по правилам Laravel Pint.

Негативные сценарии проверки:
- после правки `README.md` Pint не запускается;
- если Pint не установлен, агент продолжает работу без ошибок.

Процесс создания:
Сначала изучи официальную документацию, шаблон и репозиторий.
Предложи событие, условие, запись для hooks.json и текст скрипта.
До моего подтверждения не изменяй файлы.
```

## Проверка готового хука

1. Убедиться, что файл `.cursor/hooks.json` лежит в корне проекта, а скрипт — в папке `.cursor/hooks/` и является исполняемым.
2. Открыть **Customize → Hooks** и убедиться, что хук есть в списке.
3. Выполнить позитивные сценарии: хук должен сработать.
4. Выполнить негативные сценарии: хук не должен срабатывать или не должен ничего менять.
5. Открыть панель **Output**, выбрать канал **Hooks** и убедиться, что хук запускался без ошибок.
6. Если хук не срабатывает, проверить имя события, путь к скрипту и условие `matcher`; при необходимости перезапустить Cursor.
7. Сохранить `.cursor/hooks.json` и папку `.cursor/hooks/` в git, чтобы хук получила вся команда.
