# Промпт для создания конфигурации Cursor MCP: Team MCP server

**Team MCP server** — MCP-сервер для всей команды. Он хранится не в файлах проекта: администратор команды добавляет сервер в [дашборде Cursor](https://cursor.com/dashboard/plugins), в разделе **Plugins & MCPs**. Такой сервер доступен облачным агентам команды, а через маркетплейс команды — и участникам в приложении Cursor. Поэтому промпт просит агента подготовить настройки и конфигурацию сервера, а в дашборд их переносит администратор. MCP-сервер — посредник между Cursor и внешним сервисом или данными: агент получает от него инструменты и вызывает их во время работы. Хороший промпт определяет, кому нужен сервер, как он подключается, как участники входят в сервис и какие права он получит.

Тип подходит, если сервер нужен всей команде во всех её проектах или облачным агентам. В остальных случаях выберите другой тип:

- сервер относится к одному проекту — [Project Configuration](create-mcp-project.md);
- сервер нужен лично вам — [Global Configuration](create-mcp-global.md);
- нужен не внешний сервис, а указание для агентов команды — вместо MCP создайте [Team Rule](create-rule-team.md).

У подключения есть ещё одно свойство — способ связи с сервером, и для каждого — свой промпт: локальная программа — [stdio server](create-mcp-stdio.md), удалённый сервер — [Streamable HTTP server](create-mcp-streamable-http.md) или [SSE server](create-mcp-sse.md), удалённый сервер с заранее выданным Client ID — [Remote server with Static OAuth](create-mcp-static-oauth.md).

Требования и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/mcp#team-mcp-distribution). Шаблон — [`templates/mcp/team-mcp.md`](../templates/mcp/team-mcp.md), простая инструкция — [`docs/cursor-mcp.md`](../docs/cursor-mcp.md).

## Требования Cursor

- Team MCP server настраивает администратор команды в дашборде Cursor, в разделе **Plugins & MCPs**. Изменять его могут только администраторы команды.
- Такие серверы доступны облачным агентам команды.
- Конфигурация сервера общая: её изменение действует для всех участников команды и автоматизаций, которые пользуются сервером.
- Облачные агенты поддерживают собственные серверы с подключением по Streamable HTTP или stdio; SSE и `mcp-remote` не поддерживаются. Рекомендуется Streamable HTTP: настройки и ключи доступа сервера не попадают в среду, где работает агент. Сервер stdio запускается в облачной среде агента, и агент получает доступ к его настройкам и переменным окружения.
- Значения `env`, `headers` и `CLIENT_SECRET` после сохранения скрыты: прочитать их обратно не может никто.
- Вход через OAuth у каждого участника свой, даже если сервер общий.
- Чтобы участники могли установить сервер в приложении Cursor и в Cursor CLI, администратор выбирает **Add to Team Marketplace** в блоке **Team MCP Servers**. Сервер не устанавливается всем автоматически: это определяют настройка **Marketplace Access** и режим установки — **Default Off**, **Default On** или **Required**.
- Если удалить связанный сервер из маркетплейса или удалить маркетплейс, Team MCP server может быть удалён — и для участников, и для облачных агентов.
- MCP-сервер получает данные, которые передаёт ему агент, и выполняет действия от имени пользователя. Документация советует подключать серверы только из проверенных источников и выдавать ключи с наименьшими правами.

## Структура запроса

```text
Цель:
Какой сервис или какие данные нужны всей команде и зачем?

Аудитория:
Кто будет пользоваться сервером: облачные агенты, участники в приложении
Cursor или все?

Сервер:
Какой MCP-сервер подключить и кто его владелец? Где его официальная
документация?

Способ подключения:
Адрес сервера для HTTP или команда запуска?

Вход в сервис:
Через OAuth, по ключу доступа или без входа? Кто выдаёт ключ?

Права сервера:
Что серверу разрешено: только читать данные или также изменять их?

Не входит в задачу:
Что относится к отдельным проектам или обеспечивается другими средствами?

Проверка:
Какой запрос к агенту покажет, что сервер работает?
```

## Шаблон промпта

```text
Подготовь Team MCP server для Cursor.

Цель:


Аудитория:
Облачные агенты / участники в приложении Cursor / все.


Сервер, его владелец и официальная документация:


Способ подключения:
Streamable HTTP (адрес) / stdio (команда запуска).


Вход в сервис:
OAuth / ключ доступа (кто его выдаёт) / не нужен.


Права сервера:
Только чтение / чтение и изменение (чего именно).


Не входит в задачу:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor MCP, раздел
   Team MCP distribution:
   https://cursor.com/docs/mcp#team-mcp-distribution
2. Прочитай шаблон `templates/mcp/team-mcp.md`. Если шаблона в проекте
   нет, подготовь результат из разделов: имя сервера, способ подключения,
   вход в сервис, доступ участников, конфигурация сервера.
3. Проверь, что сервер нужен всей команде. Сервер одного проекта
   не включай: предложи оформить его как Project Configuration
   и объясни причину.
4. Перечисли предположения и задай уточняющие вопросы. Адрес сервера,
   команду запуска и способ входа бери из официальной документации
   сервера, а не придумывай. Если сервер доступен только по SSE,
   предупреди: облачные агенты такие серверы не поддерживают.
5. Подготовь по шаблону:
   - имя сервера и способ подключения;
   - способ входа в сервис;
   - рекомендацию, выбирать ли Add to Team Marketplace, значение
     Marketplace Access и режим установки — с обоснованием;
   - конфигурацию сервера без значений ключей доступа.
6. Не запрашивай у пользователя значения ключей доступа и не записывай
   их в результат: администратор вводит их прямо в дашборде. На месте
   значения оставь пометку в квадратных скобках.
7. Не создавай и не изменяй файлы проекта: Team MCP server хранится
   в дашборде Cursor. Выведи результат в чат так, чтобы его можно было
   скопировать целиком.
8. Перечисли, к каким данным получат доступ участники команды и облачные
   агенты. Предложи выдать ключ доступа с наименьшими правами, которых
   достаточно серверу.
9. Не утверждай, что сервер добавлен или работает: добавить и проверить
   его может только администратор команды. Предоставь ручной чек-лист
   проверки.
```

## Пример

```text
Подготовь Team MCP server для Cursor.

Цель:
Ошибки всех приложений команды, включая Laravel-приложение бронирований,
собираются в трекере ошибок компании. Нужно, чтобы облачные агенты
и участники команды читали сведения об ошибке сами, без копирования
текста в чат.

Аудитория:
Все: облачные агенты и участники в приложении Cursor.

Сервер, его владелец и официальная документация:
MCP-сервер трекера ошибок. Его поддерживает служба эксплуатации,
описание — во внутренней документации компании.

Способ подключения:
Streamable HTTP, адрес `https://errors.example.com/mcp`.

Вход в сервис:
Ключ доступа только для чтения. Его выдаёт служба эксплуатации.

Права сервера:
Только чтение сведений об ошибках.

Не входит в задачу:
- закрытие и изменение записей об ошибках;
- доступ к журналам с персональными данными клиентов.

Позитивные сценарии проверки:
- на запрос «Покажи последние ошибки сервиса бронирований» облачный
  агент вызывает инструмент сервера и отвечает по данным трекера;
- участник команды находит сервер в разделе Customize → MCPs
  и устанавливает его.

Негативные сценарии проверки:
- просьбу закрыть запись об ошибке сервер не выполняет;
- значения ключа доступа нет ни в файлах проектов, ни в переписке.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Подготовь настройки для дашборда и конфигурацию сервера без ключа.
Файлы проекта не создавай и не изменяй.
```

## Проверка готовой конфигурации

1. Администратор команды открывает [дашборд Cursor](https://cursor.com/dashboard/plugins), раздел **Plugins & MCPs**, добавляет сервер из подготовленных настроек и сам вводит ключи доступа.
2. Убедиться, что способ подключения, вход в сервис, **Add to Team Marketplace**, **Marketplace Access** и режим установки выставлены как задумано.
3. Запустить облачного агента команды и выполнить позитивные и негативные сценарии.
4. Если выбрано **Add to Team Marketplace**, участник команды открывает **Customize → MCPs**, находит сервер и, если нужно, устанавливает его и входит в сервис.
5. Убедиться, что ключ доступа выдан с наименьшими правами и не записан в файлы проектов.
