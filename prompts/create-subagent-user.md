# Промпт для создания Cursor Subagent: User subagent

**User subagent** — личный субагент: файл в папке `~/.cursor/agents/` (в домашней папке пользователя, а не в проекте), который доступен во всех ваших проектах. Основной агент передаёт такому субагенту задачу сам, по его описанию (`description`), или по вашему явному вызову. Хороший промпт на его создание описывает помощника, полезного в любом проекте, и отделяет его работу от требований отдельных проектов.

Тип подходит, если помощник нужен лично вам и не зависит от команд, файлов и соглашений одного проекта. В остальных случаях выберите другой тип:

- помощник нужен в одном проекте или всей команде — [Project subagent](create-subagent-project.md);
- помощник должен только проверять и ничего не изменять — [Read-only subagent](create-subagent-readonly.md);
- работа долгая, и основной агент не должен её ждать — [Background subagent](create-subagent-background.md);
- задачу нужно выполнить в облаке, не занимая ваш компьютер, — [Cloud subagent](create-subagent-cloud.md);
- задача простая и выполняется за один шаг — вместо субагента создайте [Cursor Skill](create-skill.md).

Требования к формату и актуальные ограничения приведены в [официальной документации Cursor](https://cursor.com/docs/subagents#file-locations). Шаблон субагента — [`templates/subagent/user-subagent.md`](../templates/subagent/user-subagent.md), простая инструкция — [`docs/cursor-subagents.md`](../docs/cursor-subagents.md).

## Требования Cursor

- Субагент — файл Markdown в папке `~/.cursor/agents/`. Он действует во всех проектах текущего пользователя.
- Файл хранится на компьютере пользователя, а не в репозитории: в git проекта он не попадает, и у других участников команды его нет.
- User subagent работает в приложении Cursor на вашем компьютере. Облачные агенты и Cursor CLI папку `~/.cursor/agents/` не читают: субагента, который нужен и там, размещают в проекте, в `.cursor/agents/`.
- Файл состоит из блока настроек (YAML frontmatter) и текста задания под ним.
- В блоке настроек указывают `name` — имя из строчных латинских букв и дефисов; по умолчанию оно берётся из имени файла — и `description`. Необязательные поля: `model` (по умолчанию `inherit`), `readonly` и `is_background` (по умолчанию `false`).
- Основной агент читает `description` и по нему решает, передавать ли задачу. Описание должно быть конкретным; слова «используй проактивно» или «всегда используй для…» поощряют автоматическую передачу.
- Субагент начинает работу с чистым контекстом и не видит историю переписки: всё необходимое он получает из своего задания и из запроса основного агента.
- У субагента должна быть одна чёткая зона ответственности, а задание должно быть коротким и конкретным. Для простой задачи, которая выполняется за один шаг, вместо субагента используют skill.
- При совпадении имён Project subagent главнее User subagent.

## Структура запроса

```text
Цель:
Какую работу основной агент должен передавать субагенту в любом проекте?

Когда вызывать:
При каких задачах и запросах агент должен передавать работу субагенту?

Когда не вызывать:
Какие похожие задачи субагенту не передаются?

Порядок работы:
Что субагент делает по шагам? Как он узнаёт команды и соглашения проекта,
в котором оказался?

Отчёт:
Что субагент должен вернуть основному агенту?

Настройки:
Нужна ли другая модель? Достаточно ли прав только на чтение?
Ждать результат или работать в фоне?

Не входит в задачу субагента:
Что относится к отдельным проектам и должно остаться в Project subagent?

Проверка:
По каким запросам субагент должен вызываться, а по каким — нет?
```

## Шаблон промпта

```text
Создай Cursor Subagent типа User subagent.

Цель:


Когда вызывать субагента:


Когда не вызывать:


Порядок работы субагента:


Что субагент должен вернуть:


Настройки:
Модель: та же, что у основного агента / другая (какая).
Права: обычные / только чтение.
Режим: Foreground (агент ждёт результат) / Background (работа в фоне).


Не входит в задачу субагента:


Позитивные сценарии проверки:


Негативные сценарии проверки:


Процесс создания:
1. Сначала прочитай официальную документацию Cursor Subagents:
   https://cursor.com/docs/subagents
2. Прочитай шаблон `templates/subagent/user-subagent.md` и существующих
   субагентов в `~/.cursor/agents/` и в `.cursor/agents/` текущего проекта.
   Если шаблона в проекте нет, используй формат из официальной документации.
3. Проверь, что задаче действительно нужен User subagent. Если задача
   простая и выполняется за один шаг, предложи skill. Если помощник
   опирается на команды, пути или правила одного проекта, предложи
   Project subagent. Объясни причину и не создавай субагента без
   подтверждения.
4. Перечисли предположения и задай уточняющие вопросы.
5. Предложи:
   - имя субагента: строчные латинские буквы и дефисы;
   - значение `description`: одной строкой, что делает субагент и когда
     передавать ему задачу;
   - значения `model`, `readonly` и `is_background`;
   - полный текст задания без путей, команд и правил отдельных проектов;
   - сценарии проверки.
6. До подтверждения не изменяй файлы.
7. После подтверждения создай файл `~/.cursor/agents/<имя>.md` по шаблону.
   Значение `name` должно совпадать с именем файла. Каждую настройку запиши
   в одну строку, без кавычек и без пояснений после значения; в `description`
   не используй двоеточия и символ `#`. Файл находится вне проекта: если
   записать его не удаётся, выведи полный текст файла в чат и объясни, куда
   его сохранить.
8. Проверь расположение и расширение файла, блок настроек, отсутствие
   субагента с таким же именем в `~/.cursor/agents/` и в проекте, отсутствие
   секретов. Убедись, что `description` отличает позитивные сценарии
   от негативных, а задание понятно без истории переписки и подходит
   любому проекту.
9. Не утверждай, что субагент проверен в Cursor, если проверка фактически
   не выполнялась. В таком случае предоставь ручной чек-лист проверки.
```

## Пример

```text
Создай Cursor Subagent типа User subagent.

Цель:
В разных проектах я трачу много времени на поиск причин ошибок, а разбор
длинных логов засоряет основной чат. Нужен личный помощник по отладке.

Когда вызывать субагента:
- сообщение об ошибке или трассировка стека;
- упавший тест;
- «Найди причину ошибки».

Когда не вызывать:
- добавление новой функциональности;
- вопросы о том, как устроен код.

Порядок работы субагента:
1. Прочитать README и AGENTS.md проекта, если они есть: узнать команды
   и соглашения.
2. Зафиксировать текст ошибки и шаги, которые к ней приводят.
3. Найти место, где возникает сбой.
4. Внести минимальное исправление и проверить, что оно работает.

Что субагент должен вернуть:
- причину ошибки и факты, которые её подтверждают;
- что исправлено;
- как проверить исправление.

Настройки:
Модель — та же, что у основного агента.
Права обычные: субагент исправляет код.
Режим Foreground: основной агент ждёт результат.

Не входит в задачу субагента:
- всё, что относится к одному проекту: технологии, пути, команды запуска;
- переработка кода, не связанная с ошибкой.

Позитивные сценарии проверки:
- на сообщение «Тест падает с ошибкой, вот вывод» агент передаёт разбор
  субагенту;
- на запрос «/debugger найди причину ошибки 500 на странице входа» субагент
  называет причину и подтверждающие факты.

Негативные сценарии проверки:
- на просьбу «Добавь поле в форму» субагент не вызывается.

Процесс создания:
Сначала изучи официальную документацию и шаблон.
Предложи имя, description, настройки и текст задания.
До моего подтверждения не изменяй файлы.
```

## Проверка готового субагента

1. Убедиться, что файл лежит в `~/.cursor/agents/`, имеет расширение `.md`, а его имя совпадает со значением `name`.
2. Открыть **Customize → Subagents** и убедиться, что субагент есть в списке.
3. В новом чате вызвать субагента явно, например `/debugger найди причину ошибки`: в чате должна появиться карточка задачи субагента.
4. Выполнить позитивные и негативные сценарии: основной агент должен передавать субагенту только подходящие задачи.
5. Повторить проверку в другом проекте: User subagent действует во всех проектах.
6. Убедиться, что в задании нет требований отдельных проектов, а в проектах нет субагента с таким же именем: при совпадении имён главнее Project subagent.
7. Если агент не передаёт задачу сам, уточнить `description`: назвать в нём задачи, для которых нужен субагент.
